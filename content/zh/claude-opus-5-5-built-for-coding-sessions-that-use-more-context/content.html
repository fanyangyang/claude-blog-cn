我们估计，按 token 计费的典型工作负载下，运行 Claude Opus 5.5 的成本大约比 Opus 5 低 40%。对于开发者来说，这些节省究竟如何累积起来，才是关键。 

如果你按 token 付费，你会在运行时间更长、上下文更高的会话中看到最大的成本差异——而这正是过去六个月里变得越来越普遍的 Claude Code 会话类型。 

这篇文章将深入探讨 Opus 5.5 为何能针对开发者今天的（很可能也是明天的）编码方式实现成本效益。

Claude Code 趋势

我们提取了 2026 年 3 月至 9 月开发者使用 Claude Code 的汇总数据。随着模型能力的提升，开发者正在以越来越复杂的方式部署代理。每个会话的提示次数保持稳定，但我们发现了一些有趣的行为：

  • Claude 在每个提示上工作的时间延长了 3.3 倍，每个提示的模型调用次数增加了 40% 以上，中断次数减少了 68%。
  • 开发者连接工具服务器或使用技能的可能性约为原来的两倍，而将文本粘贴到提示中的可能性降低了三分之一。
  • 每个请求的上下文增长了 2.6 倍。输入与输出的 token 比例从 189:1 变为 324:1。

所有这些都表明，开发者正在让一个更努力、信息更充分的 Claude 去处理更大、更开放的任务。对于这类会话，上下文工程的经济影响会被放大。 

简单来说，Claude 读取了更多的 token。你需要确保你提供的所有上下文都是必要的，并且尽可能多的上下文都从缓存中读取。 

是什么让 Opus 5.5 对长会话、高上下文场景具有成本效益

有三项变化让运行时间长、上下文重的会话更具成本效益：定价的变化、模型行为的变化以及 Claude Code 工作框架的变化。让我们逐一来看。

缓存很便宜

对于按 token 计费的使用，我们将输入和输出 token 的成本降低了 20%，并将读取缓存 token 的价格下调了 60%。后一项下调意义重大，因为缓存读取占代理和编码工作成本的绝大部分。 

而且正如我们刚刚讨论的，六个月里每个请求的上下文大约增加了 2.6 倍，这意味着节省正朝着正确的方向发展。同样的价格调整，对今天的 Claude Code 流量节省得比六个月前更多，因为现在账单中有更多部分是重新读取的上下文。 

截至发布之日，Opus 5.5 上读取一个缓存 token 的成本是竞品模型的五分之一，而性能却优于它们。

Claude Code 更善于利用缓存

这一点对 Opus 5.5 来说并不那么特殊，更多是过去六个月我们新增的许多 Claude Code 功能的结果。鉴于我们刚刚讨论的编码会话趋势，你可能会预期缓存未命中率会更高，但事实恰恰相反。未命中缓存的输入减少了 50% 以上。 

例如，我们让刷新登录这类小摩擦更不容易意外破坏你的缓存；我们也让添加会话中途指令或按需加载工具这类更大的操作更不容易破坏缓存。对于 Opus 5.5 和 Fable 5.1 等更新型号，你现在可以在会话过程中更改努力级别，而无需重置缓存。

我们还让缓存对运行时间更长和委派式的会话更有用。使用 API 密钥和云提供商的开发者现在可以设置一小时的缓存生命周期（订阅用户此前已经拥有），而分叉的子代理从父代理的缓存开始，而不是为同样的上下文再次付费。 

同样的任务，更少的轮次

完成同样的任务，Opus 5.5 需要的轮次可能比其他模型更少。Zeta Labs 观察到，相比 Opus 5，每项任务的轮次和工具调用更少，但成本几乎只有一半，且他们最困难的任务中有两倍的数量得以完成。

这并不适用于所有任务。在《Opus 5.5 上一个任务的成本》中，Addy 写道："在一个界定清晰的任务上，两个模型完成所需的轮次大致相同，你能得到的只有降价。差距最大的应该是开放式任务，因为模型可能在错误的想法上消耗很多轮次。没有一个数字适用于所有代码库，所以要亲自测量。"

换句话说，简单、短小、机械的任务所需的轮次相同，而更长、更难的任务则更有可能让 Opus 5.5 避免在错误的方法上浪费 token。减少一个轮次甚至比读取一个缓存 token 更具成本效益。

同样值得注意的是，尤其是当 Claude 更长时间无人值守或不受干扰地工作时，Opus 5.5 的输出生成速度比 Opus 5 快 30% 以上。虽然这不会提高缓存命中率或减少 token 使用，但它意味着在长时间运行时等待更少。

保护你的缓存读取

随着代理式编码走向成熟，组织已经从要求开发者不惜一切代价扩张，转向要求开发者高效扩张。在 Claude Code 中运行 /usage，查看你的使用中有多少是缓存读取。然后保护这个数字： 

  • 在会话开始时选择你的模型，而不是中途切换， 
  • 在离开之前压缩上下文，而不是之后， 
  • 如果你使用 API 密钥或云提供商，为长会话设置一小时的缓存生命周期。 

把 Opus 5.5 指向那些开放式的、上下文密集的工作，让这些习惯产生复利效应，并查看《Opus 5.5 上一个任务的成本》了解具体的测算数字。
