通过 AWS、Google Cloud 和 Microsoft Foundry 使用 Claude Desktop 的组织，现在可以获得完整的 Desktop 体验——对话、Claude Cowork 和 Claude Code，尽在一个应用中。

如今，IT 团队可以让推理在所有产品中都留在自己的环境内，并通过按用户的 SSO、MDM 策略模板、离线安装程序选项，以及可完全在设备上运行的 M365 连接器，在整个组织范围内部署 Claude Desktop。 

推理在你配置的云区域中运行，对话历史存储在本地。数据连接器访问哪些端点、Anthropic 接收哪些汇总遥测数据，都由你掌控。

面向整个组织的统一界面

在此之前，通过 AWS、Google Cloud 和 Microsoft Foundry 使用 Claude Desktop 的客户只能使用 Claude Cowork 和 Claude Code。现在，一次部署即可覆盖所有角色，且每个界面都有独立的策略键，由你来决定谁在何时获得什么。

用对话快速获取答案、梳理问题。用 Claude Cowork 处理员工更愿意交出去的工作：Claude 在已批准的来源中调研，处理设备上已有的文件并构建交付物，完成后呈现结果。用 Claude Code 让工程师无需守在终端里也能进行智能体编程。

部署控制

在整个组织范围部署 Claude Desktop，意味着要融入你现有的体系。

像登录任何办公应用一样登录。员工使用与其他工作一模一样的工作账号：IAM Identity Center、Workforce Identity Federation、Microsoft Entra ID，或 Okta 等任何 OIDC 提供商。没有需要轮换的共享密钥，终端用户机器上也不存在云凭据。

像管理现有应用一样部署。从设置界面导出策略模板，通过 Intune、GPO 或 Jamf 下发。离线安装程序可覆盖物理隔离环境。

在任何人看到之前先确认它能用。在正式推出前测试每个连接器，确认你的提供商提供哪些 Claude 模型，并验证连接。模型防护机制可确保路由始终停留在 Claude 上——即使某个配置有误——GovCloud 环境中也不例外。

小规模起步，随采用扩大。对话、Claude Cowork 和 Claude Code 各自有独立的策略键，因此你可以先给非技术团队开放对话和 Claude Cowork，给工程团队开放 Claude Code，再随着各团队对每个界面的采用逐步放宽访问。你的硬性拒绝规则在所有标签页中一律生效。

把 Claude 带到工作发生的地方。Microsoft 365 连接器让 Claude 通过你自己的 Entra 应用访问邮件和文档，支持租户白名单，并对 GCC High/DoD 端点提供测试版支持。对于最严格的数据驻留要求，可以使用我们的本地连接器，连接只存在于设备与 Microsoft 之间。
