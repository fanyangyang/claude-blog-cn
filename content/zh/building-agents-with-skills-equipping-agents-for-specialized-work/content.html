过去一年发生了很多变化。MCP 成为智能体连接的事实标准，被行业领袖和开发者社区迅速采用。Claude Code 发布，成为通用编程智能体。我们还发布了 Claude Agent SDK，如今它开箱即用地提供一个生产可用的智能体。

但随着我们构建和部署这些智能体，总是撞上同一个缺口：智能体拥有智力和能力，却未必拥有有效完成真实工作所需的专业知识。这促使我们创建了 Agent Skills。技能是有组织的文件集合，把领域专业知识——工作流、最佳实践、脚本——打包成智能体可以访问和运用的格式。它能把一个能力不错的通才，变成知识渊博的专家。

在这篇文章中，我们将解释为什么我们不再构建专门化的智能体、转而构建技能，以及这一转变如何改变了我们对扩展智能体能力的思考方式。

新范式：代码即所需

我们曾经以为不同领域的智能体会长得非常不一样。编程智能体、研究智能体、财务智能体、营销智能体——每一个似乎都需要自己的工具和脚手架。业界最初也拥抱了这种领域专属智能体的模式。但随着模型智能水平和智能体能力的提升，我们逐渐收敛到了另一条路线上。

我们逐渐意识到，代码不只是众多用例之一，而是一种接口，智能体可以借助它完成几乎任何数字化工作。Claude Code 是一个编程智能体，但也是一个恰好通过代码来工作的通用智能体。

设想让 Claude Code 生成一份财务报告。它可以调用 API 做研究、把数据存进文件系统、用 Python 做分析，再综合出洞察。这一切都通过代码完成。脚手架简化到了 bash 和一个文件系统的程度。

但通用能力并不等于专业知识。当我们开始用 Claude Code 处理真实工作时，一个缺口显现出来。

缺失的一环：领域专业知识

如果有人替你报税，你会选谁：一位从第一性原理出发推导的数学天才，还是一位申报过几千份报税单的资深税务师？大多数人会选税务师。不是因为他更聪明，而是因为他拥有正确的专业知识。

如今的智能体就像那位数学天才：面对全新情境时推理能力惊人，却常常缺少资深专业人士积累下来的经验。在恰当的引导下，它们能做出很棒的东西。但它们往往缺少重要的背景信息，无法轻易吸收你组织的专业知识，也不会自动从重复任务中学习。

技能正是为了弥合这一缺口：把领域专业知识打包成智能体可以按需逐步访问和运用的格式。

什么是 Agent Skills？

技能为智能体打包领域专业知识和程序性知识。 

anthropic_brand/
├── SKILL.md
├── docs.md
├── slide-decks.md
└── apply_template.py

技能的简单是刻意为之。文件是一种普适的基础原语，与你已有的一切都能配合。你可以用 Git 做版本管理、存到 Google Drive、分享给团队。这种简单也意味着创建技能不是工程师的专利。产品经理、分析师和领域专家已经在构建技能，把自己的工作流沉淀成规范。

渐进式披露

技能可能包含大量信息。为了保护上下文窗口并让技能可以组合，它们采用渐进式披露：运行时，只有元数据（YAML frontmatter 中的名称和描述）会展示给模型。

---
name: Anthropic Brand Style Guidelines
description: Anthropic's official brand colors and typography…
---

如果 Claude 判断需要某个技能，它会读取完整的 SKILL.md 文件。若需要更多细节，技能还可以包含一个 references/ 目录，存放仅在需要时才加载的支撑文档。

这种三层结构意味着你可以为一个智能体配备数百个技能，而不必撑爆它的上下文窗口——元数据约占 50 个 token，完整 SKILL.md 约 500 个 token，参考文件 2000 个 token 以上且仅在确实需要时加载。

技能可以把脚本作为工具

传统工具存在一些问题：有的说明书写得糟糕，模型无法修改或扩展它们，而且它们常常撑大上下文窗口。代码则相反：自带说明、可修改，而且不必一直待在上下文里。

举一个真实的例子：我们反复看到 Claude 编写同样的脚本来为幻灯片应用 Anthropic 样式。于是我们让 Claude 把它保存为自己的一个工具：

# anthropic/brand_styling/apply_template.py
import sys
from pptx import Presentation

if len(sys.argv) != 2:
    print("USAGE: apply_template.py <pptx>")
    sys.exit(1)

prs = Presentation(sys.argv[1])
for slide in prs.slides:
    ...

slide-decks.md 中对应的文档只是简单地引用这个脚本：

## Anthropic Slide Decks
- Intro/outro slides
  - background color: `#141413`
  - foreground color: oat
- Section slides:
  - background color: `#da7857`
  - foreground color: `#141413`

Use the `./apply_template.py` script to update a pptx file in-place.

技能生态

技能生态发展非常快，到目前为止我们看到三类主要的技能：

基础技能

它们提供人人都需要的核心能力：处理文档、电子表格、演示文稿等，把文档生成与操作的最佳实践固化下来。你可以浏览我们公开仓库中的基础技能，看看它们在实践中长什么样。

合作伙伴技能

随着技能把智能体与专业能力的交互方式标准化，各公司纷纷构建技能，让自己的服务可以被智能体访问。K-Dense、Browserbase、Notion 以及许多其他公司都在创建直接集成自家服务的技能，在特定领域扩展 Claude 的能力，同时保持技能格式的简洁。

企业技能

组织会构建专有技能，把内部流程和领域专业知识沉淀其中。技能帮助沉淀那些让智能体在企业工作中真正有用的特定工作流、合规要求和机构知识。

我们看到的趋势

随着技能的采用不断增长，一些模式正在浮现，指向这一范式可能的走向。这些趋势影响着我们对技能设计的思考，以及我们为支持技能开发者而构建的工具。

复杂度不断提升

早期的技能只是简单的文档参考。现在我们看到的是精巧的多步骤工作流，协调数据检索、复杂计算，以及跨多个工具的格式化输出。

  • 简单：“状态报告撰写器”（约 100 行）——模板与格式化
  • 中等：“财务模型构建器”（约 800 行）——数据检索、用 Python 做 Excel 建模
  • 复杂：“RNA 测序流水线”（2500 行以上）——协调 HISAT2、StringTie、DESeq2 分析

技能与 MCP

技能与 MCP 服务器天然互补。一个竞争分析技能可以协调网页搜索、经 MCP 访问的内部数据库、Slack 消息历史和 Notion 页面，最终综合出一份全面的报告。

非开发者的加入

技能创建正在从工程师扩展到各学科的产品经理、分析师和领域专家。借助 skill-creator 工具的交互式引导，他们可以在 30 分钟内创建并测试第一个技能。我们正在努力让技能创建更加平易近人，提供改进的工具和模板，让任何人都能沉淀并分享专业知识。

完整的架构

把这一切拼起来，浮现中的智能体架构由以下部分组合而成：

  1. 智能体循环（Agent loop）：决定下一步做什么的核心推理系统
  2. 智能体运行时（Agent runtime）：执行环境（代码、文件系统）
  3. MCP 服务器：连接外部工具和数据源
  4. 技能库：领域专业知识与程序性知识

每一层都有清晰的职责：循环负责推理，运行时负责执行，MCP 负责连接，技能负责指引。这种分离让整个系统可理解，也让每个部分可以独立演进。

想想在这个架构上增加一个技能会发生什么。前端设计技能能瞬间改变 Claude 的前端能力。它提供关于排版、色彩理论和动画的专门指导，只在构建 Web 界面时激活。渐进式披露保证了它只在相关时加载。增加新能力就这么简单。

把技能部署到新的垂直领域

这种“通用智能体 + MCP 服务器 + 技能”的新模式，已经在帮助我们向新的垂直领域部署 Claude。

金融服务

技能发布后不久，我们为金融服务行业的 Claude 增加了一批技能，让 Claude 对金融从业者更加有用：

  • DCF 模型构建器：构建含规范 WACC 计算和敏感性分析的现金流折现模型
  • 可比公司分析：生成含相关估值倍数和基准对比的可比公司表
  • 财报分析：处理季度业绩并生成投资动态报告
  • 首次覆盖报告：构建包含财务模型的全面研究报告
  • 尽职调查：用标准化框架组织并购分析
  • 路演材料：按行业标准制作面向客户的演示文稿

医疗健康与生命科学

我们也为医疗健康与生命科学产品增加了技能，让 Claude 对研究人员、临床医生和医疗开发者更加有用：

  • 生物信息学套件：面向 scVI-tools 和 Nextflow 部署的技能，是管理基因组流水线和单细胞 RNA 测序的关键
  • 临床试验方案生成：加速临床研究的方案制定
  • 科学问题遴选：帮助研究者识别并构建有影响力的研究问题
  • FHIR 开发：帮助开发者编写更准确的健康数据互操作代码，更快地打通医疗系统、减少错误
  • 预授权审查：交叉比对承保要求、临床指南和患者记录，减轻行政负担，加快患者获得所需诊疗

Agent Skills 标准化

为了让这一愿景落地，我们将 Agent Skills 作为开放标准发布。和 MCP 一样，我们相信技能应当可以跨工具、跨平台移植。同一个技能，无论你在用 Claude 还是其他 AI 平台，都应该能正常工作。我们一直在与生态中的成员协作制定这一标准，也很高兴看到早期的采用。

当某人第一次使用 AI 智能体时，它应该已经了解你和你的团队关心什么——因为技能捕捉并传递了这些专业知识。随着生态的成长，社区里其他人构建的技能可以让你的智能体更有用、更可靠、更强大——无论他们用的是哪个 AI 平台。

开始使用

我们正在收敛出一种通用智能体的架构，而技能提供了发布和分享新能力的范式。真正的价值来自我们共同构建的知识库：沉淀专业知识、跨团队传递，让每一个智能体都比上一个更强大。
