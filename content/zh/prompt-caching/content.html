更新：Prompt caching 已在 Anthropic API 上正式发布（GA）。Amazon Bedrock 和 Google Cloud 的 Vertex AI 也提供了预览版。（2024 年 12 月 17 日）


Prompt caching 允许开发者在 API 调用之间缓存常用的上下文，现已在 Anthropic API 上推出。借助 prompt caching，客户可以为 Claude 提供更多背景知识和示例输出——同时针对长提示词将成本降低多达 90%、延迟降低多达 85%。Prompt caching 今天以公开测试版形式面向 Claude 3.5 Sonnet、Claude 3 Opus 和 Claude 3 Haiku 提供。

何时使用 prompt caching

当你想一次性发送大量提示词上下文，然后在后续请求中反复引用这些信息时，prompt caching 会非常有效，典型场景包括：

  • 对话式智能体：为长对话降低成本和延迟，尤其是包含长指令或上传文档的对话。
  • 编程助手：将代码库的摘要版本保留在提示词中，提升自动补全和代码库问答的效果。
  • 大型文档处理：在提示词中纳入完整的长篇材料（包括图片），而不会增加响应延迟。
  • 详尽的指令集：分享大量的指令、流程和示例，精细调校 Claude 的回应。开发者常在提示词里放几个示例，而有了 prompt caching，你可以放入数十个多样的高质量输出示例，获得更好的效果。
  • 智能体式搜索与工具使用：为涉及多轮工具调用和迭代修改的场景提升性能——这类任务的每一步通常都需要一次新的 API 调用。
  • 与书籍、论文、文档、播客转录等长内容对话：把整篇文档嵌入提示词，让用户直接向它提问，让任何知识库都“活”起来。

早期客户已在多种场景中通过 prompt caching 获得了可观的速度与成本改善——从纳入完整知识库、100 个示例的 few-shot 提示，到把对话的每一轮都包含在提示词中。

缓存提示词如何计费

缓存提示词的定价取决于你缓存的输入 token 数量和使用该内容的频率。写入缓存的价格比任一模型的基础输入 token 价格高 25%，而使用缓存内容的成本则低得多，仅为基础输入 token 价格的 10%。
