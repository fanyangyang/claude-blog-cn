AI 模型的表现好坏，取决于提供给它的上下文。像 Claude 这样的 AI 助手可以回答问题、完成种类惊人的任务，但如果无法访问所需的数据或工具，它们能为你做的就很有限。通常你的解决办法是在不同标签页之间复制粘贴上下文——无论是在 Google Drive 中编辑文档、在 Slack 中回复话题，还是在 IDE 中更新代码。这个过程缓慢、手动，还有遗漏重要上下文的风险。

Model Context Protocol（MCP，模型上下文协议）提供了一种开放的解决方案，并已在所有 AI 应用和助手中广泛可用。在本文中，你将了解 MCP 是什么、它如何工作、为什么重要，以及它适合谁。你会看到 MCP 的实际应用示例，并理解如何从今天开始使用或基于 MCP 进行构建。

什么是 Model Context Protocol（MCP）？

Model Context Protocol 是一个开放标准，定义了 LLM 与外部系统通信的方式。

可以把 MCP 理解为「LLM 的 USB-C」。正如 USB-C 为你的手机、笔记本和其他设备提供了一种通用接口，MCP 为 LLM 连接外部系统提供了一种通用格式。在 USB-C 出现之前，每种电子设备都有自己的数据线：iPhone 用 Lightning，Android 用 micro-USB，相机用专有接口。随着越来越多的设备采用 USB-C，整个生态系统的连接变得无缝。

MCP 为 AI 集成带来了同样的简洁。在 MCP 出现之前，每个应用和数据库都需要定制代码才能与 LLM 连接。Google Drive 需要一套集成，Slack 需要另一套，Figma 又需要一套。现在，MCP 提供了单一、标准化的格式，把这些工具连接到 Claude 及其他 AI 应用。

MCP 从何而来？

MCP 诞生于 Anthropic，由 David Soria Parra 和 Justin Spahr-Summers 创建。这个想法源于 David 的一个烦恼：他要在 Claude Desktop 和他的集成开发环境（IDE）之间不断复制代码。意识到这是一个典型的 M×N 问题——多个应用需要多个集成——David 向 Justin 提议构建一个协议来解决它。他们基于广受欢迎的 Language Server Protocol 设计了 MCP，并于 2024 年 11 月在 Anthropic 的支持下开源，以确保整个 AI 生态系统都能从中受益。

MCP 如何工作？

MCP 采用双侧架构。像 Claude 这样的 AI 智能体和聊天机器人创建 MCP Client，从而连接到 Notion、Canva、Figma 等应用；而这些应用通过 MCP Server 把自己的工具和数据开放出来。

通过构建 MCP Client，AI 智能体和聊天机器人可以访问社区构建的数千个 MCP Server，从而拥有一条直接的路径来扩展自身能力。智能体还可以通过 MCP 隧道访问防火墙后面的 MCP 服务器。通过构建 MCP Server，公司和开发者可以让自己的产品直接为 AI 所用，开辟一条提供价值的新途径。

由于 MCP 是开源的，任何人都可以构建 MCP Server 或 Client。

MCP 为什么重要？

MCP 让 LLM 得以超越聊天、执行现实世界的任务：阅读一封邮件往来并回复、访问代码库并部署更新，或者审阅一份设计简报并生成初稿。该协议为 LLM 连接外部系统、工具和应用以访问数据、执行操作奠定了基础。这带来了：

AI 的通用兼容性

AI 助手可以访问数千种工具——一旦某个 AI 助手实现了 MCP（通过 MCP client），它就能立即连接到数千个兼容 MCP 的应用，从专业编码工具到企业工作流平台，无需为每一个单独构建定制集成。

工具和应用一次性连接到所有 AI 助手——Notion、Figma、Asana 等公司只需构建一个 MCP 服务器，即可与任何兼容（即实现了 MCP client）的 AI 助手配合。开发者只需构建一个集成，就能覆盖所有 AI 连接。

开放、AI 原生的生态系统

任何人都可以构建和分享——作为开放标准，开发者或公司发布的 MCP 服务器与任何 MCP client 兼容。这种开放性造就了一个由数千个社区构建的服务器组成的繁荣生态系统，加速了面向 AI 助手的工具和应用普及。

让软件从设计上就可被 AI 访问——传统软件是为使用 Web 界面的人类构建的。MCP 提供了一个专为 AI 交互设计的并行接口，让应用真正成为 AI 原生。这意味着 AI 模型与人们已经在使用的工具之间，会有更好、更可靠的集成。

智能体的基础协议

MCP 为 AI 智能体构建了访问任意数量服务和工具的基础设施，实现真正的端到端任务自动化。随着越来越多的应用采用该协议，AI 智能体独立处理复杂多步骤工作流的愿景正变得越来越切实可行。

MCP 适合谁？

开发者获得一种标准化的方式：只需构建一次集成，即可与任何兼容的 AI 配合工作。企业可以获得安全、由 IT 部门管控、且能在整个组织内规模化扩展的 AI 连接。消费者则可以即时把自己喜欢的工具连接到 AI，无需任何技术知识。

面向开发者：一个标准连接 AI 与应用

开发者只需遵循单一标准，就能将外部产品连接到你的 AI 应用和智能体。这简化了构建集成的过程，增加了可连接产品的数量，也提升了整个生态系统中连接的质量和安全性。

要构建一个连接众多应用的智能体？还是要构建一个被众多智能体连接的应用？MCP 让你通过精简的集成接入一个兼容工具的生态系统。

面向企业：覆盖整个组织的安全、可扩展 AI 连接

企业可以更有效地推动 AI 工具和应用的内部采用，因为 MCP 简化了将你的系统连接到 AI 的过程。这有助于让 AI 在组织内部实现更紧密的连接，扩展它对员工的能力和用处。

面向消费者：即时访问你喜欢的工具

MCP 为终端用户在他们喜爱的 AI 助手与工作工具之间提供了无缝连接。它让任务自动化更容易，也免去了跨标签页复制粘贴的麻烦。简而言之，MCP 让 AI 更好地访问和连接你的世界。

在 Claude 中，你可以即时连接到被称为 Connectors（连接器） 的 MCP Server。这为你提供了一种直接的方式，把 Claude 连接到你常用的工作应用。

FAQ

MCP 只适用于 Claude 吗？

不是。MCP 是开源协议。虽然 Claude 率先采用了 MCP，其他 AI 提供商现已采用同一协议，任何人都可以连接到同一套 MCP 服务器生态。

使用 MCP 需要编程技能吗？

使用 connectors 不需要。浏览、安装、完成认证，就这些。构建自定义 MCP 服务器需要 TypeScript 或 Python 知识，但不断扩充的 connector 库已经覆盖了大多数主流工具。

MCP 的安全机制是怎样的？

每个服务器会请求特定权限，以允许 Claude 访问。你可以批准或拒绝访问，也可以随时撤销权限。

MCP 的性能如何？

MCP 使用高效的协议。本地服务器的 Stdio 传输开销极小。远程服务器的 Server-sent events (SSE) 和 Streamable HTTP 保持持久连接。响应流式传输可避免大数据操作超时。协议支持分页、过滤和部分响应，以高效处理大型数据集。
