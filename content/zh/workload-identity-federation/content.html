Workload Identity Federation（WIF，工作负载身份联合）现已在 Claude Platform 上正式发布。WIF 兼容任何符合 OIDC 规范的身份提供商，覆盖所有 Claude API 端点，包括通过我们的第一方 SDK 和 Claude Code 访问端点的场景。

有了面向工作负载的 WIF 和面向交互式会话的 ant auth login，开发者在基于 Claude Platform 构建时完全无需接触静态 API 密钥。

Workload Identity Federation 的工作原理

WIF 用请求时签发的短期、限定范围的凭据取代静态 API 密钥。无论你是运行 GitHub Actions 的两人初创团队，还是拥有精细凭据策略的企业，现在都可以像验证技术栈中其他系统一样，向 Claude Platform 完成身份验证。

有了 WIF，就不存在需要创建、轮换或可能泄露的静态 Anthropic 凭据。工作负载使用它们已有的身份进行认证：AWS IAM 角色、GCP 或 Kubernetes 服务账号、Azure 托管标识、GitHub Actions 令牌、Okta，或其他符合 OIDC 规范的提供商。

我们还在 Claude Platform 中引入了服务账号，让每个工作负载都拥有自己的身份、角色和审计轨迹，而不是共享一个 API 密钥。首先，一条联合规则将外部身份绑定到某个服务账号。然后，当工作负载请求访问时，Claude Platform 会验证该工作负载的签名 OIDC 令牌，将其声明与你的联合规则进行匹配，并签发一个受该服务账号角色约束的短期访问令牌。每一次交换和请求都会记录到你的审计日志中对应的服务账号之下。

几分钟内配置好你的第一个工作负载

Claude Console 提供了配置工作负载身份的引导式设置流程。设置过程会验证每一个步骤，并以一条测试命令收尾，确认你的工作负载能够通过认证。

无需静态密钥即可运转整个组织

WIF 兼容用于组织管理的 Admin API。联合规则可以通过细粒度 scope 配置为实现最小权限访问。 

对于大规模运营的组织，联合配置也完全支持编程化操作。全新的 Admin API 端点让你可以创建和更新签发者、服务账号及联合规则。
