自动模式（auto mode）现已是 Claude Code 的默认设置。你不再需要逐一批准智能体想要运行的每条命令，而是由一个分类器评估每个操作，并拦截那些看起来可能有危害的操作。 

自动模式的设计化解了智能体编码中一个常见的取舍：速度与安全。逐一审查每条命令能让人类保持在决策回路中，但一旦会话延长到数小时或并行开上多个，这种监督就成了瓶颈。完全跳过权限检查确实更快——但这也正是提示词注入、范围漂移，以及偶尔误删生产资源得以通过的途径。 

自动模式填补了这一缺口的大部分。在内部评估中，分类器捕获危险操作的能力超过了开发者手动点击权限提示时的表现，其性能也经受住了第三方红队测试的考验。 而且由于会话暂停得更少，在所有 Claude Code 的使用中，Claude 在两次打断之间的工作时长达到了此前默认设置的 9 倍。 

为了解自动模式在生产环境中的实际表现，我们与 Nuro、Gusto 和 Garner Health 的团队聊了聊他们如何以及为何把自动模式作为日常主力，在生产环境中平衡速度与安全。 

在 Nuro 驱动更长时间运行的自主智能体

Nuro 是一家开发通用 L4 级自动驾驶技术的实体 AI 公司，于 2025 年底采用 Claude Code，到今年 3 月它已成为公司最受欢迎的智能体编码工具。 

在自动模式发布之前，资深软件工程师 Kai Zhou 就已经开始原型化一个内部替代方案：一个钩子把每个待执行操作发送给一个小模型，90% 的情况下自动批准常规操作，其余任何敏感操作则转发到 Slack 由人工审查。这个原型回应了一个真实矛盾：工程师们厌倦了守着批准提示点个不停，但从公司安全与法务的角度看，完全跳过权限又太危险，不能开绿灯。自动模式一发布，Kai 就把这个副项目搁置了。 

如今，Kai 写的所有东西都用自动模式运行。 

“我不想坐在那里一直点批准，”Kai 说。“我 100% 的编码工作都用自动模式。大多数时候，我会开三四个并行运行自动模式的会话，需要时再去查看一下。”

例外是涉及其他团队的工作。比如，当 Claude Code 代表他审查 Pull Request 时，Kai 会切回交互模式，在发出前逐一审查。

自动模式的运行也不是毫无约束的。Nuro 大量使用 Skills，工程师们会在设置中直接拒绝最危险的命令，比如递归删除。分类器在这些护栏之内做出自己的判断。

不过，自动模式带来的更大解锁，是能够启动那些在工程师下班后仍在继续运行的工作。具体来说，Kai 的团队用自动模式驱动长时间运行的研究智能体，对自动驾驶技术栈背后的评估指标做爬山优化：这类任务有清晰、可度量的信号，智能体可以自行迭代。 

一夜之间，一个智能体可以研究评估套件标记出的假阴性、起草方案、运行实验，并持续迭代结果。这种方法可以推广到任何有明确评估方法的任务——Nuro 的另一个团队用它来压缩某个二进制文件的内存占用——因为指标本身就会告诉智能体它是在进步还是在退步。

“前几天，我晚上 10 点启动了一个智能体，它一直运行到凌晨 5 点——早上给了我三个 PR，”Kai 说。“我觉得这相当了不起。只有自动模式才能支撑这种工作负载。”

在 Gusto 更快也更安全地交付 PR

在领先的中小企业科技公司 Gusto，转向自动模式最初是一次主动的安全升级。

Martin Emde 在公司的 AI Dev Tools 团队工作，他此前目睹了权限疲劳如何拖慢团队。自动模式让他们在保持控制与安全的同时获得了同样的速度，而且自从在工程部门全面铺开后，整体的权限负担已明显下降。

自 12 月以来，Martin 已经启动了 2425 个 Claude Code 会话，自动模式是他的日常主力。过去常常卡在文件夹访问审批上的跨仓库工作如今可以不间断运行，无人值守的任务——比如从 GitHub、Slack 和 Jira 汇编每日纪要——也都能自行运转。在他团队自己的分析中，2026 年 5 月中旬以来大约 10% 的会话记录包含一次自动模式拦截，这证明分类器在切实发挥作用，同时没有拖累正常任务。 

“自动模式在速度和控制之间给了我们一个更安全的平衡点，”Martin 说。“我们既能去掉重复的提示、提升生产力，又不用在安全上妥协。我们可以看到自动模式在正确的时机出手，这给了我们快速行动的信心。”

Gusto AIT 云工程团队的 Chad Kunsman 从另一个方向得出了同样的结论。他的工作——端点排查、日志审计、连接器管理、跨一堆 MCP 服务器的文档摄取——都是以二十分钟为单位的短促冲刺，而非通宵马拉松。他追求的不是更长的运行时间，而是想要绕过权限（bypass permissions）那种免盯管的节奏，同时又不必暴露于一个坏提示或一次提示词注入溜过检查的风险。

“考虑到它对提示词注入的防护，以及它会核验你正在做的事是否与你的要求一致，它是比 bypass permissions 更好的选择，又比权限提示快得多，”Chad 说。

在分类器确实出手的少数场合，Chad 说它判断得很准。“它拦下我的时候，理由说得通，还会解释原因。我当时正在偏离最初的要求，它来确认了。它的判断完全不离谱。”

对于最敏感的工作，Chad 仍会走出自动模式。当会话深入到生产基础设施——Terraform、AWS、对线上 API 的直接 POST 调用——他会切换到接受编辑（accept edits）模式，逐一人工核验每个工具调用。“你必须权衡节省的时间与它可能出错的地方，以及那会有多灾难性，”他说。“归根结底，出了问题你仍然要负责。”

这种判断运作在一个更广的纵深防御体系之内：Gusto 将 MCP 流量经由一个带有工具防护和提示检查的受治理代理层路由，因此在自动模式介入之前，智能体就已经在严格受限的权限下工作了。 

在 Garner Health 加速软件开发生命周期（SDLC）

医疗技术公司 Garner Health 于 2 月向全公司 550 名员工、覆盖所有职能推广了 Claude Code。这个工具接入了包括 Salesforce、Zendesk 和 Snowflake 在内的所有核心系统，公司也鼓励员工每周花大约两小时，把自己工作中最可复用的部分自动化。

在自动模式之前，这种规模是伴随开销的。Garner 的平台工程经理 Evan Magnussen 把权限管理描述为一个枯燥的循环：手工维护获批命令清单，然后眼看着管道命令被拒。

如今，Evan 和他的大多数同事在每个会话中都使用自动模式，从研究代码库到通过 MCP 管理外部集成。

“我们为整个工程组织建立了一套标准化的软件开发生命周期，而这只有在自动模式下才真正可行，”Evan 说。“员工们觉得如释重负。他们不必再连续好几个小时盯着自己的智能体了。”

这套生命周期以一组标准化 Skills 插件的形式运行。一个智能体接手任务，探索它能访问的上下文，将上下文文件提交到仓库，运行 Evan 所说的“对抗式研究”来压测自己的假设，然后进入实现阶段——只有当它需要自己找不到的上下文时才停下来找人类。Evan 指出，这些重研究的阶段在自动模式之前是不可能实现的。

开箱即用的分类器几乎不需要调校。Evan 唯一的调整与 Nuro 的 Kai 相同：他配置自动模式不去批准与他人沟通的操作，比如发送 Slack 消息或邮件。 

“我个人不喜欢 Claude 在我与另一个人沟通时擅自替我行动，”他说。那些从事核心知识产权工作的团队——在自动模式之前对跳过权限最持怀疑态度的人——也学会了调校分类器注入的提示，使其对自己的工作更宽松或更严格。

他对其他准备推广的企业有什么建议？大胆拥抱，并建立正确的管控，这样既能赋能工程师，又能确保安全部署。“如果我们说，大家都去自建各自的工作流，而我们没有任何遥测数据，那会非常危险，”Evan 说。“正因为我们有遥测，正因为我们已经建立了相对标准化的工作流，我们才更有信心。”
