更新：auto mode 已在 Claude Code 中面向所有用户正式发布。（2026 年 7 月 10 日）

今天我们推出 auto mode（自动模式），这是 Claude Code 中的一种全新权限模式：由 Claude 代表你做出权限决策，同时由保障机制在操作执行前进行监控。它目前已作为 research preview 在 Team 计划中上线，并将在未来几天内推送给 Enterprise 计划和 API 用户。

工作原理

Claude Code 的默认权限设置刻意保持保守：每一次文件写入和 bash 命令都需要审批。这是一个安全的默认值，但意味着你无法启动一个大型任务后转身离开，因为 Claude 会在执行过程中频繁请求人工审批。虽然有些开发者会选择用 --dangerously-skip-permissions 绕过权限检查，但跳过权限可能带来危险且具有破坏性的后果，不应在隔离环境之外使用。

Auto mode 是一条中间路线：它让你能够以更少的中断运行更长的任务，同时相比跳过全部权限又引入更小的风险。在每次工具调用执行之前，会有一个分类器对其进行审查，检查是否存在潜在破坏性的操作，比如批量删除文件、敏感数据外泄或恶意代码执行。

分类器认定安全的操作会自动继续执行，有风险的操作则会被拦截，并引导 Claude 改用其他方式。如果 Claude 执意执行持续被拦截的操作，最终会触发一个面向用户的权限确认提示。

预期效果

与 --dangerously-skip-permissions 相比，auto mode 降低了风险，但并未完全消除，我们仍然建议在隔离环境中使用它。分类器仍可能放行某些有风险的操作：例如用户意图模糊不清，或者 Claude 对你的环境缺乏足够上下文、无法判断某个操作可能带来额外风险时。它偶尔也可能误拦无害的操作。我们会持续改进这一体验。

Auto mode 可能对工具调用的 token 消耗、成本和延迟产生轻微影响。

开始使用

Auto mode 今天已作为 research preview 面向 Claude Team 用户在 Claude Code 中提供，并将在未来几天内逐步推送给 Enterprise 和 API 用户。它同时支持 Claude Sonnet 4.6 和 Opus 4.6。

  • 面向管理员：Auto mode 即将面向 Enterprise、Team 和 Claude API 计划的所有 Claude Code 用户开放。若要在 CLI 和 VS Code 扩展中禁用，请在托管设置中设置 "disableAutoMode": "disable"。在 Claude 桌面应用中，auto mode 默认处于关闭状态，可通过 Organization Settings -> Claude Code 开启。
  • 面向开发者：运行 `claude --enable-auto-mode` 启用 auto mode，然后按 Shift+Tab 切换到该模式。在桌面应用和 VS Code 扩展中，先在 Settings -> Claude Code 中打开 auto mode，然后在会话的权限模式下拉菜单中选择它。
