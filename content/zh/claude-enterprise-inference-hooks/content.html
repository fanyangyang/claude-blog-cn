推理钩子（Inference hooks）让你的合规团队能够在每个提示词和工具调用响应到达 Claude 之前对其进行检查和策略执行——覆盖 Claude Enterprise 的各个产品界面，包括聊天、Claude Code、Claude Cowork 等。由你的 DLP 服务器决定拦截还是放行，Claude 会实时执行该决定，在未经批准的内容到达 Claude 之前将其拦截。

安全团队要求所有员工可能传输敏感数据的通道都必须经过其团队控制的检查点。在此之前，原生内联执行仅限于 Claude Code 的客户端钩子（hooks）。推理钩子弥补了这一缺口，以单一执行层覆盖所有 Claude Enterprise 产品界面，无需为每个产品单独集成或部署智能体。 

推理钩子如何工作

当组织开启推理钩子后，每个推理请求都会通过经过签名的 WebSocket 连接路由到一台安全服务器。在模型开始生成之前，Claude 会将提示词及其上下文发送到你的服务器。你的服务器返回裁决结果——允许或拒绝——Claude 只有在收到结果后才会继续。同样的检查也会作用于工具调用：当 Claude 调用某个工具时（包括通过 MCP、Skills 和插件连接的工具），工具的响应会在返回给模型之前先接受检查。

各团队已经在实际运用这种实时检查。“推理钩子增加了一个检查点，可以在模型看到内容之前实时检查流向 Claude 的数据，”Bandwidth 的信息安全副总裁 Andrew Grimmett 表示。“这让我们能够在不放弃控制权的情况下，更安全、更快速地推进 AI 应用。”

推理钩子的使用方式

将你现有的 DLP 体系扩展到 Claude。推理钩子采用开放的、基于 webhook 的协议，并发布了正式的数据模式（schema）。这使得部署非常简单——只需将它指向你的其他工具已经在上报的同一台服务器，包括 Netskope、Palo Alto Networks、Proofpoint、Zscaler，或你自建的 AI 安全服务器。

通过一套配置覆盖聊天、Claude Code、Cowork 以及其他 Claude Enterprise 产品。在组织层面开启一次推理钩子，它就会应用于所有 Claude Enterprise 产品界面，包括通过 MCP 连接器、Skills 和插件发起的工具调用。

借助影子模式（始终允许）、基于角色的豁免和按百分比的灰度发布来简化上线过程。你可以自定义失败策略容忍度、超时等设置，以匹配你组织的风险偏好。

开始使用

推理钩子目前以测试版形式向 Claude Enterprise 客户提供。请阅读文档，配置你组织的 DLP 服务器，并开始在 Claude Enterprise 的各个产品界面上执行策略。

对于安全厂商而言，推理钩子基于带有公开文档化模式的 webhook 协议构建，因此你可以构建集成，Claude Enterprise 客户就可以将其组织指向你的平台。
