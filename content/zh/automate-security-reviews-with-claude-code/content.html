今天，我们在 Claude Code 中推出自动化安全审查。借助我们的 GitHub Actions 集成和全新的 /security-review 命令，开发者可以轻松让 Claude 识别安全隐患——并接着让它修复这些问题。

随着开发者越来越依赖 AI 来更快地发布软件、构建更复杂的系统，保障代码安全变得愈发关键。这些新功能让你能够把安全审查融入现有工作流，在漏洞进入生产环境之前将其捕获。

在终端中审查代码漏洞

全新的 /security-review 命令让你可以在提交代码之前，从终端随时运行安全分析。在 Claude Code 中运行该命令，Claude 就会搜索你的代码库中的潜在漏洞，并详细解释发现的每个问题。

该命令使用一个专注安全的专用提示词，检查常见的漏洞模式，包括：

  • SQL 注入风险
  • 跨站脚本（XSS）漏洞
  • 身份验证与授权缺陷
  • 不安全的数据处理
  • 依赖项漏洞

在问题被识别后，你还可以让 Claude Code 实现相应的修复。这让安全审查融入你的核心开发循环，在问题最易修复的早期阶段就将其捕获。

为新拉取请求自动执行安全审查

全新的 Claude Code GitHub Action 将安全审查更进一步，在拉取请求创建时自动对其进行分析。完成配置后，该 Action 会：

  • 在新拉取请求创建时自动触发
  • 审查代码变更中的安全漏洞
  • 应用可自定义的规则，过滤误报和已知问题
  • 在 PR 中以行内评论的形式发布发现的隐患，并附上修复建议

这为整个团队建立了一致的安全审查流程，确保任何代码都经过基线安全审查才能进入生产环境。该 Action 可以与你现有的 CI/CD 流水线集成，并可按团队的安全策略进行定制。

提升 Anthropic 的产品安全

我们自己也在使用这些功能，帮助保障团队发布到生产的代码的安全，其中就包括 Claude Code 本身。自设置该 GitHub Action 以来，它已经在我们自己的代码中发现了安全漏洞，避免其被发布出去。

例如，上周我们的团队为一个内部工具构建了新功能，该功能需要启动一个仅接受本地连接的本地 HTTP 服务器。GitHub Action 识别出一个可通过 DNS 重绑定（DNS rebinding）利用的远程代码执行漏洞，并在 PR 合并之前就完成了修复。

在另一个案例中，一位工程师构建了一个代理系统，用于安全管理内部凭证。GitHub Action 自动标记出该代理存在 SSRF 攻击漏洞，我们随即修复了这一问题。

开始使用

这两项功能现已面向所有 Claude Code 用户开放。要开始使用自动化安全审查：

  • 关于 /security-review 命令：只需将 Claude Code 更新到最新版本，然后在项目目录中运行 /security-review。参阅文档自定义你自己的命令版本
  • 关于 GitHub Action：参阅文档获取分步安装和配置说明
