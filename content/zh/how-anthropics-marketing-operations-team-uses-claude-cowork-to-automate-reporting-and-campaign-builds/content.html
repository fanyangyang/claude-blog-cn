营销运营团队要花相当一部分时间，让营销项目背后的系统与业务保持同步。自动化固然在他们的职责范围内，但实际工作却远非自动化可言：营销技术工具之间无法干净地集成，报表要靠手工汇总，落地页只能一个一个地搭。

Anthropic 营销运营团队的 Ian Chan 过去每周要花一到两天时间整理每周营销指标回顾。负责活动运营的 Annabel Custer 过去每上线一个新活动，都要按顺序在 Salesforce、HubSpot、Swoogo 和邮件工具里逐个点击配置。如今，两人都在 Claude Cowork 中搭建了工作流，把过去几天的人工工作压缩到了几个小时。

省下来的时间改变了他们工作的形态。Ian 和 Annabel 如今花在系统里点来点去的时间少了，而花在赋能、校验，以及营销团队赖以运转的底层数据和流程上的时间多了——因为公司里越来越多的人在自行拉取数据、主导自己的项目。

生成每周营销指标报告

在一个理想世界里，Ian 为营销团队和管理层准备的每周报告中的每一项指标，都应该躺在仪表盘里，他的工作只是把叙事组织起来。但现实中，有些指标已经在仪表盘里，有些还没从数据仓库同步过去，还有些根本没有接入仓库。新的指标可能只存在于一条 Slack 消息或一通电话的会议记录里。

在 Anthropic，业务变化的速度超过了传统报表管线的跟进速度，Ian 过去每周都要花一到两天时间追踪数据并核验。现在，Claude Cowork 承担了这份数据搜寻工作的大部分。

一个定时任务在每周日晚上运行，提示 Claude 阅读上周的回顾和最新的会议记录，查看 Slack 了解销售团队在关注什么，查询数据仓库，然后留下一个包含各项数字和若干建议关注点的文件夹。

周一早上，Ian 打开 Claude Cowork 拉取初版报告，其中包含指标表和建议的标题，也就是重点关注领域。

Ian 审阅之后，一旦确认或决定了叙事的焦点，就告诉 Claude 用支撑性细节和案例进行展开。有些周团队在响应销售侧的重点，有些周则在响应产品发布。到了季度交替时，Ian 会告诉 Claude 以季度计划开篇，并把季度回顾文档喂给它。

Claude 基于同样的数据和叙事生成管理层幻灯片：什么发生了变化、为什么，以及各团队正在采取什么行动。所有后续事项都会变成 Asana 任务。

当数字对不上时，Claude 会标记出差异，而不是瞎猜。比如销售团队经历了一次组织调整后，营销侧的报表数据与他们的数据不再吻合。Claude 标记了这个差异，并询问 Ian 该如何处理。

整个流程运行在与团队所用营销平台和工具相连的连接器之上，外加 Ian 搭建并持续更新的三个 Skills：

  • 一个准备 Skill 负责驱动报告组装，包括确定焦点、生成标题，以及用支撑细节进行展开。
  • 一个校对 Skill 会把草稿中的每一个数字与已验证的来源逐一核对。
  • 一个行动项 Skill 把后续事项转化为 Asana 任务。

在每次周度会话结束时，Ian 会请 Claude 总结本次出现的问题，看哪些应该写回 Skills。比如新的销售组织架构、他做的修正，或者他希望标题换一种框架来表述。就 Ian 的情况而言，这个过去最多耗时两天的工作流程，如今最多只需要两个小时。

现在，Ian 有相当一部分时间转而去帮助营销人员打磨问题、精炼提示词，以及在他们自己从 Claude 拉取数据时解读结果。他也有余力深入数据层，确保 Claude 对数字、定义和区域结构的理解与数据仓库保持一致。

人工校验已经成为两条工作流中不可或缺的一环——随着 Claude 把传统上占据营销分析师大量时间的枯燥手工任务自动化，这一转变正在加速。

自动化活动搭建与数据导入

搭建营销活动背后的基础设施，历来是营销工作中最依赖人力的环节之一。每一场活动、网络研讨会或整合营销活动，都需要在 CRM 中设置，在负责邮件序列及其自动化的营销自动化平台中设置，还要在负责注册页面和活动落地页的活动管理平台中设置。这些通常出自三家不同的供应商，而它们之间的集成很少是完整的。

在使用 Claude Cowork 之前，Annabel 要从专门的 Slack 频道接下每一个请求，然后手工完成整个流程。她的新方案则几乎完全由 Claude 处理。流程始于一张需求表单，申请人需注明所需的支持类型：活动搭建、数据导入、申请参会，还是审批支持。

每个小时，一个调度 Skill 会读取频道，挑选最紧急的请求，在工单上打上标记以避免重复处理，然后将其交给 Annabel 设置的五个专业 Skill 之一去执行具体工作。调度 Skill 本身不做任何活动设置；它的职责是决定接下来运行什么，而把它独立出来，让 Annabel 可以单独打磨每个专业 Skill，而不必触碰路由逻辑。

对于最复杂的请求类型——活动搭建，一个活动搭建 Skill 会端到端处理完整流程：创建 CRM 活动、搭建带工作流和列表的营销自动化活动、配置活动平台、起草邮件、生成落地页，以及它们之间的所有集成。

搭建完成后，它会移交给一个新的 agent 进行审计。审计 agent 从零开始、不带任何先验上下文，在正式上线的落地页上提交一次测试注册，在 Gmail 中打开确认邮件，如果一切正常就把 Asana 任务标记为完成。Annabel 会在每个结果发布前进行审阅。

这个工作流运行在与 Annabel 打交道的营销平台和工具相连的连接器之上，外加她搭建并随新边界情况不断更新的若干 Skills：

  • 一个调度 Skill 读取需求频道，把每个请求路由到下面正确的专业 Skill。
  • 一个活动搭建 Skill 驱动跨平台的端到端配置。
  • 一个网络研讨会落地页创建 Skill 为网络研讨会快速生成落地页。
  • 一个审计 Skill，由一个全新的独立 Claude 实例运行，在任务标记完成前验证活动搭建 Skill 的输出。
  • 一个申请参会 Skill 处理注册流程中的临时变更：
  • 一个审批支持 Skill 处理活动审批，并按计划节奏发送相应邮件。
  • 一个数据导入 Skill 清洗列表并处理参会者数据。

她还保持一个独立的"管理者"agent 常开。当某次运行出了岔子，她就打开管理者 agent，让它查看发生了什么，并提出调整建议。凡是值得保留的东西，都会写回相关的 Skill。

虽然这些自动化工作流会为 Annabel 节省大量时间，但她搭建它们的首要动机是工作质量。随着营销团队扩张，营销人员从手边随便哪个模板克隆活动页面可能产生各种 Bug，比如确认邮件里出现错误的城市名，或者落地页打不开。借助 Claude Cowork，她获得了大规模且跨活动一致的搭建质量。

随着 Claude 承担起活动运营中的重复性环节，Annabel 得以专注于更具战略性的项目，比如团队赋能，以及为实现更好的洞察而进行流程和活动架构的自动化与优化。

给营销运营团队的 Claude Cowork 入门建议

  • 把反复出现的修正变成 Skill。当你发现自己在同一件事上纠正 Claude 超过一次，这条反馈就应该写进一个 Skill。你甚至不需要亲手搭建 Skill：Claude 可以代劳。
  • 先搭建一个校对 Skill。校对 Skill 会检查 Claude 写进报告的每一个数字是否都能追溯到已验证的来源。
  • 让 Claude 复盘。Claude 阅读指令的方式与人类书写指令的方式不同，因此在一条新工作流的最初几次运行后，问问它指令里哪些地方不好懂。Annabel 会把暴露出的问题作为持续更新 Skills 实践的一部分，回写到相应 Skill 中。
  • 善用定时任务。每个周日晚上或每个小时自动运行的工作，就是没有人需要惦记着去做的工作。
