Claude Managed Agents 的 Memory 即日起以公开测试形式提供。你的 agent 现在可以从每一次会话中学习，使用一层在性能与灵活性之间取得平衡、针对智能优化的记忆层。因为记忆以文件形式存储，开发者可以导出它们、通过 API 管理它们，并完全控制 agent 保留什么。

Claude Managed Agents 中的 Memory 如何工作

Claude Managed Agents 的 Memory 是一层内置、针对智能优化的记忆层，让 agent 可以从每一次会话中学习。Memory 对照内部基准做了优化，面向那些跨会话改进、并彼此分享所学的长时运行 agent。

我们发现，当记忆建立在 agent 已经在用的工具之上时，效果最好。Claude Managed Agents 上的 Memory 直接挂载到文件系统，因此 Claude 可以依赖同样让它擅长 agentic 任务的 bash 和代码执行能力。有了基于文件系统的记忆，我们最新的模型会保存更全面、组织更好的记忆，并更会判断某项任务该记住什么。

面向生产级 agent 的可移植记忆 

Memory 为企业部署而设计，具备范围化权限、审计日志和完整的编程控制。Store 可以在多个 agent 之间共享，并设置不同的访问范围。例如，组织级 store 可以是只读的，而按用户划分的 store 允许读写。多个 agent 可以并发使用同一个 store，而不会互相覆盖。

记忆是可以通过 API 导出并独立管理的文件，开发者拥有完全控制权。所有变更都有详细审计日志，因此你可以判断某条记忆来自哪个 agent 和哪次会话。你可以回滚到更早的版本，或从历史中删除内容。更新也会作为会话事件出现在 Claude Console 中，方便开发者追溯 agent 学到了什么、从哪里来。

团队在构建什么

团队一直在用 Memory 闭合反馈循环、加快核验，并取代定制检索基础设施：

  • Netflix 的 agent 会跨会话携带上下文，包括花了多轮才挖出的洞察，以及人类在对话中途给出的纠正，而不必手动更新提示词和 skill。
  • Rakuten 基于任务的长时运行 agent 用 Memory 从每一次会话中学习，避免重复过去的错误，把首轮错误减少了 97%，且都在按工作区划分、可观测的边界之内。
  • Wisedocs 在 Managed Agents 上构建了文档核验流水线，用跨会话记忆发现并记住反复出现的文档问题，核验速度提升了 30%。‍
  • Ando 正在 Managed Agents 上构建工作场所消息平台，捕捉每个组织如何互动，而不是自己搭建记忆基础设施。
