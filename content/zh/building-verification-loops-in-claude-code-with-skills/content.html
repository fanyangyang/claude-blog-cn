大多数智能体编程（agentic coding）会话都遵循一个循环：你提出改动需求，Claude 收集上下文、采取行动、验证结果，必要时再回过头去收集更多上下文。

验证是智能体在回应之前检查自己工作的方式。Claude 已经会通过观察你代码库中的确定性信号来完成其中一部分，包括类型检查器、linter、测试和运行时错误。而 Claude 无法自行推断的部分，就变成了你手动检查某项功能时的那些步骤。 

不过，这些手动步骤完全可以转化为验证循环（verification loop）。在 Claude Code 中，验证循环是一个迭代过程：Claude 检查工作成果，并尝试修复问题。

在本文中，我们会介绍最常见的几类验证循环，并展示 Anthropic 内部在用的做法。随后我们会演示如何把你已有的手动检查编码成 skills，让 Claude 自己闭环反馈，而你可以在它迭代时去做别的事。

刚接触智能体循环？请先阅读循环入门。

什么是验证循环？

验证循环是一个不断重复的周期：AI 智能体检查自己的工作——运行测试、linter 或自定义检查——并在继续之前修复失败的部分。在 Claude Code 中，验证循环可以打包成 skills，这样每次会话都会自动执行相同的检查，而不必依赖人去记住它们。

内置的验证循环

在设计自定义验证循环之前，先了解一下 Claude 对多种验证循环的内置支持会很有帮助。常见的功能和做法包括：

  • /verify skill：构建、运行并观察应用中的变更。
  • 工具链：Claude 会尝试捕捉并根据你提供的任何工具（如 linter）的错误码和警告采取行动。一个好的实践是把确切的构建和测试命令写进 CLAUDE.md，这样 Claude 就不必去猜。
  • Code Review（research preview）：一项托管多智能体服务，可对你启用的仓库中的 PR 自动执行一轮审查。你可以手动修复问题后推送，也可以在问题上评论 @claude 来闭环（前提是你已按下方说明配置好 GitHub Actions）。
  • GitHub Actions：定义一个调用 Claude 并携带验证 skill 的 job，你在本地跑的那些检查就会在每次 push 或 PR 时自动触发。
  • Spec 校验：一个帮助你依据仓库中的 markdown 规格文档校验每次变更，并尝试修复违规之处的 skill。
  • Claude Managed Agents 中的评分标准（Rubrics，beta）：一项托管的智能体服务，允许你使用独立的评分智能体（grader agent）依据评分标准验证结果。失败的任务会自动循环返工。

编写验证循环 

当你在一个现有项目中发现，每次让 Claude 实现新功能后，自己都要重复做一些相同的小修正时，就该把这些步骤变成你自己的自定义验证循环了。第一步，是把你发现自己每次都在做的事情完整写下来。

如果你在启动一个新项目、需要明确项目应有的行为，同样如此。用平实的语言写出最佳实践版本，就像第一天入职时交给新同事的文档那样。

如果你说不清楚这条验证检查本身，可以先让 Claude 给出最佳实践，再在此基础上修改。你的版本大概会在几个具体细节上不同，而那些差异正是你要捕捉的东西。

实用提示：放进这里的检查不一定非要是定性判断。"拒绝任何没有回填（backfill）步骤就删列的迁移"是一条确定性规则，通用 linter 抓不住它，但项目专属的检查可以。任何你总是不得不靠手动把关的检查，都值得沉淀为一个循环。
