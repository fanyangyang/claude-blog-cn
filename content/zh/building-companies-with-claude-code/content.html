创业加速器 Y Combinator 自 2005 年以来已孵化超过 5,000 家公司，合计估值超过 8000 亿美元，其中包括 Airbnb、Stripe 和 DoorDash 这些家喻户晓的名字。

如今，Claude Code 这类智能体编程工具正在从根本上改变 YC 初创公司构建和扩张的方式。创始人现在可以直接从终端交付产品，把开发周期从数周压缩到数小时，甚至让非技术背景的创始人从第一天起就能与成熟玩家同台竞技。

我们与三家 YC 初创公司进行了对话，它们正是这场变革的生动注脚：

  • HumanLayer（F24 批次）用 Claude Code 构建了整个平台，并开创了上下文工程（context engineering）实践
  • Ambral（W25 批次）正借助用 Claude Code 和 Claude Agents SDK 构建的精密子智能体工作流，规模化其 AI 驱动的客户管理
  • Vulcan Technologies（S25 批次）用 Claude Code 应对政府和行业的监管复杂性

我们开始吧。

HumanLayer：从 SQL 智能体到规模化 AI 优先工程团队

Dexter Horthy 在构建管理 SQL 数仓的自主 AI 智能体时，注意到了智能体落地面临的一个根本性（但完全可以理解）的挑战：企业不愿意让 AI 应用在无人监督的情况下触碰敏感操作，比如删除数据库表。

一切始于那次产品转向

这个洞见成了 HumanLayer 的核心认知：软件中最有用的功能，往往也是风险最高的，对于非确定性的 LLM 驱动系统尤其如此。

"我们的 MVP 是一个在 Slack 中与人协作的智能体，可以做些基础清理工作，比如删掉任何 90 天以上没被查询过的表，"Horthy 解释道。"我们不放心让 AI 应用在无人监督的情况下跑原生 SQL，所以我们接入了基本的人工审批步骤。"

2024 年 8 月，Horthy 做出了一个 MVP，向旧金山湾区的各家初创公司演示，并拿到了第一批付费客户。

这些进展让 HumanLayer 进入了 YC F24 批次，团队随即全力投入构建一套 API 和 SDK，让 AI 智能体能够通过 Slack、电子邮件、短信等渠道向人类寻求反馈、输入和批准。

整个 2025 年第一季度，HumanLayer 团队做了大量客户调研，与数十个构建 AI 智能体的工程团队交流，发现智能体开发闭环中存在一个他们此前未曾预料到的缺口。

"每个团队都自己捣鼓了一套智能体架构，"Horthy 解释说。"我们意识到，光做一个更好的 API 是不够的——我们还需要帮助确立让整个生态走向成熟的模式和原则。"

于是 Horthy 把团队的经验总结成了《12-Factor Agents：可靠 LLM 应用的模式》。这份指南于 2025 年 4 月发布后迅速走红，浓缩了他们构建生产级智能体系统的经验，并为新兴的上下文工程学科提炼了最佳实践。

用 Claude Code 构建一切

带着这些认知，HumanLayer 团队开始探索新的产品方向和转型角度。

当 Anthropic 推出 Claude Code 时，Horthy 和团队早已是 Claude 模型编程能力的坚定拥趸。他们立即开始用它来做这些实验。

"我们所有东西都是用 Claude Code 写的，"Horthy 说。"当 Claude Agent SDK 随 Opus 4 和 Sonnet 4 一起推出、支持无头（headless）智能体执行时，我们就知道这会是件大事。"

在内部打磨 Claude Code 工作流数月之后，Horthy 开始向关系要好的创始人朋友们分享。

"让我下定决心全力投入的，是和 BoundaryML（YC W23）的 Vaibhav 的一整天结对编程，"Horthy 回忆道。"Vaibhav 起先是怀疑的，但当我们花 7 个小时交付了通常需要一到两周的工作量之后，他信了。我意识到这套工作流完全可以复制到其他团队和代码库。"

构建 CodeLayer：规模化 AI 优先工程

如今，HumanLayer 的产品 CodeLayer 帮助团队使用 worktree 和远程云端 worker 并行运行多个 Claude 智能体会话。他们发现了一个关键规律：一旦工程师掌握了 Claude Code，生产力提升如此显著，真正的挑战就变成了组织层面的——如何让这些工作流在整个团队中铺开。

"当团队里有多个人都在交付 AI 写的代码，你面对的就是一类完全不同的问题，"Horthy 解释说。"这是沟通、协作、工具和管理问题。你必须重塑团队构建软件的所有方式。"

自 2025 年第四季度初以来，HumanLayer 已与各种规模的工程团队敲定了多个大型试点，部署这些工具和工作流——而这一切都是用 Claude Code 构建的。

Ambral：用子智能体构建生产系统

Jack Stettner 和 Sam Brickman 创立 Ambral，是为了解决每个 B2B 初创公司创始人和首席营收官都熟悉的难题：随着公司规模化，驱动早期增长的创始人级客户亲密度变得难以维系。

用 Claude Agent SDK 改造客户管理

无论是一路狂飙的早期公司，还是成熟的企业，客户经理通常要同时打理 50 到 100 个客户账户。"你不可能用一个人五十分之一的注意力提供有效的客户管理体验，"Stettner 解释说。曾经装在创始人脑子里的客户上下文，如今散落在系统、日志、Slack 消息、会议纪要和产品使用数据中。

Ambral 把客户活动和互动中的信号合成为每个账户的 AI 驱动模型。系统能指出谁需要关注、为什么需要，自主推动或推荐客户扩展，并捕捉不满的早期信号以防止流失。

"我们想提供的是让每个客户都拥有一对一客户经理的体验，"Stettner 说。

作为这家年轻初创公司的 CTO 兼唯一工程师，Stettner 在开发上重度依赖 Claude Code，产品本身则由 Claude 的 Agent SDK 驱动。其技术架构反映出他对如何从不同 Claude 模型中榨取最大价值的深刻理解。

委派式工作流：Opus 负责思考，Sonnet 负责构建，子智能体全面出击

Stettner 采用了一套精确的工作流，把不同 Claude 模型的强项与子智能体结合起来：

"我用 Opus 4.1 做研究和规划。Sonnet 4.5 在把我用 Markdown 写的规划落地实现这件事上表现极其惊艳，"Stettner 解释道。

他的开发流程分为三个泾渭分明的阶段：

  1. 研究阶段（Opus 4.1）：围绕功能实现所需的任何背景做深入研究。"我认为最重要的是先研究再规划，"Stettner 强调。"让 Claude 替你做研究，产出一份大而全的长篇研究文档。"他会用一系列子智能体并行研究代码库的多个区域。
  2. 规划阶段（Opus 4.1）：制定一份分阶段实现功能的计划。"我会让 Opus 制定一个分阶段的计划——明确拆分成离散阶段，讲清楚具体怎么实现——然后我会修订这份计划。也许我会和 Opus 讨论某些细节问题，或者直接手动更新这个 markdown 文件。"
  3. 实现阶段（Sonnet 4.5）：系统化地执行计划的每个阶段。"然后我会用 Sonnet 4.5 去逐个实现每个阶段。"

在他尝试过的所有工作流中，这一套脱颖而出，而且受到了 Horthy 在 HumanLayer 所做工作的影响："我试遍了所有编程工具，也几乎试遍了所有模型。我只是认为 Anthropic 的模型目前在工具使用上是最强的，而这直接体现在写代码上。"

构建稳健的研究引擎

产品本身也呼应了这种多智能体思路。Stettner 用 Claude Agent SDK 构建了 Ambral 的核心研究引擎，为每种数据类型配备了专门的子智能体。

"我花了大量时间用 Claude Agent SDK 构建了一个非常稳健的研究引擎，可以处理所有这些数据，"Stettner 解释说。"它围绕 Claude 子智能体构建，每种数据类型我们都有一个专门理解该数据的子智能体专家。"

无论是用户与系统对话，还是 Ambral 为客户构建自动化，一切都由 Claude Agent SDK 和一组在使用数据、Slack 消息、会议纪要和产品交互之间检索与推理的子智能体支撑。

架构灵感直接来自 Stettner 的开发体验："我想正是 Claude Code 子智能体在开发上帮了我的大忙，让我想把同样的子智能体思路用到产品的研究引擎里。"

Vulcan Technologies：让非技术创始人也能交付产品

对 Vulcan 的联合创始人兼 CEO Tanner Jones 来说，Claude Code 的影响远不止生产力——它意味着创业的民主化。创立公司时，Vulcan 团队坚信一定存在一款能让政府为民众做得更好的产品。若没有 Claude Code，这个愿景将无从谈起，因为两位创始人都没有工程背景。

没有专职工程师也能交付产品

Vulcan 处理的是一个积累了数个世纪的问题：监管法规的复杂性。弗吉尼亚州的市民议会（House of Burgesses）是世界上最古老的连续运作的民主机构，正是这一挑战的缩影。四百多年的监管累积，造就了全美最细致复杂的法规体系之一。

当 Aleksander Mekhanik 和 Tanner Jones 在 2025 年 4 月共同创立 Vulcan 时，两人都没有传统的工程背景。Mekhanik 在大学学的是机器学习和数学，而 Jones 上一次写代码还是高中的一门 AP JavaScript 课，那时他们还在用纸笔写代码。然而这对搭档在 5 月 1 日前就为弗吉尼亚州州长办公室做出了他们第一款产品的原型——并从老牌咨询公司手中赢得了合同。

"整个原型都是用 Claude 做的，"Jones 解释说。"那还是 Claude Code 之前的时代。我们真的是把脚本复制粘贴到网页应用里，再换掉其中的方法。"做完原型后，他们聘请了曾在 Google 参与 Gemini 和 Waymo 工作的 CTO Christopher Minge。随后，当 Claude Code 在六月上线时，三人组的速度又一次倍增。

Vulcan 的 AI 驱动监管分析通过识别冗余和重复的监管要求，帮助弗吉尼亚州把新房均价降低了 24,000 美元，每年为弗吉尼亚人节省超过十亿美元。弗吉尼亚州州长对 Vulcan 的工作极为满意，甚至签署了第 51 号行政令，要求所有州机构采用"智能体 AI 监管审查"。

创业的民主化

对 Jones 来说，Claude Code 的意义超越了生产力指标。

"只要你懂语言、懂批判性思维，你就能用好 Claude Code，"他说。"我甚至觉得学人文的人可能还有点边际优势，因为我们与 AI 沟通的媒介就是语言。如果你对语言的驾驭力很强，擅长组织有序的列表、嵌套的要点和深思熟虑的流程，你的提示词可能执行得更好。"

Jones 将 Claude Code 视为 Vulcan 成功的关键组成部分："四个月，三位创始人，其中只有一位是严格意义上的技术背景，我们拿到了州政府和联邦政府的合同，并从顶级风投那里融了 1100 万美元的种子轮。没有 Anthropic 这些难以置信的工具，这一切都不可能发生。"

拥有"严格技术"背景的 Vulcan CTO Christopher Minge，也经历了自己对工程认知的转变。

"感觉就像我在 Google 有个同事，我把所有的想法和任务都交给他，他会频繁犯错，而我的职责是协调多个 Claude Code 实例，练就一双发现常见错误的火眼金睛，并高效地传达想法，"Minge 解释道。

来自 YC 创始人的最佳实践

这三家初创公司都打磨出了经过实战检验的方法，来最大化 Claude Code 的价值，包括：

1. 把研究、规划和实现拆分到独立会话

"别让 Claude 一边做研究、一边想规划、一边还忙着实现，"Stettner 建议。"用离散的提示词，把它们变成离散的步骤。"

这种模式可以防止上下文污染，让每个阶段专注于核心目标。为每个主要阶段开启新的 Claude Code 会话，只把提炼后的结论传递下去，而不是拖着整段上下文历史。

2. 对上下文管理保持刻意

Stettner 给其他创始人的建议围绕刻意的上下文管理展开：

"上下文至关重要。当我看到意外或低质量的输出时，通常是因为某处提示词里存在自相矛盾，"他解释说。"要对你放进系统提示词的信息、以及你选择开启新对话的时机非常刻意，因为你不想污染上下文。提示词里只要有矛盾，你收到的输出质量就会下降。"

3. 监控并及时打断思维链

"试着审视思维链，盯着它在做什么，"Jones 建议。"手随时放在'紧急制动'上，一旦出现不良行为就打断它。"

在运行多个实例时，这一点尤其重要。在前几次工具调用中就发现错误方向，远比让 Claude Code 跑完一整条歧路节省时间。

新建造者的优势

这三家初创公司展示了公司构建方式的根本转变。HumanLayer 在转型和扩张的同时，把如今被整个 YC 生态采用的上下文工程实践系统化了。Ambral 以精简的创始团队在海量规模上攻克客户成功。Vulcan 以非工程师身份赢得了政府合同。

构建软件的传统壁垒——技术专长、团队规模、开发时间——正在让位于新的竞争优势：清晰的思考、结构化的问题拆解，以及与 AI 高效协作的能力。
