在我们的创业公司如何用 Claude 构建系列中，我们介绍创业公司如何用 AI 改造自己的行业。本文讲述 Curative 如何在 Claude 上构建一套 agent 层级体系，使签约医疗服务提供方的速度比其团队 2025 年的水平快了约 50 倍。

快速概览
公司名称Curative
成立时间2020 年；2022 年推出健康计划
创始人Fred Turner（CEO）、Isaac Turner（CTO）、Tami Wilson-Ciranna（总裁）
技术栈Claude Platform、Claude Code、自研理赔系统
增长以 12.75 亿美元估值完成 1.5 亿美元 B 轮融资。165,000+ 名会员、1,200+ 家雇主（2025 年 12 月）。由 Gwen 签署 23,000 份提供方合同。每周新增 2,000 至 2,400 份合同，而 2025 年全年仅为 2,100 份。

Curative 向雇主销售健康保险，会员完成 Baseline Visit 后，网络内诊疗的共付额和免赔额均为 0 美元。Curative 并非从保险起家，它起初是一家实验室创业公司，按内部估算处理了全美 10% 的 COVID-19 检测，因此几乎与全国每一家保险公司都有过合作。

它的英国创始团队习惯了患者无需为医疗付费的体系，看到了种种低效之处，于是立志打造一家以预防为核心的支付方。他们后来意识到，自己严重低估了构建全国性网络有多难。

「有时候创业公司里的天真反而是好事，因为你不知道那是不可能的。然后一路走来，你会想出办法让它变得并非不可能。」Curative CEO Fred Turner 说，「去年我们签了 2,100 份合同，是前一年的两倍，但按每年 2,000 份算，我们意识到这仍然需要 30 年才能建成。全国性网络之所以只有寥寥几家，而且都是大约 30 年前建立的，是有原因的。」

Curative 需要加速签约，但仅靠招聘无法填补如此巨大的缺口。

他们的解决方案是 Gwen——一个从初次接触到签约全程负责单笔提供方交易的 agent，周围环绕着更小的 agent，负责审核其费率、检查其消息、回答其问题，并在遇到非标准定价时升级给人类。

以下是他们的构建方式，以及过程中出现的那些问题。

Gwen：提供方合同 agent

Gwen 同时处理主动咨询和主动外拓的线索。Gwen 的每次运行只处理一家提供方，主要运行在 Claude Opus 上，因此其他交易不会对它产生任何影响。

例如，如果某家诊所在 Curative 网站上填写了表单，Gwen 会研究这家诊所，并基于采购的理赔数据集和支付方如今必须公布的价格透明度文件，回复建议费率。Gwen 会向提供方展示这些市场费率数据，以辅助谈判。

费率审核员运行在 Sonnet 上。当 Gwen 想超出标准费率模板时，它会写明理由，由审核员判断该费率是否合理。

「很长一段时间里，Gwen 如果想超出模板一定幅度，就得进入一个庞大的审批队列，但后来我们逐步放宽了。让第二个 agent 审核费率，比直接给 Gwen 更多权限效果更好。」Fred 说。

Sonnet 费率审核员会通过 Gwen 约三分之二的请求，其余非标准的则交由 Fred 审批。

「我看到的请求要么来自大型医疗集团，要么是那种即便没有 agent 主导、也会找上我的特殊请求。」Fred 说。

主动外拓交易需要更多坚持，因为诊所通常很忙。有些提供方的回复要等到第十四封邮件和第九份传真之后。

一个运行在 Haiku 上的 judge 会在每条消息发出前先行阅读。Curative 是在 Gwen 把「最多能让到多少」的内部备注抄送给提供方之后才加上它的。被拦截的消息会连同原因返回，Gwen 可以据此重写并重试。

每份合同大约消耗 2,000 万 token 才能完成，成本约为最初的十分之一。这些效率提升支撑了 Curative 的核心策略之一：签约那些常被大型网络忽视的小型提供方。

「无论你是大型医院系统还是个体诊所，agent 都会给你同样程度的关注。」Fred 解释道，「在 agent 看来，这家提供方就是它唯一的焦点。」

谈判过程中，Gwen 会对照 Curative 的政策文件核查诊所提出的修改，然后编写 Python 把双方的改动合并成最终文档。

从填写表单到完成签署，整个过程最快可在一小时内完成。合同签署后，另一个资质认证 agent 会核查提供方的执照，还有 agent 负责载入提供方数据和合同，以便理赔据此定价。

自 Gwen 上线以来，Curative 的签约团队从 45 人增至约 55 人，每人的产出约为原来的 2.5 倍。他们把冷启动外拓和文书工作交给 Gwen，自己通过电话接手意向明确的线索。Curative 也会为 Gwen 促成的交易向签约团队发放报酬，让人类与 agent 共享同一目标。

「人们的工作更多变成经营关系，而不是处理文书。」Fred 说。

Fred 还认为，更快的签约有助于小诊所保持独立。「如果你开了一家诊所，却要花三个月才能进入网络并完成资质认证，那这三个月你就是拿不到钱。」他说。

Gwen 并非 Curative 唯一的 agent。另一个基于 Opus 的 agent Brad 帮助向雇主销售 Curative 的计划，主要通过经纪人渠道。Brad 会就每份报价跟进经纪人，并通过从核保人员以往手工清洗的电子表格中提取员工数据，帮助核保团队加快进度。

借助人机团队，Curative 现在可以在 30 分钟内回复通过邮件或传真提交的理赔争议，并附上一封针对该笔理赔的信函。「理赔争议回复过去大约需要 90 天，现在通过邮件或传真不到 30 分钟就能完成。」Fred 说，「多数支付方使用的是一套模板做邮件合并。这让提供方非常不满，因为模板通常并没有真正说明发生了什么。现在提供方会收到一封定制信函，说明这笔具体理赔的细节、当前进展以及原因。」

他们所有的 agent 都运行在自研的理赔、预授权和财务系统之上，这些系统由 13 名工程师今年用 Claude Code 重建。这个团队曾估算，仅构建一个理赔系统就需要 100 个工程师年。

「我们并不是想把这些 agent 接进某个理赔系统。」Fred 说，「理赔系统是运行在 AWS 上的 Python，它有一个 MCP，也有一个 API，而且是 Claude 写的，所以 Claude 理解它。」

Curative 从构建与人谈判的 agent 中学到了什么

以下是 Curative 团队关于如何构建与人谈判的 agent 的经验。

  • 从一个通用工具开始。「我们一开始想的是『哦，我们要有一堆工具』，但效果不太好，因为修改合同条款相当复杂。」Fred 说，「我们发现最有效的是让模型只拥有一个工具，也就是运行 Python，由它用 docx 库完成所有条款修改。效果非常好。」
  • 在人们习惯的渠道上与其接触。一个传真工具让 Gwen 的成交率提高了一倍多。许多提供方现在会手写在打印出来的传真件上，再传回给 Curative。「这就是在人们所在的地方与他们接触。」Curative CTO Isaac Turner 说，「没错，他们有邮件，但他们真正习惯的是传真。」
  • 让每次运行相互隔离。Gwen 的一次运行只处理一家提供方，且不跨交易保留记忆。Curative 的销售 agent Brad 确实会保留记忆，这有效但需要谨慎。「你可能会写下错误的备注，然后陷入死循环，因为它有一个永远无法清除的错误记忆。」Fred 指出。
  • 从运行之外改进系统。每隔几天，Fred 会给 Claude Code 同一个提示：抽样最近的 10,000 次运行，标出任何异常，并提交 PR 修复。「改进循环来自用 Claude Code 跑大量历史对话，并追问它本可以如何做得更好。」他说。
  • 先在远离 PHI 的场景中试验。很长一段时间里，Gwen 被禁止接触受保护健康信息（PHI），因此早期的错误都发生在风险较低的场景中。如今在 agent 接触 PHI 的环节，后端控制限制了哪些内容可以进入对话，agent 的活动也会被记录以供审计。「我们在那里学会了怎么做，然后把它转移到 PHI 领域。」Fred 说。签署商业伙伴协议（BAA，HIPAA 要求供应商处理 PHI 前必须签订的合同）也变得更简单了。「尤其是 Anthropic，在快速推出符合 HIPAA 要求的最新服务版本方面做得非常好。」Isaac 说，「尽管处于受监管领域，我们仍能很快地引入这些新技术。」
  • 留意 agent 开始自行做哪些事，并确保其符合你的风险画像。当提供方想要一份可在内部传阅的宣传单时，Gwen 用它自己的 Python 工具做了一份，并没有任何策略要求它这么做。当某家网络内诊所的前台拒绝接待一位会员时，Gwen 要求该诊所培训员工，随后确认该会员得到了接诊。

Curative 的下一步

接下来，Curative 计划把 agent 引入护理导航，扩展其 130 名会员指导与辅导人员的覆盖范围。

Fred 预计提供方一侧也会出现 agent。相当一部分理赔争议目前看来已由 agent 撰写，他希望提供方也能用 agent 来谈合同。「存在一个清算价格，你越快找到清算价格，大家就能越快专注于提供医疗服务。」他说。

来自 Curative 团队的最佳实践
agent 一开始应该拥有多少权限？比你认为它能处理的要少。Gwen 最初对任何超出模板的费率都设有人工审批队列。Curative 分步骤放宽限制，对更确定性的决策给予更大空间，随后又加入了费率审核员，而审核员未能通过的仍由 Fred 审批。
agent 出错时怎么办？提前做好预案，并与替代方案作对比。「标准不是完美。」Isaac 说，「标准是：如果你有一千个人在签合同，他们会犯下多少让你后悔的错误？」
如何审计数十万条消息？记录一切，为每条外发消息配备一个 judge agent，并让 Claude Code 对运行过程进行抽样检查。
