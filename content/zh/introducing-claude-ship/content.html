任何开过拉取请求（PR）的人都知道这流程怎么走。他们刚转去处理下一件事，评审意见就回来了。只好停下来，重新钻回旧代码，推一个修复，再等评审重跑一遍。然后还得去找人批准。

这样运作是有充分理由的。多数团队希望每一处改动都由人来批准，而当每一行代码都由人写时，这很容易跟上。但现在很多开发者用智能体写代码。在 Claude Code 团队，Claude 写下了我们的大部分代码，我们希望 PR 之后的每个环节也能以同样的速度推进。

这就是我们构建 Claude Ship 的原因，今天起以 beta 版提供。它可以评审 PR、修复 PR，并根据每个团队设定的策略判断哪些改动可以合并。团队始终掌控它在哪些地方运行、哪些改动需要人来把关。目标是：代码写得多快，交付就能多快。

符合条件的 Claude Enterprise 组织可领取至少 10,000 美元的 Claude Ship 额度，须在领取后 30 天内使用。领取截止日期为 2027 年 1 月 15 日。适用条款。

Claude Ship 如何工作：评审、修复与批准

Claude Ship 由已经正式可用的 Code Review，以及两个处于 beta 的新智能体组成：PR Steward 和 Claude Approvals。三者协同，把一个拉取请求依次带过评审、修复和批准决策，团队不必再手动管理每一个环节。

Code Review 会通过多个视角，对照代码库对拉取请求做深入评审。它收集发现的问题，以对抗方式逐一验证，进行分类，然后发布到 PR 上。在 Claude Code 团队，Claude 的评审只是更大流程中的一层，从 6 月到 9 月，合并的 PR 翻了一倍多，而被回退的比例下降了 40% 以上。Code Review 为团队提供快速评审、清晰的发现，并可按仓库选择 Quick、Standard 或 Deep 三种评审级别。

PR Steward 的职责是让 PR 保持通过状态，但它的设计目标不是批准或合并拉取请求。它会在 CI 检查失败、出现合并冲突，以及收到来自 Code Review、其他评审工具或团队成员的评审意见时介入。每次推送后，它会留言说明改了什么、如何撤销。开发者可以评论 @claude 并附上指令来引导工作，或评论 @claude stop 让它退后。

接下来，Claude Approvals 会执行团队写在仓库中某个文件里的批准策略。在策略允许的情况下，Claude 可以自行批准常规改动，也可以针对特定场景要求更深入的人工签核。它就像一个更聪明的 CODEOWNERS 文件。团队可以让 Claude Approvals 在决策过程中参考多种信号，包括 Code Review 的发现，或用自然语言编写的自定义分类器。对多数客户，我们建议先以仅观察模式启用，建立信心后，再配置分支保护要求 Claude Approvals 放行。

两种上手方式

开发者：在 Claude Code 里 /ship 一下

开发者可以用 Claude Code 中新的 /ship 命令，在自己的拉取请求上试用 Claude Ship。改动就绪后，运行 /ship。Claude 会推送代码、创建 PR、评审改动，并处理反馈和失败的检查，帮助它达到可合并状态。最终能合并什么，取决于开发者的权限和仓库的分支规则。

管理员与工程负责人：逐个仓库设定规则

为整个仓库开启 Claude Ship，它就会在团队设定的配置和批准策略下，自动处理该团队的所有拉取请求。开发者无需手动调用 /ship 命令。

  • 管理员决定 它在哪里运行。管理员为每个仓库分别开启 Code Review 和 PR Steward。当已连接的仓库在其默认分支上有策略文件时，Claude Approvals 就会启动，管理员也可以将其关闭。
  • 每个 仓库获得所需的设置。管理员选择评审级别（Quick、Standard 或 Deep）、选择评审何时运行，并配置支出上限。
  • 团队保留现有工具。Claude Ship 与现有的分支保护和必需检查兼容。

节奏由团队掌握。可以从一个仓库开始，选择评审级别和评审运行时机，设置每月支出上限，并让批准策略先在观察模式下运行，直到建立起信任。

Claude Code 团队如何交付

我们在自己的许多拉取请求上都运行 Claude Ship。最大的变化之一是：谁能对客户反馈采取行动。例如，Claude Code 团队的一位产品经理现在可以读一条反馈，与 Claude Tag 讨论想法与取舍，让它开一个 PR，然后转去处理下一件事，而 Claude Ship 负责把 PR 走完评审、修复和批准决策。

最近有位客户感到困惑，因为我们的 Analytics API 文档暗示 Admin 密钥可以拉取 Pro 和 Team 的用量数据。这位 PM 问 Claude Tag 是否已有修复在路上，它便开了一个。Code Review 没有发现阻塞项，文档评审人签核通过，Claude Approvals 放行，修复当晚就合并了。

客户怎么说

可用性

Claude Ship 面向 Claude Team 和 Enterprise 套餐提供，支持 GitHub 上的仓库。Code Review 已正式可用，PR Steward 和 Claude Approvals 处于 beta。

Claude Ship 的用量按 token 计费，因此开启后可能增加组织成本。具体金额取决于所覆盖拉取请求的数量和规模、评审级别、评审运行频率，以及 PR Steward 的工作量。管理员可以为 Code Review 和 PR Steward 设置支出上限。Claude Approvals 没有基础费用，但策略中的分类器按其使用的 token 计费；使用 Claude 评审的策略会触发一次计费的 Code Review，即使在观察模式下也是如此。运行 /ship 计入常规的 Claude Code 用量。

Claude Ship 不向启用 Zero Data Retention、HIPAA 配置或客户自管加密密钥的组织提供。

开始使用

开发者可以更新 Claude Code，在下一次改动时运行 /ship。/ship 从今天起在 Claude Code 和桌面应用中逐步推出。

已在使用 Code Review 的团队，可以为某个仓库添加 PR Steward，以及一个处于观察模式的批准策略。

初次接触 Code Review 的团队，可以阅读设置指南，连接 GitHub 并开启第一个仓库。
