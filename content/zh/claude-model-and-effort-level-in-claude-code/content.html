核心要点：

  • Claude 模型选择决定的是固定的权重集合，也就是模型的整体能力范围。虽然可以为模型提供上下文或进行引导，但模型的整体知识库和能力是既定的。
  • 投入程度（effort）的含义不止于"思考时间"。它控制的是 Claude 在你的请求上总体投入多少工作，包括读取多少文件、使用多少工具，以及在回头找你确认之前走多少步。
  • 常规任务选较小的模型，复杂或模糊的任务选较大的模型。从每个模型的默认投入档位开始，再根据你的工作类型将其调整为一种整体偏好，而不是逐任务调优。
  • 如果 Claude 已掌握所有相关上下文、确实尝试过却仍然出错，那是该换更强模型的信号；如果 Claude 是因为跳过了某个文件、没跑测试、或者重构做到一半就放弃而出错，那就该调高投入档位。

Claude Code 的投入档位与模型选择

Claude Code 提供两个看起来都能"让答案变得更好"的设置：模型和投入档位。你可能会认为，Claude Fable 5 这样的大模型会比 Claude Sonnet 给出更聪明的输出，而更高的投入档位意味着 Claude 在回答前思考更久。

第一种假设是准确的。按照业界标准基准测试，我们最大的模型确实能力更强。

但投入的含义不止于"思考时间"。投入档位控制的是 Claude 在你的请求上总体投入多少工作。它确实包括模型思考多久，但也包括：

  • 读取多少文件；
  • 核验多少内容；以及
  • 在向你汇报之前，把一个多步骤任务推进多远。

在更高的投入档位下，Claude 会在回到你面前之前完成更多这类动作（例如读文件、跑测试、反复检查）。在更低的档位下，它宁可向你索要更多上下文，也不愿自己花 token 去弄清楚某件事。
