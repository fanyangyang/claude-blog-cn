今天，我们推出 mods——用 TypeScript 编写的小型函数，可以改变 Claude Code 的工作方式。一个 mod 可以重写提示词、添加新的 UI、替换内置功能，或增加全新的能力。你可以自己编写 mod，也可以让 Claude Code 帮你写一个。Mods 随插件一起分发，所以你可以像安装任何插件一样安装和分享它们。它们可以在 Claude Code CLI 和桌面应用中运行。

Mods 对你机器的访问权限与 Claude Code 本身相同。它们没有沙箱隔离，你应该只从可信来源安装 mods，就像在电脑上安装任何代码一样。

想了解 mods 能做什么，可以阅读我们关于构建第一个 mod 的指南。

我们为什么构建 mods

开发者希望拥有更多对 Claude Code 工作方式的控制权，而不必等待我们发布新功能。Hooks 已经给了用户一部分这种控制，但 hooks 无法重写事件、绘制新的 UI 或替换功能。Mods 可以。

我们希望 Claude Code 用起来像你自己的工具，让你可以把它塑造成符合自己工作方式的样子。我们在发布前就在 GitHub 上分享了 mods 的设计，以收集开发者的反馈。感谢每一位参与讨论的人。

Mods 的工作原理

Claude Code 每做一件事，就会发出一个事件。例如调用工具、请求权限、绘制部分屏幕。一个 mod 就是挂钩到其中一个事件的函数。mod 可以在事件之前、之后运行，也可以替代该事件运行。它还可以包裹事件，在事件前后都运行代码。仅凭一个函数，mod 就能：

  • 在提示词到达模型之前重写它。
  • 阻止、重写或重试工具调用。
  • 批准或拒绝权限请求。
  • 在 Claude 读取工具输出前，将其中的机密信息脱敏。

Mod 还可以改变你看到的内容。它可以编辑或替换 Claude Code 绘制的部分界面，比如工具结果或 Claude 提出的问题。它可以添加按钮和输入框，其他 mods 可以在你点击它们时做出响应。目前，一个 mod 可以针对终端、桌面应用，或两者同时生效。

当多个 mods 挂钩同一个事件时，它们按照加载顺序运行。最先加载的 mod 最先看到事件，最后拿到结果。这样你就可以叠加来自不同作者的 mods。

你也可以用 Claude Code 来给 Claude Code 添加 mod。让 Claude 创建一个 mod，它可以编写 TypeScript、安装它，并在你的会话中热重载。

用你自己的功能替换内置功能

Claude Code 的部分内置功能现在以 mods 的形式提供。例如，内置的 /diff 功能现在就是一个 mod，所以你可以在（/plugin 中）关掉它，或者用你自己的版本替换它。我们计划逐步把更多内置功能迁移为 mods，这样你就可以把 Claude Code 精简到一个小的核心，再只加回你需要的部分。

面向团队和企业的 Mods

Mods 随插件一起分发，所以你现有的插件控制仍然适用。管理员可以允许或阻止插件市场。在 Team 和 Enterprise 计划中，所有者可以在管理控制台中设置这些。在 Claude API 和第三方 API 计划中，管理员将托管设置推送到用户的机器上。

在 Team 和 Enterprise 计划中，以及任何启用托管设置的机器上，一个名为 sec-default（“安全默认”）的内置 mod 会最先加载。它会阻止用户安装的 mods 做危险的事，比如覆盖你的权限拒绝规则。你可以查看源代码了解它限制了什么。管理员可以改为先加载自己的 mods。如果你这样做，请把 sec-default 加入你的列表，以保留它的限制。

团队还可以用 mods 构建自己的控制和功能。例如：

  • CI/CD 状态：mod 可以在对话旁的窗格中显示你的流水线状态，并在构建通过或失败时更新它。
  • 生产环境保护：mod 可以要求在任何命令触及生产配置之前先进行确认。
  • 审计日志：先加载的 mod 可以记录其他每个 mod 发起的每一次调用。

开始使用

Mods 今天就可以在 Claude Code CLI 和桌面应用中使用。你可以从 Claude 目录安装包含 mods 的插件，或者在 CLI 中运行 /plugin。要分享一个 mod，请把它打包进插件，然后提交到目录。 

要构建你自己的 mods，可以阅读我们的入门指南，或查看文档。
