消息线程（Message threads）现已在 Claude Platform 上公开测试。借助消息线程，智能体无需在每次调用时重新发送完整的对话历史，从而降低长时间运行会话的延迟。

消息线程的工作原理

一个编程智能体在单次会话中可能发起数百次请求，而每次请求都会重新发送此前的每一条消息和工具结果。一旦对话达到数十万 token，重发全部内容会在 Claude 开始响应之前增加额外耗时。借助消息线程，智能体只需发送自上一轮以来新增的内容，从而缩短首 token 时间（TTFT）。

对于大多数 Claude Code 用户，消息线程默认开启，500k 至 1M token 的请求中位 TTFT 大约降低 35%。

要使用消息线程，请在 Messages API 请求中添加 thread 参数。第一个请求包含完整对话并启动一个线程，之后每个请求只需包含新增消息以及上一条响应的 ID。在两次调用之间，我们会将每个线程保存在内存中，并对其加密且不写入磁盘。线程在其最后一次请求 5 分钟后过期，届时你的客户端会重新发送完整对话以开启新线程。虽然使用消息线程后每个请求变得更小，但 Claude 在每一轮仍会读取完整对话，因此 token 用量保持不变。

消息线程最适合对延迟敏感的活动会话，包括：

  • 长时间运行的编程智能体，其中每个工具结果或文件编辑都会加入对话。
  • 计算机使用（Computer use）智能体，截图随线程保留，而无需在每一轮重新上传。
  • 文档和图片密集的工作流，让请求变得更小。

智能体携带的上下文越多，消息线程就越能缩短首 token 时间。

开始使用

消息线程现已在 Claude Platform 原生环境公开测试，并可在 AWS 上的 Claude Platform、Microsoft Foundry 中的 Claude，以及 Google Cloud 上的 Claude Models（由 Anthropic 托管）中使用。标准 Claude token 费率及现有速率限制同样适用。请参阅文档开始使用。
