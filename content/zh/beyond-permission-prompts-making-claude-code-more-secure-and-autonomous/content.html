为帮助应对这一问题，我们在 Claude Code 中基于沙箱推出了两项新功能，它们既为开发者提供更安全的工作场所，也让 Claude 能更自主地运行，并减少权限提示。这些功能是原生沙箱的例子：在设定的边界内让 Claude 自由工作，从而同时提升安全性和自主性。

我们目前保护用户安全的做法

Claude Code 采用基于权限的模型：默认只读，这意味着它在做出修改或运行任何命令之前都会请求许可。也有一些例外：我们用静态分析自动放行 echo 或 cat 这类安全命令，但大多数操作仍需要明确批准。

但不断点击“批准”会拖慢开发，并可能导致“批准疲劳”，用户可能不再仔细看自己批准了什么。为了让 Claude Code 既更安全又更有效，我们希望找到更好的方法。 

沙箱：更安全、更自主的做法

沙箱预先划定边界，让 Claude 可以在其中更自由地工作，而不必为每个动作请求许可。 

随着这次对 Claude Code 的更新，我们转向这一做法。我们的沙箱方法建立在操作系统级功能之上，以启用两项新功能，它们都基于以下两类边界：

  1. 文件系统隔离， 确保 Claude 只能访问或修改特定目录。这在防止被提示注入的 Claude 修改敏感系统文件时尤其重要。
  2. 网络隔离， 确保 Claude 只能连接到已批准的服务器。这能防止被提示注入的 Claude 泄露敏感信息或下载恶意软件。

值得注意的是，有效的沙箱需要文件系统隔离和网络隔离同时存在。没有网络隔离，被攻陷的 agent 可能把 SSH 密钥等敏感文件外泄；没有文件系统隔离，被攻陷的 agent 很容易逃出沙箱并获得网络访问。正是同时使用这两种技术，我们才能为 Claude Code 用户提供更安全的 agentic 体验。

Claude Code 中的两项新沙箱功能

沙箱化 bash 工具：无需权限提示即可安全执行 bash

今天，我们推出一个新的沙箱运行时（研究预览），让你可以精确指定 agent 可以访问哪些目录和网络主机，而无需启动和管理容器的开销。它可用于为任意进程、agent 和 MCP server 加沙箱。现已作为开源研究预览提供：  [Github link?]

在 Claude Code 中，我们用这个运行时为 bash 工具加沙箱，让 Claude 能在你设定的限制内运行命令。这些命令默认更安全，需要的用户权限提示更少，因此 Claude 可以更自主地运行。如果 Claude 试图访问沙箱之外的内容，你会立即收到通知，并可以选择是否允许。 

我们建立在 Linux bubblewrap 和 MacOS seatbelt 等操作系统级原语之上，在 OS 层强制执行这些限制。它们不仅覆盖 Claude Code 的直接交互，也覆盖该命令派生出的任何脚本、程序或子进程。

如上所述，这个沙箱同时强制执行：

  1. 文件系统隔离， 允许对当前工作目录进行读写，但阻止修改其外的任何文件。 
  2. 网络隔离， 只允许通过连接到沙箱外代理服务器的 unix domain socket 访问互联网。该代理服务器强制限制进程可以连接的域名，并处理对新请求域名的用户确认。如果你希望进一步提升安全性，我们还支持定制该代理，对出站流量强制执行任意规则。 

‍

这两个组件都可配置：你可以轻松允许或禁止特定文件路径或域名。 

沙箱确保即使提示注入成功，也会被完全隔离，无法影响用户的整体安全。这样，被攻陷的 Claude Code 无法窃取你的 SSH 密钥，也无法回连到攻击者的服务器。

要开始使用此功能，请运行：claude --sandbox，并在此阅读我们安全模型的更多技术细节。

Claude Code on the web：在云端安全运行 Claude Code

今天，我们还发布了 Claude Code on the web，让用户能在云端的隔离沙箱中运行 Claude Code。Claude Code on the web 会在隔离沙箱中执行每一次 Claude Code 会话，使其能以安全的方式充分访问自己的服务器。我们设计这个沙箱，确保敏感凭证（例如 git 凭证或签名密钥）永远不会进入沙箱环境。这样，即使沙箱中运行的代码被攻陷，用户也能免于进一步伤害。 

Claude Code on the web 使用一个定制代理服务，透明处理所有 git 交互。在沙箱内，git 客户端用定制的、带范围的凭证向该服务认证。代理验证该凭证以及 git 交互的内容（例如确保只推送到已配置的分支），然后在把请求发往 GitHub 之前附上正确的认证令牌。
