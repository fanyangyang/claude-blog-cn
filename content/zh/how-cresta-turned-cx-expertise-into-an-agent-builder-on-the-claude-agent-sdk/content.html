在我们的系列文章「创业公司如何用 Claude 构建产品」中，我们关注 AI 产品背后的决策。这一次，我们来看看 Cresta 如何将其构建 AI 原生客户体验的专业能力带入 Conductor——一个帮助开发者构建和改进其他智能体的智能体。

为客户体验场景构建企业级 AI 智能体，需要理解广泛分布于各类客户交互中的上下文。例如，客户可能会：

  • 要求退款，却没有说明指的是哪一笔购买；
  • 在同一条消息里同时报告账单问题和登录问题；或者
  • 在退货窗口关闭之后申请退款。

要正确应对这些情况，智能体可能需要查询客户购买了什么、退款政策、账户历史或支付状态。

Cresta 能以规模化方式处理这些交互。其平台支撑着客户体验：AI 智能体自主处理对话，为并肩工作的人类客服提供实时指引，并输出对话智能洞察，帮助业务方看到该在何处改进。 

构建和维护客户体验智能体，要求组织在运营需求上做出关键决策：智能体需要知道什么、必须访问哪些系统，以及它的行为在哪些地方应当灵活、哪些地方应当确定。Cresta 希望让更多团队也能拥有这种判断能力，而不必每次都从零开始。 

Conductor 正是这一想法的产物：一个自然语言智能体构建器，帮助团队把复杂的业务上下文转化为可投入生产的智能体。用户描述他们想构建什么，Conductor 便会从有依据的蓝图出发，引导完成实现、评估和优化全流程。

Cresta 最初使用 Claude Sonnet 和 Claude Opus 构建了 Conductor 的早期版本，用于帮助内部团队支撑客户部署。当时悬而未决的问题是：Cresta 能否把这套系统变成一款产品，让客户直接在平台内用它构建智能体。

为了承担开放式开发工作，Conductor 将 Claude Agent SDK 用作通用型执行框架，用于收集上下文、调用工具、编写并运行代码，并根据结果进行调整。

「我们在内部把 Claude Code 当作开发工具来用，因为它在构建智能体所涉及的软件开发方面非常高效，」Cresta Conductor 工程负责人 Renjie Li 表示。「Claude Agent SDK 让我们能以编程方式使用同一套智能体开发框架。借助 Conductor，我们将它与 Cresta 深厚的对话智能、CX 专业能力、评估体系和运行时连接起来，为用户提供我们当初就希望拥有的智能体构建体验。」

据 Cresta 报告，在 Cresta 及其合作伙伴的早期用例中，Conductor 将初始部署时间大约缩短了一半。 

一个帮助构建下一代智能体的元智能体

Conductor 是一个自我改进的元智能体，建立在 CX 智能体开发的成熟最佳实践之上。随着团队用它构建并打磨更多智能体，他们沉淀出自己验证过的模式、工作流和专家判断。这就形成了一个知识飞轮，让后续开发更快、更一致。

上线之后，生产环境的交互、工作流结果和反馈都会成为下一次改进的新信号。 

Conductor 帮助构建者把一次智能体构建中学到的东西转化为可复用的记忆产物，沉淀其中的模式、业务规则和评估方法。然后，他们可以把它作为技能分享给团队其他成员，让其他人也能基于同一套经过验证的实践来构建。

让关键决策更容易

写出第一条提示词只是构建一个有用智能体的开始。更难的抉择在于：对话的哪些部分应保持灵活，哪些部分需要明确的业务规则和受控的工具行为。

「你不希望做得太确定化，否则你会造出一棵巨大的决策树，试图覆盖每一个可能的分支……但确实有一些企业关键工作流必须保证始终正常运转，尤其是对于风险容忍度低的高度受监管行业，」Renjie 说。「Conductor 帮助发现并固化这些确定性需求及其实现，同时保留足够的灵活性来改善整体体验。」

Conductor 会参考历史对话，帮助团队判断哪些环节应保留人工介入、哪些环节可以放手让模型自主调整。一旦这些边界被确定下来，开发者仍需要针对这些确定性部分做测试，验证其是否满足要执行的业务规则，并在底层业务规则变化时修订这些测试。 

Cresta 如何评估 Conductor

Conductor 的衡量标准是它构建智能体的好坏。为此，Cresta 会让 Conductor 完成一组构建任务：

  • 构建一个新的智能体
  • 为某个智能体编写测试用例
  • 修改一个已有的智能体
  • 执行根因分析

完成任务并非唯一标准。团队还会审视结果、Conductor 的实现路径，以及它在过程中使用了什么。

同样的任务也充当安全网。每当有新的 Claude 模型发布或 Conductor 框架更新，Cresta 都会重跑评估。它使用相同的任务和相同的评分标准，在任何人采用变更之前，识别出哪些方面有改进、哪些仍需打磨。

同样的评估纪律也内置于 Conductor 中，让用户能够检查并确认自己的智能体是否按预期运行。Conductor 会把构建阶段捕获的需求和边界场景转化为评估模块中的测试。 

当策略、连接系统和对话模式发生变化时，团队可以持续监控那些必须每次都能正常运转的工作流。这为他们提供了一种务实的方式，在业务变化时更新智能体，同时不牺牲已经固化下来的工作流的可靠性。

基于 Claude Agent SDK 构建 Conductor

Cresta 将 Conductor 设计为面向智能体开发的 CX 专属控制平面。它汇聚了对话数据、领域专业知识和开发实践，并通过策略、可观测性、验证和反馈驱动的改进来管控每一次智能体运行。

Claude Agent SDK 位于 Conductor 之下，充当通用执行框架。它负责收集上下文、调用工具、编写并运行代码等工作；Conductor 则在其上叠加 Cresta 的 CX 工作流、工具和领域上下文。

团队针对 Conductor 实际需要完成的工作评估了 SDK：多步骤任务、大量上下文和重复的工具调用。评估覆盖了数据隐私、租户架构、组织级密钥分发、控制措施以及整个实现过程中的可观测性。

「Anthropic 为智能体软件开发提供了强大而通用的基础，这让我们能把工程投入放在 Cresta 最能创造持久客户价值的地方，」Cresta 工程副总裁 Xiangru Chen 表示。

把 Cresta 的工程专业能力直接交到客户手中

Conductor 起步于 Cresta 内部，帮助其前向部署团队了解哪些开发任务可以变得可复用、上下文在哪些地方最重要，以及构建者一路上需要检查什么。它在内部工作中取得的成功，让团队有信心把同样的能力带给客户和合作伙伴。

对于任何产品部署定制智能体的速度超过工程师手工构建速度的团队来说，Cresta 的做法是一个很好的参考：无论智能体还是元智能体，初次构建之后的工作往往才是最困难的部分。
