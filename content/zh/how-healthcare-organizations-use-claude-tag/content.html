医疗机构正在使用 Claude Tag（测试版）——它将 Claude 作为队友带入 Slack——来帮助他们分类生产环境告警、维护内部工具，以及解答关于支付方规则的问题。虽然 Claude Tag 目前尚未纳入 Anthropic 的商业伙伴协议（Business Associate Agreement），但已有几家医疗机构正在不涉及受保护健康信息（PHI）的频道和连接器中使用它。

在频道中提及 @Claude，它会阅读整个讨论串，使用你已连接的工具，完成工作并汇报结果。它会记住每个频道中发生的事情，因此长期进行的工作无需重复解释；当你允许时，它还可以持续关注某个频道并自主介入。

管理员决定 Claude Tag 可以在哪里工作、能够接触到什么，因此医疗团队可以将 Claude Tag 排除在保存 PHI 的频道和系统之外：

  • Claude Tag 可以默认关闭，并且只在获批的频道中启用，同时禁用私信，连接器按频道设置范围。 
  • Claude Tag 不会读取整个 Slack——它只看到工作区成员能看到的内容。虽然它可以阅读工作区的公开频道并按关键词搜索，但它无法访问未被邀请进入的私密频道。 
  • 访问捆绑（Access bundles）让团队可以在一个频道中连接代码库、问题跟踪器等数据源，同时让 EHR、临床系统和患者沟通内容保持不可访问。要了解更多关于 Claude Tag 的智能体身份访问模型及其完整架构，请参阅安全与数据处理文档；你也可以在这里阅读面向医疗机构的更多最佳实践。

以下就是 Insight Health、Tennr 和 Medallion 目前如何使用 Claude Tag 构建人机协作团队（human-agent teams）。

Insight Health 的事件响应

Insight Health 构建了 MagicDocs——一款面向专科医疗诊所的 AI 转诊协调工具。MagicDocs 读取患者入站文档（传真、转诊单、预授权请求、化验单和病历），提取临床细节，将每份文档匹配到正确的患者，并将结构化数据写入 EHR。该公司服务于 56 个专科的 1,100 多家诊所。

随着 Insight Health 客户群的扩大，生产环境告警分类占用了精简工程团队本可以用于更高价值工作的时间。因此，过去三个月里，该公司在无 PHI 的工程和支持频道中运行 Claude Tag，由它调查生产告警、提交并去重工单、审查 PR，并在讨论串之间传递上下文。

在他们高流量的生产告警频道中，他们将 Claude Tag 与第二个智能体 Zeus（由 Insight Health 基于 Claude Agent SDK 构建）配对，将事件从首次通知推进到经过测试的修复。这两个智能体拥有刻意区分的访问权限：Claude Tag 可以访问代码库和 Linear，因此它了解代码模式和历史工单；Zeus 运行在公司受 BAA 覆盖的 Claude API 组织中，因此它可以查询生产数据，在数据到达 Slack 之前对 PHI 进行脱敏。当告警到达时，两个智能体协同调查——查询生产数据、与代码和近期部署进行核对、并与历史工单进行比对——同时在 Slack 讨论串中汇报进展。一旦确定根本原因，它们会开启一个草稿 PR 并监控测试，最后由工程师审查并合并。Claude Tag 的频道记忆在这里很有价值：它能把新的投诉识别为已知问题（修复正在进行中），回忆起数周前的调查，并无需提示地遵循既定指示。

“Slack 频道中的每个人都能看到两个智能体的推理过程以及它们如何分工，”Insight Health 联合创始人兼 CTO Saran Siva 说。“这种透明度建立了信任，也教会了团队如何从智能体中获得最大价值。”自从 Claude Tag 上线以来，Insight Health 关键告警频道中 97% 的告警在工程师无需介入的情况下关闭，团队得以专注于核心产品工作。

除了事件之外，Insight Health 团队还将 Claude Tag 用于招聘、供应商谈判准备、合同审查（对照通话记录检查条款）以及一般业务运营。

Tennr 的内部工具维护

Tennr 是一个患者协调平台，通过自动化入院、文档、授权和排班工作（这些工作原本会拖延护理进度），帮助医疗服务提供者更快地将患者送到合适的护理环境。Claude Tag 存在于其内部工具中，帮助非技术团队搭建和维护自定义内部应用。

在 Tennr 这样的快速增长公司中，内部工具消亡的速度和它们被创建的速度一样快，因为没有人有精力去维护它们。2026 年 7 月，Tennr 在构建内部工具时采取了不同的方法。他们上线了 recruiting.tennr.com——一个用 Claude Code 构建的内部录用通知展示门户——并通过一个专门的 Slack 频道让 Claude Tag 成为它的主要维护者。现在，真正使用该工具的人（招聘人员、People 团队成员、招聘经理和 RevOps）用通俗的英语 @ 提及 Claude 提出请求，Claude 就会交付代码变更、部署并汇报结果。他们可以直接对工具进行迭代，而无需把工程师从产品工作中抽走。

在大约一个月的时间里，团队以这种方式交付了 15 个以上的工单：一个基于上传的 PDF 一页纸文档构建的福利深度解读板块、一个链接到 Dropbox Sign 的“在这里签署录用通知”横幅、目标奖金字段，以及自助式管理员控制。当发现一个公开暴露的复制 API 时，Claude 当天就将其锁定。当一个 Ashby 导入 bug 不断重置有效录用通知上的股权信息时，Claude 修复了该 bug 并传播了修正后的数值。当另一个 bug 短暂地错误显示候选人的浮动薪酬时，Claude 主动在频道内发布了包含受影响时间段和补救措施的公告。它还撰写了入职文档，并负责该工具的权限管理。

团队在频道内向 Claude 传授了自己的运营规范，包括一套表情符号状态图例，以及一种带编号的工单格式（包含工单编号、请求人、提交链接、截图和实时测试链接）。Claude 此后一直遵循这些规范。招聘人员用自然语言提交相当于工程工单的请求，有时只是一张截图，一小时内就能拿到生产环境的变更。“Claude Tag 让内部工具变得真正可行，”Tennr 业务运营与战略副总裁 Abe Griffiths 说。“有了 Claude 通过 Slack 频道充当工具的管家，真正使用工具的人可以直接迭代它，而无需把工程师从产品工作中抽走。”

推广之所以迅速，是因为基础已经具备。Tennr 只允许 PHI 存在于有限的私密频道中，因此广泛引入 Claude Tag 并没有带来新的数据问题。让 Claude Tag 容易被接受的关键，是逐频道的作用域设置。

“在录用工具频道中，我们希望 Claude 积极主动：修复问题、修改代码、跳过 PR 审查并直接上线，”Griffiths 说。“这种姿态在 Product 或 Eng 频道显然是错误的，在那里 Claude 的角色更接近信息收集或帮我们保持有条理。能够逐频道划定这些边界，意味着我们可以在低风险的地方给予 Claude 真正的自主权，而无需处处授权。”

Medallion 积累支付方专业知识

Medallion 为医疗机构自动化供应商认证、许可和支付方登记。这些工作中很大一部分依赖于晦涩难懂、没有文档记载的规则：哪些支付方要求一个团体在登记前必须有一定数量的已认证供应商、各州的具体法规，以及几十个类似的问题——工程师在把流程编入产品之前必须得到答案。过去，这些答案只存在于一小群内部医疗领域专家脑中，为核心产品开发决策制造了一个持续的人力瓶颈。

现在，Claude Tag 加入了这一环节，打破了知识孤岛。当工程师在 Slack 中提出支付方规则问题时，Claude Tag 会依据过去的专家答复、历史数据和非结构化的内部资源来回答。专业知识在频道中不断积累，而不是只存在于某个人的脑子里。

“当它不确定时，它会@相关的专家，而专家的答复会成为未来相关主题回答的基础，”CTO Armaan Sarkar 说。

是什么让他们放心地推广 Claude Tag？Sarkar 指出了三点：选择正确的无 PHI 工作流、专家审查和自动化验证。Claude Tag 在政策层面运作：问题涉及支付方规则和流程，而不是单个患者或供应商。它不会独自作答：专家提供监督和纠正，每一次交流都发生在公司任何人都可以审计的 Slack 频道中。而且输出会在下游得到检查，因为 Medallion 的系统使用这些政策采取的行动本身就会接受审计和验证。
