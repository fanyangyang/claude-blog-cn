从中小企业到财富 500 强，超过 25 万家公司使用 monday.com 来管理他们的工作。十多年前公司刚创立时，其核心产品是一个帮助团队自动化工作流和管理项目的可视化界面。如今，它已经围绕“人类与 agent 协作”的模型对产品进行了彻底重构，让 AI 在每一个层面融入工作。以 Claude 为核心，monday 的新平台负责处理技术复杂性，让客户能在他们早已熟悉的工作流中直接站上 AI 前沿。

“转向 agent 优先的产品，是我们作为公司做出的最重大的决策之一，” monday.com 首席产品与技术官 Daniel Lereya 说。“这意味着要从根本上重新想象平台应该做什么，而不仅仅是在现有工作流上叠加 AI。我们的愿景是让 monday 成为人与 AI agent 无缝协作的地方，而 Anthropic 和 Claude 一直是帮助我们实现这一愿景的可信赖伙伴。”

撞上“AI 粉尘”的天花板

monday 的重构经历了三个阶段。在第一阶段，随着前沿 LLM 技术日趋成熟、客户热情不断高涨，monday 团队着手将 AI 能力嵌入原有平台。这项工作在 2025 年 5 月以一次内部“AI 月”活动告一段落——整整四周时间，全公司专注于交付 AI 功能或产品。

采用率很高，也带来了热度，但团队很快就撞上了天花板。“我们当时做的是‘AI 粉尘’，把自动化撒在现有工作流上，却没有把它们真正嵌入产品，也没有改变产品的核心价值主张，” monday.com AI Works 平台产品副总裁 Orly Stern Izhaki 说。“我们的功能能帮用户总结文本、归类信息，但没能形成持续的使用习惯。”

公司需要把重心从“给产品功能加 AI”转向“把 AI 原生构建进平台”。“采用 AI 功能并不等于成为一家 AI 公司，” Izhaki 说。“想明白这一点之后，一切都变了。”

于是 Izhaki 的团队开始彻底重新想象 monday：从一个工作管理工具，变成人与 agent 共同完成工作的地方。产品转型的号令虽然来自最高层，但把这一北极星转化为具体的产品选择、构建各自的 agent，则要靠每个团队和每一位员工。

经过数月的密集工作，公司宣布了其历史上最重大的变革：围绕人类与 agent 协作来重建整个产品体验，并复用已有的上下文、工作流、看板、权限和治理能力。自 2026 年 5 月上线以来，monday 的客户已在其平台上与 agent 进行了超过 500 万次交互。

Agent 即队友

除了访问权限和限制之外，每个 monday agent 都有自己的名字和头像，同事可以通过 monday 平台中的触发器和提及（mention）给 agent 分配工作。

这一设计是有意为之，针对的是 monday 在客户群中普遍观察到的一个现象：许多企业想让 AI 发挥作用，却往往止步于一个与实际工作场所并行运行的 AI 聊天窗口。把 agent 直接嵌入工作流，让人们像与同事互动那样与 agent 互动，agentic AI 就从一个抽象概念变成了具体、可落地的东西。

monday 为 agent 规划的任务五花八门：从工单分诊、知识库维护，到候选人寻源和面试安排，再到面向销售和市场团队的竞争情报简报，以及会议准备、把决策转化为可跟踪任务等幕僚长式的工作。

在 monday 中运行 Claude 的四种方式

客户可以通过四种能力在 monday 平台内使用 Claude：

借助 monday Agents，团队可以用提示词构建自定义 agent，并选择 Claude 作为其模型。平台会为 agent 赋予名字、形象，以及在看板上的位置，任何人都可以给它分配工作。

自带 Agent（Bring Your Own Agent，BYOA）让 Claude Managed Agents 得以加入平台。一旦进入 monday 平台，一个人构建的 agent 就能成为整个团队可以提及、可以派活的队友。

预构建 Agent（Pre-built Agents）在 monday Agents Store 中提供，把 Claude 插件变成专门的队友：法务团队可以在自己的工作流中把法律插件作为 agent 运行，财务团队也可以如法炮制。

Claude Coding 集成让团队能够在 monday 仪表盘中接入 Claude，然后规划并向 agent 分配任务。Claude Managed Agents 在客户自己的环境中执行，结果和更新会自动回到工单上，再交由下一个 agent 或人类进行评审。整个流程从业务需求出发，变成可运行的代码，再回到业务用户手中。

不离开看板，从简报直达落地页

举一个端到端的例子：一个市场团队在单个看板条目内运行一条营销活动生产线。市场营销人员和内容负责人在这个条目上打磨简报，就目标、受众、核心信息和渠道达成一致。一个用 monday Agents 构建的战略 Agent（Strategist Agent）把这些原始输入转化为结构化简报，涵盖活动目标、信息支柱、渠道拆分和成功指标。

接下来，落地页构建 Agent（Landing Page Builder）接手。它以 Claude Managed Agents 的方式在该公司自己的环境中运行，拉取已批准的简报，并基于现有落地页生成一个新变体，文案、结构和信息都针对该活动做了适配。产出会自动回到 monday 条目上。在页面进入审批之前，一个作为 Claude Managed Agent 运行的品牌评审 Agent（Brand Reviewer）会依据品牌规范和法律标准对其进行检查，并标记出需要人工关注的地方。然后市场经理只需做一个决定：发布，还是继续打磨。

站在 AI 前沿的家族企业

Cooke 是一家 1985 年创立于新不伦瑞克省布莱克斯港（Blacks Harbour）的家族海鲜企业，从单一养殖场、5000 条三文鱼起步，发展成为业务遍及 16 个国家的全球最大家族海鲜公司。如今，Cooke 在 Claude 和 monday 上共同运行项目交付、资源管理和合同管理。产品经理使用 Claude 将批准的章程和需求转化为初步项目计划、生成状态报告，并识别风险和问题，直接汇入他们的 monday RAID 日志，覆盖约 200 个进行中和提议中的项目。Claude 自动化了让生命周期工作流在 130 份合同上保持准确所需的报表和数据准备工作——这些维护工作过去既繁琐又依赖人工。

“monday 和 Claude 加在一起，帮助我们看清团队产能，做出更聪明的人员调配决策，” Cooke 战略总监 Patti Stevens 说。“过去 monday 是一个我们必须去更新的平台。现在我们直接在它上面运转。”

monday.com 的经验总结

对于计划进行类似重构的公司，monday 团队分享了他们在把平台转型为 AI 优先产品过程中的五条经验：

  • 心智模式的转变比技术更难。人们天然地想要保护质量、持续改进已经奏效的东西。把团队从“我们如何负责任地改进现有产品？”带到“我们如何负责任地为另一种未来重构它？”，花的时间比技术工作本身更长。
  • 当一切都在同时变化时，小团队跑得更快。方向、UX、技术、定价、信任模型，乃至公司自己对“好”的定义，都在同时变动。层级繁多的相关方会丢失大量细节，而拥有清晰所有权和快速决策权的小团队则能始终贴近细节。
  • 采用与否，取决于信任，不亚于取决于能力。产品与市场的契合取决于用户的信心，以及他们是否准备好让 agent 介入实际的工作方式。治理、权限、透明度和可靠性，决定了 agent 是止步于试点项目，还是真正走进生产环境。
  • 能力需要与之匹配的基础设施。当 agent 基于实时的项目数据、团队历史和结构化工作流运行时，其表现会截然不同；而在企业级规模下，后端必须扛得住。在构建 agent 层的同时，monday 还投资建设了 monday DB，让数据基础设施足以支撑 agent 在整个组织中运行所产生的数据量、速度和复杂度。
  • 在已经奏效的东西之上构建。monday 一直把自己描述为人们组队协作、推动业务成果的地方，而 agent 优先的重构把这一承诺延伸到了一种新的团队成员身上。人们仍然是为了实现目标而来到 monday，区别只在于，身边并肩作战的队友中有一些现在是 agent。
