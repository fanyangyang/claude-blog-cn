Claude Opus 5.5 现在是 Pro、Max、Ultra 和 Team 方案中 Claude 的默认模型。我们推荐把它作为你知识工作的日常主力模型，也就是在使用 Claude 进行调研、分析、写作，或产出备忘录、报告、表格和演示文稿时保持选中的那个模型。

如果你或你的团队一直把 Sonnet 用于日常工作，而把 Opus 留给重度分析或复杂项目，这值得重新考虑：能力更强的模型可以通过更少的工作完成一个任务，这往往能抵消其更高的单 token 价格。

以下是当前各模型的对比：

我们的模型在知识工作上的对比
模型适用场景每百万 token 价格（输入 / 输出）*相对速度
Claude Haiku 5.5快速查询与最看重速度的高频工作$0.10 / $0.50最快
Claude Sonnet 5.5快速、边界清晰的任务，以及根据明确需求产出精致的文档、幻灯片和表格$2 / $10快
Claude Opus 5.5大多数知识工作：调研、分析，以及需要判断力的成品文档、演示文稿和表格$4 / $20中等
Claude Fable 5.2最具野心、最开放的技术工作，例如编程、金融和科学领域$8 / $40中等

*价格为按 token 计费的用量价格（模型对比）。Haiku 5.5 的价格适用于不超过 100k token 的提示，更长的提示价格为 $0.50 / $2.50。在 Pro、Max、Ultra 和 Team 方案中，价格更高的模型会更快消耗你的额度。Pro 方案以及 Team 和按席位计费的 Enterprise 方案的标准席位，除限时发布优惠外，其额度不包含 Fable 5.2，因此它按用量额度计费。

Haiku 5.5 是我们最快、最便宜的模型，专为快速查询和高频工作（例如撰写摘要、整理数据）打造。这是我们的首个支持 effort 控制的 Haiku 模型，因此你可以要求它做更细致的一轮处理，然后再切换到更大的模型。它最适合简短、范围明确的任务。若需要更长的分析，请切换到 Opus 5.5。

Sonnet 5.5 在需求明确的边界清晰任务上比 Opus 5.5 更快、更便宜。这类任务可能是让 Claude 把已完成的笔记整理成一份精致的文档，或使用幻灯片模板制作一套演示文稿。不过在更高的 effort 设置下，Sonnet 5.5 的单任务成本会接近 Opus 5.5，所以如果你发现自己在把 Sonnet 推到 Extra high 或 Max effort，不妨考虑改用 Opus 5.5。

Opus 5.5 专为需要谨慎判断的复杂工作打造，例如调研、财务分析，以及产出成品文档、演示文稿和表格。我们将在后文详细说明为什么推荐把 Opus 5.5 用于日常知识工作。

Fable 5.2 最适合要求最高的推理和长时间运行的工作，例如深度的多步骤调研，或可以交给大规模子智能体团队连续运行数小时的编程任务。对大多数知识工作来说，先从 Opus 5.5 开始，当项目范围和复杂度确实需要时再转向 Fable 5.2。Fable 5.2 在所有付费方案中均可使用，不过它如何计入你的用量取决于你的方案。

无论你使用哪个模型，如果 Claude 的表现不如预期，先尝试提高 effort，而不是升级模型。如果它已经掌握了上下文、也确实认真尝试过，但仍然出错，那就升级模型。

Opus 5.5 在文档、调研、金融和图表上表现最好

Opus 5.5 能精确遵循指令并保持在范围内，因此它产出的表格、幻灯片和文档往往几乎不需要修改。它对数字和来源也很谨慎。在一次内部调研测试中，Opus 5.5 仅凭一份保存下来的网页快照撰写某公司季度业绩报告，而在这份快照中该公司的财报很难找到。一个自动评分器会把每一个数字和引文与该快照中的页面逐一核对，并设定只要有一个数字或引文是编造的，报告就不合格。在各种 effort 设置下，它的 18 份报告中有 16 份通过。

它的写作也比早期模型更清晰。Opus 5.5 会把最重要的信息放在最前面，使用更少的行话，遵循你给定的写作规则；在较长的任务中，它会清楚地说明自己做了什么、发现了什么，以及需要你提供什么。这也让它的工作更容易核查，我们把这既视为安全上的收益，也视为实用上的收益。

Ramp 的资深软件工程师 John Ruelas 表示：“它写起来像一位好同事，而且遵循我们的写作规则。一份设计规范几乎不用修改就能用，当它重写我们的某个提示时，我甚至更喜欢它的版本。”

财务分析是另一项强项。Opus 5.5 能准确阅读密集的申报文件、财务模型和图表，并在整个项目或交易中保持对上下文的把握。在另一项内部测试中，它分析了两家虚构人力资源软件公司拟议的合并，在 Excel 中构建财务模型，然后转化为一份高管演示，说明这笔交易在给定价格下是否合理。它用 63 分钟完成，而 Opus 5 在同样任务上用了 93 分钟；成本只有一半，模型更严谨，演示也更易读。

投资机构 Walleye Capital 负责中央股票量化研究工程的 Frank Corrao 表示，在更高的 effort 设置下，Opus 5.5 “发现我们自己的指令中按分钟索引存在一处偏差，并做了修正，还指出这会因此被评分器扣分。它是对的，而我们测试过的任何模型此前都没有发现并处理过这个问题。”

Opus 5.5 是我们视觉能力最强的 Opus 模型。它能准确读取密集文档、图表、截图和示意图，因此非常适合从文档中提取数据。即使在最低的 effort 设置下，它读取密集图表数值的准确度也高于 Opus 5 在最高设置下的表现。

更好地使用 Opus 5.5

每个新模型都是重新检验你交给 Claude 的工作、并抛弃为老模型养成的提示习惯的理由。

先试试这些任务

  • 直接要求成品文件。如果你想要一份表格或文档，就直接要那份表格或文档，而不是要一个大纲自己再加工。多数情况下，Opus 5.5 能一次从你的请求直接得到成品文件。
  • 让它检查长文档。给它一份很长的方案、报告或演示文稿，让它找出错误和不一致之处。Opus 5.5 能发现长文档中容易遗漏的细节，比如演示文稿里的某张图表与源数据不符。
  • 交给它一个研究问题。提出一个没有标准答案的问题，让它汇总来源、通读长文档，并把发现写成备忘录、报告或演示文稿。
  • 试试视觉类工作。它的视觉能力提升也能用于设计，可以试着用它给界面做原型、搭建网站，或为某个概念配图。

改变这些提示习惯

  • 把 Claude 连接到你的工作文件和系统。这是让输出贴合你工作的最有用步骤之一，因为当 Claude 能通过连接器访问你的文件和系统时，它就能去获取任务所需的信息，而不只是依赖你粘贴进来的内容。在 Team 和 Enterprise 方案中，需要由所有者先开启连接器，成员才能使用。
  • 在第一条消息里说明“完成”是什么样的。不要一条条给 Claude 下指令，而是描述你的目标、最终产出，以及你希望它在何时停下来询问。Opus 5.5 比 Opus 5 更能把冗长、多环节的工作推进到底。
  • 删掉“think hard”和“think carefully”。Opus 5.5 的思考始终开启，并会根据你的请求和 effort 级别决定思考多少。在我们的测试中，删掉这些句子后回复开始得更快，质量没有明显下降。
  • 从 Medium effort 开始。Medium 是 Opus 5.5 的默认设置，在我们的编程和知识工作评测中，Medium 的 Opus 5.5 达到或超过了 High 的 Opus 5。更高的设置会思考更久、花费更多，但未必总是产出更好，所以当 Medium 卡住时再升到 High。要更改设置，点击发送按钮旁的模型名称并选择 Effort。
  • 直接附上图表，而不是重新输入。分享图表、截图或示意图本身，而不是把其中的数字复制到提示里。为早期模型设计的变通做法（比如转录图表数值）可能已经不再需要。
  • 点名你不想要的风格。在设计工作中，像“避免千篇一律”这样的笼统指令往往只是把一种默认风格换成另一种。点名要避免的具体模式（例如奶油色背景或胶囊形按钮）效果更好。
  • 把企业风格交给它。把你的品牌或写作规范粘贴到请求中，或让 Claude 参考你最好的现有演示文稿（例如它能通过连接器访问的 Google Drive 文件夹），并要求它对齐。要完全对齐通常需要几轮调整。

关于 effort 的发现同样适用于早期测试者。Factory 的技术团队成员 Zimu Li 表示：“Claude Opus 5.5 是我们第一个会默认用 medium effort 的模型。在我们的测试中，它在 high effort 下与 Opus 5 相当，同时输出 token 少了 20% 到 25%。”

在一个演示项目中测试 Opus 5.5

下面是我们演示中一个完整项目的实际过程。在一家假设的零售公司，营收增长在过去一年放缓，管理层有四种猜测，而一位分析师手里有一堆材料：按门店划分的销售表格、最近一次管理层务虚会的 PDF，以及其他文件。使用 Medium effort 的 Opus 5.5，提示大致是：

今年增长放缓了很多。管理层对原因有几种猜测，写在[我经理的]笔记里。我手上的材料都在上传的文件夹里。请用数据逐一验证这四种猜测，告诉我哪些站得住脚。

提示里没有让 Claude 努力思考，也没有说明哪个猜测该查哪个文件。它只陈述了目标和最终产出的样子，把方法留给 Claude。

Claude 发现数据并不支持这四种猜测中的任何一种，尽管其中一种无法被完全排除。随后它提出了一个此前没人提到的解释：新店开得离老店太近，把老店的销售分流走了。按城市列出门店时，这个规律不太明显；一旦按与新店的距离筛选，就很清楚了。Claude 用销售影响对该距离的回归分析为这一发现提供了支撑。

接下来，Claude 把分析变成一份文档，图表和交互元素与文字并存，其中包括一个滑块，展示销售如何随新店与老店之间的距离变化。一位同事同时审阅了这份文档。

随后经理让 Claude 把文档转成以答案开篇的董事会幻灯片。对于不使用 Claude 的同事，文档可以导出为 Word、PDF 或 Google Docs，演示文稿可以导出为 PowerPoint、PDF 或 Google Slides。

在你自己的工作里试用 Opus 5.5

挑一件你平时会拆成好几次请求来完成的事，比如一份调研备忘录、一次差异分析，或一套基于现有文档制作的演示文稿。把文件和对最终成果的描述放在同一条消息里交给 Opus 5.5，保持 Medium effort，然后把它与其他模型通常给你的结果做个对比。
