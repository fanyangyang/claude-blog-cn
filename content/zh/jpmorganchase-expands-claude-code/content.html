JPMorganChase 正在全公司范围推广 Claude，覆盖的不只是工程师，而是更多员工。在商业与投资银行部门，工作能更快进入生产环境，公司也把由此释放的产能重新投入到业务重点上。

各团队正在对其它遗留系统进行现代化改造，工程师则在构建自己的智能体，包括拉取请求（pull request）审查智能体和自愈（self-healing）智能体，并分享行之有效的做法。

基础设施与运维团队使用 Claude Code (opens in new tab) 进行监控、告警和根因分析。公司的安全团队则使用我们的前沿模型更快地发现并修复漏洞，相关工作我们最初在 Project Glasswing (opens in new tab) 中做过介绍。

触达产品团队与顾问

最贴近业务的人也在用 Claude 构建。产品团队直接把需求转化为工程待办事项，其它团队则用 Claude Code 做风险与控制评估以及项目规划。

知识工作已经在进行中。产品开发生命周期的很大一部分发生在代码之外：调研、需求、设计和规划。

在其资产与财富管理业务中，JPMorganChase 把最具业务洞察力和最大胆想法的人，与技术及产品专家一起编入小型、被充分授权团队。这帮助他们更轻松地大规模构建并交付定制化的客户投资解决方案。Claude Code 现已成为其工程工作流的一部分，团队在加快节奏的同时，让每一项变更在触达客户之前都经过更严格的测试。

上个月，J.P. Morgan Asset Management 宣布了一项连接器，将 55ip 的 ActiveTax Technology® 引入 Claude for Financial Advisors (opens in new tab)，把税务感知的投资组合转换分析带入顾问的日常工作。

为受监管机构而构建

Claude Code 运行在受控环境中，包括该公司自建基础设施上的容器化开发平台 Devspace。其目的是防止智能体直接接触员工凭据或内部系统。访问权限分阶段放开，新的 Claude 模型也要先通过公司自己的审批流程，员工才能使用。

代码发布同样遵循这套纪律。数千个自动化测试和审批关卡会检查每一项变更，自动化关卡会给出明确的通过或中止结论，由流水线强制执行，因此 Claude 无法为自己的工作签发通过结论。每一次生产变更仍由人负责。

过去一年里，JPMorganChase 对 Claude 的使用已从软件工程扩展到网络防御，再扩展到面向财务顾问的工具，而 JPMorganChase 对我们的要求，也在塑造我们为其它受监管机构构建的东西。让 Claude 在世界上最庞大金融机构之一的管控框架内运作，正是我们努力的方向。
