用插件分享你的 Claude Code 配置

斜杠命令（slash commands）、agents、MCP 服务器和 hooks 都是可以用来自定义 Claude Code 使用体验的扩展点。随着这些功能的推出，我们看到用户构建出越来越强大的配置组合，并希望把它们分享给队友和更广泛的社区。插件正是为了让这件事变得更容易而设计的。

插件是一种轻量的方式，可以将以下任意组合打包并分享：

  • 斜杠命令：为常用操作创建自定义快捷方式
  • Subagents：安装为特定开发任务量身打造的专用 agent
  • MCP 服务器：通过 Model Context Protocol 连接工具和数据源
  • Hooks：在 Claude Code 工作流的关键节点自定义其行为

你可以在 Claude Code 中直接使用 /plugin 命令安装插件，该功能目前处于公开 beta 阶段。插件可以按需随时开启或关闭：需要特定能力时启用，不需要时禁用，从而减少系统提示词的上下文占用和复杂度。

今后，插件将是我们打包和分享 Claude Code 自定义配置的标准方式，随着更多扩展点的加入，我们也会持续演进这一格式。

使用场景

插件可以帮助你围绕一套共享的最佳实践来标准化团队的 Claude Code 环境。常见的插件使用场景包括：

  • 执行标准：技术负责人可以通过插件确保代码审查或测试流程中运行特定的 hooks，从而保持团队的一致性
  • 支持用户：例如，开源项目维护者可以提供斜杠命令，帮助开发者正确使用他们的软件包
  • 分享工作流：构建了提效工作流（如调试配置、部署流水线或测试工具集）的开发者可以轻松地与他人分享
  • 连接工具：需要通过 MCP 服务器连接内部工具和数据源的团队，可以使用插件以统一的安全和配置协议来加速这一过程
  • 打包自定义配置：框架作者或技术负责人可以将多个相互配合的自定义配置打包，服务于特定用例

插件市场

为了让分享这些自定义配置更加容易，任何人都可以构建、托管插件，并创建插件市场（plugin marketplace）——这是一种经过精选的集合，其他开发者可以在其中发现并安装插件。

你可以通过插件市场与社区分享插件、在组织内部分发经过审批的插件，或者基于针对常见开发挑战的现有方案进行构建。

要托管一个市场，你只需要一个 git 仓库、GitHub 仓库，或一个包含格式正确的 .claude-plugin/marketplace.json 文件的 URL。详情请参阅我们的文档。

要使用市场中的插件，请运行 /plugin marketplace add user-or-org/repo-name，然后通过 /plugin 菜单浏览并安装插件。

发现新的插件市场

插件市场放大了我们社区已经积累的最佳实践，社区成员正在引领这一潮流。例如，工程师 Dan Ávila 的插件市场提供了覆盖 DevOps 自动化、文档生成、项目管理和测试套件的插件；工程师 Seth Hobson 则在他的 GitHub 仓库中精选了 80 多个专用 sub-agent，开发者通过插件即可即时使用。

你也可以看看我们开发的几个示例插件，涵盖 PR 审查、安全指导、Claude Agent SDK 开发，甚至还有一个用于创建新插件的“元插件”。

开始使用

插件现已面向所有 Claude Code 用户开启公开 beta。使用 /plugin 命令即可安装，插件将在你的终端和 VS Code 中通用。

查阅我们的文档以快速上手、构建你自己的插件，或发布一个插件市场。想直观了解插件的实际效果，可以试试我们用来开发 Claude Code 的这个多 agent 工作流：

/plugin marketplace add anthropics/claude-code

/plugin marketplace add anthropics/claude-code
/plugin install feature-dev
