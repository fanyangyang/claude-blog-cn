每天，数以百万计的人将 Claude 连接到他们的应用、工作工具和数据。今天，我们让开发者更容易触达这些用户。

插件（Plugins）打包了 MCP 连接器（connectors）、Agent Skills，或两者兼有，是为 Claude 构建第三方扩展的主要方式。构建一个插件，通过新的目录提交通道提交，一旦获批，它就会被列在 Claude 目录中。

‍在目录提交通道中提交并跟踪插件

目录提交通道向付费 Claude 套餐的开发者开放。有两种方式可以提交并在 Claude 目录中发布你的插件：

  • 单个 MCP 连接器：指向你的远程 MCP 服务器。
  • 插件包（Plugin bundle）：组合 MCP 服务器和技能，托管在 GitHub 上，并提交该仓库。在 Claude Code 中，插件还可以包含 LSP、命令、hooks 和 agents。 

无论你选择哪条路径，该通道都会引导你从提交走向发布。你可以：

  • 自动验证你的插件。每次提交都会在提交后立即被检查和进行安全扫描，以便你尽早发现问题。
  • 查看审核状态和反馈。查看你的插件在审核流程中的位置、安全扫描的结果以及建议的修改。
  • 在你准备好时发布。一旦获批，你可以决定何时在 Claude 中发布你的插件。

插件发布后，持续监控和改进

一旦你的插件上线，使用分析会显示按产品面和版本统计的安装情况，因此你可以为用户优先安排修复和功能。在发现侧，你可以看到你的列表被查看的频率，以及哪些搜索会引导用户找到它，从而可以优化它以触达新用户。

借助 MCP 2.0 及其扩展，为用户带来丰富的体验

Claude 支持最新的 MCP 规范，通常被称为 MCP 2.0，它包含一个无状态核心（stateless core）。你可以通过两个 MCP 扩展来改善使用插件的体验：MCP Apps，用于聊天中的交互式 UI；以及 Enterprise Managed Auth，为企业的企业用户提供零接触 OAuth。更多 MCP 特性和扩展的支持即将推出。

开始为 Claude 构建插件

插件是第三方开发者创建 Claude 扩展的主要方式。在接下来的几周内，一个统一的发现体验将陆续在 Claude 和 Claude Code 中推出。

Skills 和 MCP 连接器仍作为构建模块保留，Claude 目录将继续列出它们。未来，开发者将能够把他们的连接器列表转换为插件。如果你在 Claude 目录上已有技能、连接器或插件，则无需做任何更改。

要开始构建插件，请阅读我们关于如何构建插件的文档，并在此处提交你的插件。
