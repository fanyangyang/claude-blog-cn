Claude Cowork 现已在所有付费计划上正式全面可用。在公司内部，Claude Cowork 已成为团队运转的关键部分：处理任务、起草项目交付物，并让团队保持同步。 

今天，我们推出组织控制，帮助团队在全公司部署 Claude Cowork：面向 Enterprise 的基于角色的访问控制、组级支出上限、扩展的 OpenTelemetry 可观测性，以及让管理员看到 Claude Cowork 采用情况的用量分析。 

早期信号

Claude Code 帮助开发者从把问题交给 Claude，转向把整项任务交给它；我们在整个组织里也看到同样的模式发生在 Claude Cowork 上：绝大多数 Claude Cowork 用量来自工程团队之外。重要的是，运营、营销、财务和法律等职能并不是把核心工作交给 Claude，而是把环绕最关键任务的那些工作交给它——项目更新、协作演示、研究冲刺等等。 

作为 Claude Cowork 的早期企业采用者，当他们在一个团队里看到这种模式后，往往希望更广泛地推广，随之而来的问题是：谁能获得访问、如何管理支出，以及如何看清各团队正在发生什么。

面向全组织部署的控制

在组织内部署具备 Claude Cowork 能力的 agent，需要给管理团队治理和可见性。今天，我们增加了组织所需的更多控制：

基于角色的访问控制。Claude Enterprise 的管理员现在可以把用户组织成组——手动或通过身份提供方的 SCIM——并为每一组分配自定义角色，定义其成员可以使用哪些 Claude 能力。为特定团队打开 Claude Cowork，并随采用情况调整。

组级支出上限。从管理控制台为每个团队设置预算。成本可预期，并随你了解各团队所需而调整。

用量分析。Claude Cowork 活动现在会出现在管理仪表盘和 Analytics API 中。从仪表盘，管理员可以按不同日期范围追踪 Claude Cowork 会话和活跃用户。Analytics API 更深入：按用户的 Claude Cowork 活动、skill 和 connector 调用，以及与现有 Chat 和 Claude Code 数字并列的 DAU/WAU/MAU。看清哪些团队在采用、哪些工作流落地了，以及下一步该投向哪里。

扩展的 OpenTelemetry 支持。Claude Cowork 现在会发出工具和 connector 调用、读取或修改的文件、使用的 skill，以及每项由 AI 发起的操作是手动批准还是自动批准的事件。事件兼容 Splunk 和 Cribl 等标准 SIEM 流水线，共享的用户账户标识符让你可以把 OTEL 事件与 Compliance API 记录关联起来。OpenTelemetry 在 Team 和 Enterprise 计划上可用。

Zoom MCP connector。Claude Cowork 与团队已经在用的工具集成。今天，Zoom 推出了一个 connector，把会议智能直接带进 Cowork 体验。Zoom connector 会连同转录和智能录像，提供 AI Companion 会议摘要和待办事项——帮助团队把 Zoom 上的对话变成 Cowork 中的 agentic 工作流。可在 Claude 设置的 connector 目录中添加 Zoom。

按工具的 connector 控制。管理员现在可以限制组织内每个 MCP connector 可用的操作——例如允许读访问但禁用写操作。权限在全组织生效，并在管理控制台中配置。

组织如何使用 Claude Cowork

Zapier 把 Cowork 连接到他们的组织数据库、Slack 和 Jira，以浮现工程瓶颈——得到一份仪表盘、按团队的分析，以及一份优先路线图，产品和 Design Ops 随后为自己复制了同样的做法。Jamf 把一份七个维度的绩效评估变成 45 分钟的引导式自评，随后为供应商审查和事件响应构建了类似工作流。Airtree 是一家风险投资机构，构建了一套董事会准备流程，从被投公司的 Drive、Slack 更新和竞品新闻中拉取信息，并与上一份准备材料交叉对照。
