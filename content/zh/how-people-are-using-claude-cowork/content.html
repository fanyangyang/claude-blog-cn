2025 年我们发布 Claude Code 时，惊讶于有那么多非技术用户开始把玩它。有些从未打开过终端的人，用它创建整理文件夹、去重文件、编写表格公式的 agent。

但对另一些人来说，终端仍然是个让人有点发怵的地方——一个名副其实的"黑盒子"。我们打造 Claude Cowork，就是为了把 Claude Code 的 agent 能力延伸到人们早已用来与 Claude 对话的那个聊天界面。

自 1 月发布以来，Claude Cowork 已成为那些以信息创造与交换为工作重心的人们的利器——也就是许多人所说的"知识工作"。人们用它处理的各种任务，未必是某个具体岗位的标志性工作，而是围绕岗位的连接性工作：它们推动项目前进，让企业持续运转。比如起草一份状态更新、制作一套幻灯片，或把堆积如山的资料浓缩成一份报告。

在这篇文章中，我们分享 2026 年 5 月一批 Claude Cowork 会话的数据，并探讨它揭示了人们在终端之外如何将 AI 用于日常工作。

数据说明了什么

我们抽取了 2026 年 5 月 11 日至 31 日期间 120 万个匿名化、聚合处理的 Claude Cowork 会话，并按照一套包含 20 个工作类别的分类体系进行归类。我们发现，占比最大的用途是"业务流程与运营"——比如把散落各处的进展汇总成一份报告、制作入职清单、核对电子表格——占 33.4%。这很好理解，因为业务运营任务横跨多种角色：财务、HR 和行政岗位的人，都可能在 Cowork 上处理这类任务。

其次是内容创作与文案写作——以综合为核心的业务沟通工作，如产出草稿、幻灯片、帖子、提案——占 16.4%。面对一张白纸往往是动笔的第一道障碍，而 Claude Cowork 是把想法和信息串成初稿的好帮手。这类任务同样横跨多种角色：市场、传播、业务拓展和项目管理等岗位的人都可能与 Claude Cowork 协作完成。

再往下的大类依次是：软件开发，占 8.7%；DevOps 与基础设施，占 7%；研究与情报，占 6.4%；数据分析与商业智能，占 5.8%；文档处理与信息提取，占 4.1%；销售与营收运营，占 4%。

其余所有类别均不足数据集的 4%，其中包括个人事务助理 3.8%、教育 2.4%、会议智能 1.8%。

知识工作者如何使用 AI

两大头部用途——业务流程与运营、内容创作与文案写作——合计约占 Claude Cowork 全部用量的一半，这一事实很能说明问题。这些类别绝大多数属于连接性工作：电子表格把分散的数据点拉进一个可以阅读、比较和追踪的上下文；幻灯片把一个想法或决策传达给背景深浅不一的更广泛受众；入职清单帮助新员工接入机构的集体知识。

我们的数据表明，人们正在用 Claude Cowork 去组装和结构化那些能让他们施展专业能力的信息。比如，一位律师可能用 Claude Cowork 处理文档排版和归档，从而把更多时间用于在疑难案件上运用法律判断；一位招聘经理可能用 Cowork 安排会议、汇总面试反馈，从而把更多时间花在候选人面谈和作品评估上；一位团队负责人可能用 Claude Cowork 制作解释某个艰难决策的幻灯片，从而腾出精力去真正做出那些艰难的决断。

这一使用模式与 Claude Code 形成了有趣的对照：Claude Code 最常被软件开发者用于其岗位的核心部分——构建、调试和发布代码。因此，软件开发在 Claude Cowork 用量中占比如此之小，或许并不令人意外。开发者写代码时更可能用 Claude Code 而不是 Claude Cowork，而他们在 Claude Cowork 中做的是围绕每个岗位（软件工程也不例外）的连接性、以沟通为中心的工作。

AI 在知识工作中的兴起

尽管编程依然——完全可以理解——是最受关注的 AI 用途之一，但 AI 用于日常业务工作的比重正在上升，人们发现它最有帮助的任务类型也逐渐清晰。人们正转向 Claude Cowork 寻求帮助的，是那些在团队之间追踪和传达信息与想法的任务：状态报告、幻灯片、追踪表等等。

这只是一个快照，Claude Cowork 还很新，其用途正在快速演进。我们的目标是把它作为一个参照点，帮助那些正在摸索如何把 AI 产品融入日常工作的人，并展示用量最集中的领域。我们计划随着用量的增长和迁移持续发布数据，并随时报告其变化。

关于本研究的更多细节

以下是本次 Claude Cowork 用户调研的更多方法信息。

我们如何测量

本分析基于一批 Claude Cowork 会话样本，由自动化系统将其归入一套 20 类工作分类体系。数据采集使用了一个保护隐私的分析工具，所有用户信息均保持匿名；没有任何单个会话被人类分析师阅读，我们只处理聚合后的类别级统计。

样本按设限速率采集——每小时固定最多采集一定数量的会话——而非按流量的固定百分比。因此，本报告中的每个数字都是抽样会话的占比，而不是绝对量。数据采集时间为 2026 年 5 月 11 日至 31 日，覆盖来自 60 多万个组织的 120 万个抽样会话。

局限性

  • 分类体系的粒度：我们使用的分类体系按所做的工作归类会话，而不是按做这件事的人的职位。若干类别可以干净地对应到可辨识的知识工作职能，例如研究与情报（占会话的 6.4%）、数据分析与商业智能（5.8%）、销售与营收运营（4%）、法律与合规（1.3%）。会议与对话智能（1.8%）和客户支持（0.8%）也有出现。但分类体系的拆分能力有限：没有为市场、财务或 HR 单设类别——这些职能最适合归入"业务流程与运营"，这也是该类别占到全部用量三分之一的部分原因。
  • 占比与绝对量：由于样本按速率设限采集，抽样的会话数和组织数并不能反映 Cowork 的总用量或增长，且一天中较繁忙时段的用量相对于清闲时段略有低估。
  • 时间窗口选择：我们采用最近的三个完整星期而非更长时间段，是因为各类别占比在 5 月 11 日前后发生了变化，而这一变化与我们标注管线的调整相符，并非用户行为的改变。本文报告的占比完全在变化之后计算，在两种解释下都是正确的。
  • 工作与个人用途混合：样本覆盖的是外部组织而非个人的使用。但抽样的 Claude Cowork 会话中包含部分个人非工作用途（个人事务助理、兴趣爱好和陪伴式对话合计约占会话的 5%），因此样本并不纯粹代表职场活动。
  • 自动化分类：类别标签由自动化系统打上，而非人工审核者，任何分类器都可能出错。当一个会话可以合理地归入多个类别时，结果取决于我们分类体系中的定义；这些定义对解读影响最大的地方，我们已在上述"分类体系的粒度"一条中注明。
