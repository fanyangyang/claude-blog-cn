Claude Enterprise 推出了新的安全与管理员功能，包括安全中心、正式上线的推理钩子（inference hooks）、集中化管理和额外的访问控制。

要了解 Claude 的配置情况，安全中心会展示你组织的 Claude 设置与 Anthropic 推荐配置之间的对比。要执行你的策略，推理钩子会将提示词和工具调用发送到你的数据安全工具进行检查。要管理访问权限，集中化管理为你的公司提供一个管理全公司设置的管理控制台，新的访问控制功能则让你可以通过 Admin API 将成员强制下线、自行管理 IP 白名单，并在受管理的电脑上阻止 Claude Desktop 中的个人账户及其他外部 Claude 账户，从而帮助防范影子 IT。

我们最近还宣布了一项端点检测与响应（EDR）集成，该集成可在用户电脑上的 统一 Claude 和 Cowork 虚拟机内运行你组织的传感器。

安全团队需要了解 Claude 的配置方式、它在公司设备上做什么，以及员工工作时数据如何处理。这些功能为他们提供了所需的可见性和控制力。

安全中心：在一个地方查看你的 Claude 安全设置

安全团队可以在一个页面上查看 Claude 针对聊天、Cowork 和 Claude Code 的安全设置，而不必逐项查看。安全中心是 Organization 设置中的一个新页面，它会将设置与 Anthropic 的推荐配置进行对比，让团队一目了然地看到需要改什么、在哪里改。

对于每项控制，安全中心都会显示当前值、推荐值（如有）以及可修改该项设置的链接。它还会显示哪些设置是新增的或近期变更的。安全中心会在每次页面加载时检查你的配置，因此自动检查的控制项会反映你的当前设置。拥有 Compliance API 的组织也可以通过该 API 读取相同的结果。

Attestations（证明）为管理员提供了一个共享的安全审查工作区。他们可以一起完成审查流程，在一个地方记录每项控制的当前状态、接受风险并标记问题。

你可以将安全中心页面下载为报告，与审计人员和相关利益方分享。报告会标明哪些控制项由页面自动检查、哪些由 Owner 确认。安全中心是基于 Anthropic 建议的指导，并非认证，也不保证符合任何法律或标准。

推理钩子（Inference hooks）

推理钩子将 Claude 与你组织已在使用的数据安全工具连接起来，使你的数据丢失防护（DLP）和安全策略能够在员工工作时应用于提示词和工具调用。

钩子有两种类型，现已全部正式上线：

  • 提示词钩子（Prompt hooks）将受支持的 Claude 产品中的提示词发送到你的安全工具进行检查。
  • 工具调用前钩子（Pre-tool-call hooks）会在受支持的 Claude 产品中的工具调用执行前对其进行检查。

钩子与安全供应商协同工作。你的团队可以保留已编写的策略，并将其应用于 Claude。

集中化管理：整个组织统一的身份与访问管理控制台

集中化管理让你的父组织（parent organization，代表你的公司在 Claude Enterprise 和 Claude Platform 各组织中的整体）拥有自己的管理控制台，地址为 admin.claude.com。管理员可以在那里一次性管理父组织下各组织的公司级设置，而不必在各个组织设置中分别操作。这些设置包括单点登录、目录同步（SCIM）、域名验证、群组和 Compliance API 密钥。

控制台会在一个地方显示父组织下的所有组织，并新增两个角色。父组织 Owner 可以管理父级别的所有内容，包括谁拥有 owner 和 admin 角色。父组织管理员可以管理除这些角色分配之外的所有内容。

公司还可以连接多个身份提供商，每个提供商都有自己的单点登录和 SCIM 配置。被收购的公司可以保留其现有提供商，你的团队也可以按域名逐个迁移到新提供商。

每个组织保留自己的成员、角色、设置和组织级安全控制，例如 IP 白名单、租户限制和会话时长。父角色默认不会授予进入组织内部的访问权限，但在父级别创建的 Compliance API 密钥可以跨组织读取数据。

访问控制：成员强制下线与影子 IT 防范

安全团队现在可以通过一次 Admin API 调用将成员从 Claude 中强制下线，而无需将其移出组织。该调用会终止该成员在所有浏览器和设备上的登录会话，Claude Code 等应用需要重新登录。它不会终止 API 密钥、正在运行的云端会话或定时例行任务，成员之后仍可重新登录。

企业管理员现在可以自行设置和管理 IP 白名单，无需经过 Anthropic。IP 白名单将大多数 Claude 产品的访问权限限制在你组织批准的 IP 地址范围内。

管理员现在可以设置最常用的 Claude Desktop 设置，无需设备管理推送。为帮助防范影子 IT，管理员还可以在受管理电脑上的 Claude Desktop 中阻止个人账户及其他外部 Claude 账户。Owner 还可以限制员工可将哪些工作区文件夹与 Claude 一起使用。

Cowork 与统一 Claude 中的端点检测与响应（EDR）

当 Cowork 和统一 Claude 在本地工作时，它们会在用户电脑上一个隔离的虚拟机中运行 shell 命令和代码，以提供额外保护。这种隔离有助于保护设备，而安全团队一直希望在虚拟机中获得与其他端点位置相同的可见性。

管理员现在可以在 Cowork 虚拟机内部运行其组织的 EDR 传感器。传感器会将那里的活动报告到你安全团队已经在监控的同一控制台。这覆盖用户电脑上的虚拟机，但不包括云端 Cowork 会话。

管理员通过 macOS 和 Windows 上的设备管理来设置该集成。每次虚拟机启动时，Claude 都会在安装前验证来自你 EDR 供应商的传感器软件包的签名。传感器以检测模式运行：它们向你的安全团队报告活动，但不会阻止活动。该集成适用于受支持的 EDR 供应商，名单见帮助中心。

开始使用

这些功能适用于 Claude Enterprise，Beta 测试期间的某些例外情况见帮助中心。

安全中心处于 Beta 测试阶段。推理钩子（包括提示词钩子和工具调用前钩子）已正式上线。管理员可以在 Organization 设置中管理推理钩子和安全中心。

集中化管理也处于 Beta 测试阶段。要开始设置，父组织下任一组织的管理员需前往 admin.claude.com 并提名父组织管理员。其他组织的管理员进行审核和批准，最后一次批准即完成设置。设置一旦完成便无法撤销，因此请在开始前确定你的父组织管理员人选。

通过 Admin API 强制成员下线和自助 IP 白名单处于 Beta 测试阶段。Owner 可以在 Organization 设置中管理Claude Desktop 设置，同样处于 Beta 测试阶段。

Cowork 中的端点检测与响应在 macOS 和 Windows 上处于 Beta 测试阶段，适用于 Claude Team 和 Enterprise，以及通过 MDM 为受支持供应商部署的 Amazon Bedrock、Google Cloud Vertex AI 和 Microsoft Foundry 上的 Claude 桌面应用。
