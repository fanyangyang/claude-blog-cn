自 Claude Security 于 4 月进入公开测试版以来，已有数千家组织使用它发现了超过一百万个漏洞。

Claude Security 不再需要等人手动启动扫描，现在它会随着代码的变化持续跟进你的代码仓库，跟踪哪些发现已被修复，并利用你的团队提供的环境信息来判断哪些问题更重要。Claude Security 由我们全系列模型驱动，包括 Claude Mythos，且无需访问 Cyber Verification Program。

最新版本的 Claude Security 即日起面向 Claude Enterprise 客户提供公开测试版。组织每月可获得 $25,000 的免费用量额度，持续两个月。该优惠适用于截至 2026 年 12 月 31 日的用量。完整条款可在 帮助中心 查看。

持续监控，紧跟你的代码

一次扫描只能捕捉一个瞬间，而代码每天都在变化。团队告诉我们，他们希望在不依赖任何人手动安排的情况下，获得持续更新的覆盖。

创建一个项目，通过 Claude GitHub 应用（包括 GitHub Enterprise Server）连接你的代码仓库，或使用来自 GitLab 和其他 Git 提供商的访问令牌连接，并为每个仓库选择分支和范围。Claude 会先运行一次深度基线扫描，然后根据变更的风险和复杂度定期扫描变更内容，让你的发现列表始终贴近代码的当前状态。

一个项目可以包含多个代码仓库，这样 Claude 就能捕捉到服务之间的关联问题，例如某个后端信任了本应由客户端校验的输入。

修复落地后，发现项即自动标记为已修复

大多数修复都发生在发现问题的工具之外。Claude Security 会将未解决的发现项与发生变更的代码进行比对，当修复落地时将其标记为已修复——无论你的团队是在 Claude Code 中修复，还是通过其他独立流程修复。如果之后 Claude Security 再次发现该问题，发现项会自动重新打开。

团队的知识塑造扫描

每个环境都有扫描器仅凭代码无法看到的控制措施。团队希望能有一种方式把这些控制措施告诉 Claude Security，并能够跨相互依赖的服务进行全局审视。现在，每个项目都有一个知识库，你可以在其中描述代码的部署方式、适用哪些安全策略，以及团队中新来的安全工程师需要了解的任何信息。

Claude Security 还会根据你的代码生成威胁模型，供团队审阅和编辑。后续的扫描会利用这些威胁模型来决定哪些内容值得标记。新增的上下文还能帮助 Claude Security 跳过你的环境已经处理过的风险。

每个发现项都有严重级别和利用路径

每个发现项都带有严重级别评级（针对你项目的威胁模型进行评判），并说明攻击者如何能够触达存在漏洞的代码，这样团队就可以优先修复实际可触达的问题。发现项还可以包含攻击路径图。

发现项触达你的工具，并为更大规模推广提供管控

新的 API 让你可以把 Claude Security 集成到现有的工作流程中。你可以列出和读取项目与发现项、解决或重新打开发现项，以及创建和管理项目及其代码仓库。用户可以在 Claude Security 设置中创建个人访问令牌，该令牌只能查看和更改该用户权限范围内的内容。Webhook 还可以在新发现项出现时通知你的系统。

Claude Security 还可以作为 MCP 连接器在 Claude.ai 和 Claude Code 中使用。工程师可以在同一会话中调出发现项、向 Claude 提问、着手修复并将其标记为已解决。

新的基于角色的访问控制让管理员可以决定谁能查看项目、分流发现项和创建项目。组织可以让更多拥有代码的团队使用 Claude Security，而无需让所有人都能创建项目。
