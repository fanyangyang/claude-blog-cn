现在，你可以将 Claude Managed Agents、Messages API 和 Claude SDKs 生成的 OpenTelemetry（OTel）追踪数据发送到任何 OTel 工具，并跟踪 agent 执行的每一步。如果你已经在向可观测性工具发送 Claude Code 或 Cowork 的追踪数据，那么你在 Claude Platform 上构建的 agent 也能显示在同一个地方。

使用 OpenTelemetry 追踪 agent

要赋予 agent 更多访问权限，首先要追踪它的模型调用、工具使用和 MCP 服务器调用。先审查它的追踪记录，再随着其可靠性得到验证逐步扩大它的访问权限。

在 Claude Console 中添加一个目的地，每次 agent 轮次、模型调用和工具使用都会以标准的 OpenTelemetry 追踪记录形式（包含延迟、token 数和 ID）进入你的可观测性工具。

与你的可观测性工具协同工作

Claude 的追踪遵循 OpenTelemetry GenAI 语义约定，因此来自 Claude 和其他服务商的数据可以在相同的工具和仪表盘中使用。

  • 与技术栈的其余部分一起调试 agent。在 Grafana Cloud、Honeycomb、Sentry 和 Splunk 中，agent 追踪记录与你的日志和指标并列展示，因此你可以看到缓慢或失败的步骤来自哪个服务。
  • 用生产数据改进 agent。借助 Arize AI、Braintrust、Datadog、Langfuse、LangSmith by LangChain、New Relic 和 PostHog，你可以将真实追踪转化为评估（evals）、发现质量问题，并衡量某项改动是否有效。
  • 跟踪整个组织的使用情况。将追踪数据发送到 Databricks Unity Gateway，让平台与安全团队可以按团队查看 token 用量并标记异常活动。

Claude 的追踪同样适用于任何接受标准 OTLP 端点的其他 OpenTelemetry 工具。

开始使用

Claude Platform 上的 OpenTelemetry 追踪现已进入公开测试阶段。Managed Agents 和 Messages API 需要在 Claude Console 中配置目的地，而 Claude SDKs 会自动导出追踪数据。
