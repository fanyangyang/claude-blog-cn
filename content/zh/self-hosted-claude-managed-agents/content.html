自托管 Claude Managed Agents现已推出私测版。开发者可以构建直接在企业代码库和内部系统中工作的智能体，并在自己的环境中运行这些智能体。

自托管是运行 Managed Agents 的一种新方式。Managed Agents 是一套可组合的 API，用于构建和部署自主智能体，提供智能体 harness、沙箱、凭证处理和会话历史，帮助长时间运行的智能体进入生产环境。

在你自己的环境中运行智能体控制平面

我们最初是在 Claude Platform 上以托管服务的形式推出 Managed Agents，由 Anthropic 为你运行基础设施。对于需要让代码留在自己环境中的团队，我们随后增加了自托管沙箱。

此后，智能体的能力越来越强，也承担起更关键的工作，例如修复损坏的构建、测试发布版本、分诊告警、处理积压的缺陷。它们在无人值守的情况下运行在你的代码之上，并需要访问你的内部系统。对于拥有这种访问权限的智能体，一些团队希望把整个服务都放在自己的环境中，而不仅仅是沙箱。在此之前，这意味着要自己搭建这个平台。

使用自托管 Managed Agents，服务的每个部分都运行在你自己的云或本地环境中，包括 harness、沙箱、凭证和会话历史。你负责运维 Managed Agents 服务器、其数据库，以及智能体运行 shell 和文件工具的工作节点。模型请求发送到哪里由你决定：可以直接发给 Anthropic、你的云服务商（Amazon Bedrock、Google 的 Agent Platform 或 Microsoft Foundry），或者你自己的网关。你的开发者仍然使用与托管版 Managed Agents 服务相同的核心 API 来构建智能体。

会话历史存储在你自己的数据库中。如果你的组织与 Anthropic 之间启用了零数据保留（ZDR），那么它同样适用于发送给 Claude 的请求，与任何其他 Messages API 调用一致。

为智能体安全而设计

当智能体在你的代码和系统中无人值守地运行时，你不能依赖某个人来检查每一步，因此限制必须内建在系统本身之中。这就是为什么智能体安全要从架构开始，也是我们围绕四项原则设计 Managed Agents 的原因。无论是由 Anthropic 托管全部内容、你只托管沙箱，还是你托管整个服务，这些原则都适用。

大脑与双手是分离的

harness（大脑）调用 Claude，沙箱（双手）则是智能体代码运行的地方。二者在设计上保持分离。智能体的代码在沙箱中运行，而智能体循环、会话历史和金库密钥都留在沙箱之外。将二者分离还意味着智能体不依赖某一个沙箱在整个运行期间存活，沙箱只在某个工具需要时才启动，会话历史则以事件日志的形式存放在沙箱之外。

凭证不进入沙箱

金库的设计目的就是让凭证不进入沙箱。对于 MCP 工具和受支持的 API 调用，沙箱之外的代理会把凭证添加到请求中。使用自托管 Managed Agents，你还可以把凭证存放在自己的密钥管理器中。

网络访问可以被限制

你可以把每个环境限制在一份允许的主机列表内，发往其他主机的请求都会被阻止。对于一个修复损坏构建的智能体来说，这份列表可能只有你的 git 主机和软件包仓库。当你自己托管沙箱时，你在自己的防火墙中设置同样的限制。

每次会话都留下完整记录

Managed Agents 会记录智能体采取的每一步，包括它发起的工具调用以及返回的内容。该记录可通过 OpenTelemetry 导出，因此你可以把它发送到已经在用的监控工具，并将智能体活动与系统其余部分一并审查。
