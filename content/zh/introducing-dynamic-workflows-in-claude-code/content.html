更新：Dynamic workflows 现已正式发布（GA）。

今天我们在 Claude Code 中推出 dynamic workflows（动态工作流），帮助 Claude 端到端地承担最具挑战性的任务。过去需要按季度规划的工作，现在几天内就能完成。Claude 会动态编写编排脚本，在单个会话中运行数十到数百个并行 subagent，并在任何结果交付给你之前先完成自我校验。

有些问题单靠一个 agent 一次处理难以完成，尤其是在复杂的遗留代码库中：跨越整个服务的 Bug 排查、涉及数百个文件的迁移、在正式投入之前希望从各个角度进行压力测试的方案。Dynamic workflows 可以端到端地处理所有这些任务。

Dynamic workflows 现已在 Claude Code CLI、桌面端和 VS Code 扩展中面向 Pro、Max、Team 和 Enterprise 计划正式发布，同时也可在 Claude API、Amazon Bedrock、Vertex AI 和 Microsoft Foundry 上使用。

注意：Dynamic workflows 消耗的 token 可能显著多于一般的 Claude Code 会话，因此我们建议先从一个范围明确的任务入手，了解它在你的工作中的实际用量。 

为了获得最佳体验，使用 dynamic workflows 时请开启 auto mode。在此之上，你有两种启动工作流的方式：

  1. 直接让 Claude 创建一个 dynamic workflow（例如“创建一个工作流”），或者
  2. 开启 Claude Code 的一个新设置项 ultracode。它位于 effort（投入度）菜单中，会将 effort 级别设为 xhigh，同时让 Claude 自动判断何时使用工作流来处理你的任务。

Dynamic workflows 实战

早期体验用户和 Anthropic 内部团队已经在各种场景中使用 dynamic workflows，包括：

  • 全代码库 Bug 排查、基于 profiler 的优化审计和安全审计：Claude 并行搜索某个服务或代码仓库，然后对每个发现进行独立验证，确保报告呈现的是真实问题。同样的模式也适用于加固类任务：对整个代码库进行权限校验、输入验证和不安全模式排查。
  • 大规模迁移与现代化改造：Claude 可以端到端地完成框架替换、API 弃用处理、涉及数千个文件的语言迁移。‍
  • 需要反复核查的关键工作：当错误答案的代价很高时，工作流会让 Claude 对问题进行多次独立尝试，并安排对抗性 agent 试图攻破结果，然后才呈现给你。
