更新：动态工作流（dynamic workflows）现已正式全面可用。

今天我们在 Claude Code 中推出动态工作流，帮助 Claude 端到端承担最具挑战性的任务。你通常按季度规划的工作，现在可以在几天内完成。Claude 会动态编写编排脚本，在单次会话中运行数十到数百个并行子 agent，并在任何结果到达你之前先检查自己的工作。

有些问题对单个 agent 的一次通过来说太大，尤其是在复杂的遗留代码库里：跨整个服务的缺陷排查、触及数百个文件的迁移、你想在投入之前从每个角度压测的计划。动态工作流可以端到端处理这一切。

动态工作流已在 Claude Code CLI、Desktop 和 VS Code 扩展中对 Pro、Max、Team 和 Enterprise 计划全面可用，也可通过 Claude API、Amazon Bedrock、Vertex AI 和 Microsoft Foundry 使用。

注意：动态工作流消耗的 token 可能远高于一次典型的 Claude Code 会话，因此我们建议先从一个范围明确的任务开始，感受它在你工作中的用量。 

为获得最佳体验，使用动态工作流时请打开 auto mode。之后你有两种方式启动工作流：

  1. 直接让 Claude 创建动态工作流（例如“Create a workflow”），或
  2. 打开一个新的 Claude Code 专用设置 ultracode。它可在 effort 菜单中访问，会把 effort 级别设为 xhigh，同时让 Claude 自动决定何时用工作流来处理你的任务。

动态工作流实践

抢先体验用户和 Anthropic 内部团队已将动态工作流用于广泛场景，包括：

  • 全代码库缺陷排查、由 profiler 引导的优化审计，以及安全审计：Claude 并行搜索一个服务或仓库，再对每一项发现做独立核验，让报告浮现真正的问题。同样的形态也适用于加固：跨整个代码库检查 auth、输入校验和不安全模式。
  • 大规模迁移与现代化：Claude 可以端到端处理框架替换、API 废弃，以及跨越数千个文件的语言移植。‍
  • 需要双重检查的关键工作：当答错的代价很高时，工作流会让 Claude 对问题做独立尝试，并让对抗性 agent 在你看到结果之前去打破它。

用动态工作流重写 Bun

动态工作流能在规模上解锁什么，一个例子是最近对 Bun 的重写。Jarred Sumner 用动态工作流把 Bun 从 Zig 移植到 Rust，现有测试套件通过率 99.8%，大约 75 万行 Rust，从第一次提交到合并用了十一天。一个工作流为 Zig 代码库中每个 struct 字段映射正确的 Rust lifetime。下一个工作流把每个 .rs 文件写成对应 .zig 文件的行为等价移植，数百个 agent 并行工作，每个文件配两名审查者。随后一个修复循环驱动构建和测试套件，直到两者都干净通过。移植落地后，一个过夜工作流处理了不必要的数据拷贝，并为每一项开出 PR 供最终审查。虽然尚未进入生产，但这一切都由动态工作流完成。Jarred 之后还会再写这方面的内容。

工作原理

工作流启动后，Claude 会根据你的提示动态规划，拆成子任务，并把工作分发给并行运行的子 agent。结果在并入之前会先检查，你最终看到的是一份协调好的单一答案。Agent 从独立角度处理问题，其他 agent 尝试反驳他们的发现，运行会持续迭代直到答案收敛——这就是工作流能达到单次通过无法达到的结果的原因。

动态工作流为可延伸到数小时乃至数天的并行和长时工作而设计，完成此前需要数周的最复杂工程工作。进度会在运行过程中保存，因此被中断的任务会从停下的地方继续，而不是从头开始。因为协调发生在对话之外，无论任务变得多大，计划都能保持在轨道上。

需要注意的是，动态工作流消耗的用量明显高于一次典型的 Claude Code 会话。工作流第一次触发时，Claude Code 会展示即将运行的内容并请你确认。组织管理员也可以通过托管设置选择关闭工作流。

开始使用

动态工作流对 Max、Team 和 Enterprise 计划默认开启，通过 API 使用 Claude Code 时也是如此。Pro 计划用户可以在 /config 中启用。让 Claude 创建工作流，或打开 Claude Code 专用设置 ultracode 即可开始。管理员可以在 settings 中管理可用性。
