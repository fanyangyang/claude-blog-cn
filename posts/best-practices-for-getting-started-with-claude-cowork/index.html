Claude Cowork 上手最佳实践

阅读英文原文 →

2024 年，Claude 还待在聊天窗口里。你提出问题，它给出回答，但要把回答变成有用的东西，还是得靠你自己。2025 年，Claude Code 让工程师们的交付速度快到让我们其他人有点眼红。

今年，我们所有人都能跟上节奏了——借助 Claude Cowork。

我从去年开始用 Claude Code 来处理聊天模式应付不了的长流程、多步骤任务。不到一周，我就从一个不知道终端是什么的人，变成了搭建出能把 30 分钟任务在 30 秒内完成的 Claude Code 工作流的人。当时我用 Claude Code 做非技术工作，纯粹是因为 Claude Cowork 还不存在。

现在，我 90% 的工作都在 Claude Cowork 中完成。在这篇文章里，我会告诉你如何判断哪些任务适合交给它，通过我工作中的真实案例带你走一遍流程，并让你在大约十分钟内产出第一份完成的交付物。

Chat、Claude Cowork 与 Claude Code 怎么选

如果你的工作是非技术性的知识工作——邮件、幻灯片、表格、文档、会议，以及“能不能帮我汇总一下这个”——那 Claude Cowork 就是为你准备的。你不需要会写代码，也不需要知道什么是“智能体”或者怎么搭建一个。

如果你在过去两年里一直开着 100 多个标签页和文件，其中一个标签页是 AI 聊天，你把提示词或问题复制粘贴进去，再把答案复制粘贴出来，那你已经会用 Claude Cowork 了。它做的就是这件事，只是省去了复制粘贴。

Chat、Claude Cowork、Claude Code、Claude Design，以及 Claude 出现的所有其他地方，背后都是同一批 Claude 模型。它们是用于不同工作类型的独立工作区，但内部运行的是同样的模型。下面是一个帮助你判断何时使用哪一个的框架：

  • Chat 往往是知识工作者接触 Claude 的起点。你把自己手头的东西交给 Claude：上传一个文件、粘贴一段文字、描述一下情况，然后得到回答。Chat 适合获取答案、头脑风暴和梳理思路。
  • Claude 桌面应用中的 Claude Cowork 则把这件事反转过来。不是你把工作带给 Claude，而是把 Claude 带到你的工作中。你让它指向电脑上的某个文件夹，把它连接到你已经在用的应用，然后告诉它你想完成什么。使用 Claude Cowork 时，你只需描述一个成果，然后走开，回来时工作已经完成。‍
  • Claude Code 专为构建和交付软件的开发者设计。如果你的工作以代码为核心，从它开始。

很多人不知道，Claude Cowork 和 Claude Code 底层运行在同一个引擎上。

什么时候该用 Claude Cowork？

理解什么时候用 Claude Cowork、什么时候用 Chat，是大多数人卡住的地方，所以这里分享我的经验法则：

  • 如果想要的东西在几轮对话内就能解决，比如一个问题、一段解释、一次头脑风暴或一个快速求证，用 Chat。
  • 如果你需要的是一份交付物——比如一个别人会打开的文件、一份别人会演示的幻灯片、一张待整理的表格——用 Claude Cowork。凡是多步骤的、涉及多个文件或文件类型的、跨多个应用的，或者你会把它描述为“任务”而不是“问题”的事情，都用它。使用 Claude Cowork 时，你是在把工作委派给 Claude。

适合 Claude Cowork 的任务有五个特征

刚上手时如果不确定该把哪些项目委派给 Claude Cowork，可以用这份清单过一遍。不必五条全部满足，但一个合适的候选任务通常能命中其中几条：

  1. 输入不止一样东西。多个文件、一整个文件夹，或者一个文件加上若干连接器。如果只有一个输入，Chat 大多数情况下就够用了（不过你仍可以多试试）。
  2. 产出是一个文件。你需要一份可以附加、演示、分享或再利用的交付物：文档、幻灯片、表格或 CSV。
  3. 你会反复做这件事。一次性的任务也没问题，但周期性任务才是最佳场景。你可以把它们安排在你还没到工位之前就自动运行。
  4. 你已经知道“好”长什么样。你对产出的形态很熟悉，所以能在 15 秒内判断结果是正确的、错误的，还是完成了七成。
  5. 中间过程是无聊的部分。思考集中在一头一尾：开头是决定你要什么，结尾是判断结果对不对。中间的一切（提取、汇总、核对、重新排版）就是你交出去的部分。

我在 Anthropic 如何使用 Claude Cowork

我在 Anthropic 负责增长营销，所以我的例子都带着营销色彩。不要照搬这些工作流——从长远看那不会有什么帮助。要看的是每个案例如何命中上面清单中的若干条，因为那才是你在自己的 Claude Cowork 工作流中要寻找的模式。

每日简报

营销人员每天收到的 Slack 消息和邮件数量可能让人喘不过气。我设置了一个每天早上 6 点运行的“每日简报”任务。Claude Cowork 连接了我的 Slack 和 Gmail，我的提示词告诉它查看我未读的邮件和我关注的频道，把它们分类整理，并生成一份简短的报告。

这份报告会给我一个“需要关注什么”的 TLDR、按类型分组的标记邮件、频道摘要，以及任何可能影响营销的隔夜产品相关事件。任何被 Slack 和邮件淹没的人都可以运行某个版本的这个工作流。

预算消耗进度

我的部分职责包括效果营销的预算消耗进度管理。这是那种没人想干的活，因为既无聊又繁琐。许多效果营销团队会在 Google Sheets 中跟踪每日花费和消耗速率，来估算达成目标的进度。要么你手动从每个渠道导出每日花费再粘贴到表格里，要么你花钱买第三方工具帮你做数据的抽取、转换和加载。

有了 Claude Cowork，我连接 Google Ads 和 Meta Ads，在桌面应用中创建一个实时 artifact（本质上就是一个 HTML 仪表盘），自动拉取我的每日花费并帮我计算消耗进度。我还可以直接用自然语言告诉 Claude 如何筛选我的广告系列，以及需要留意什么。

拿上面的清单来对照：多个数据源输入（每个渠道的花费）、产出一个文件（这里是仪表盘）、我会不断重新运行，而中间过程正是那种榨干灵魂的“下载—复制—粘贴”机械劳动，我绝对不想自己干。由于广告平台都是通过连接器集成的，我可以随时更新这个仪表盘。

报告

我不是导出一堆 CSV 再手动建数据透视表或合并文件，而是让 Claude Cowork 连接 Google Search Console。它拉取我关心的内容（查询词、国家、页面），并核对汇总到一张表格里——而不是像 Google 默认的那样，手动导出数据时每个维度一个 CSV。

我还会告诉 Claude 该关注什么，比如对比最近七天和之前七天、只筛选特定国家、标记任何有明显变化的项目，并按照我想要的模板撰写报告。之后我可以随意微调，或者向 Claude 追问。

借助 Claude Cowork 的定时功能，这每周自动运行一次。报告以前每周要花我大约 30 分钟，现在只要 5 分钟，而且我可以把时间花在真正需要判断力的部分：补充缺失的背景、打磨重点提示。

你的前 10 分钟 Claude Cowork 体验

第一次打开应用？按下面的步骤开始：

  1. 打开 Claude 桌面应用，切换到 Claude Cowork 标签页。
  2. 给 Claude 一些可用的材料。放入几个文件、让它指向电脑上的某个文件夹，或者连接一个你常用的应用（Slack、Gmail、Notion、CRM 等）。Claude Cowork 产出的平庸与出色之间的差距，几乎从来不在你的提示词，而在于你是否提供了足够丰富的上下文供 Claude 使用。
  3. 告诉 Claude 你想要的成果。描述你最终想要的交付物，并提供必要的背景信息。
  4. 从一个你非常熟悉的真实任务开始。你会立刻看到它哪里强、哪里需要你补充上下文，而且你本来就知道这个任务的“好”是什么样子。
  5. 让 Claude 在开始之前先向你提问。这是我养成的最有用的习惯。在提示词里加上这句：开始之前，先向我复述一遍我的需求以确认我们理解一致，然后把你所有想澄清的问题都问我。

这会暴露出你没想到要说明的事情，比如我们看的是哪个时间段、这里的“好”意味着什么、有哪些你才知道而 Claude 不知道的边界情况。陷阱在于假设 Claude 已经知道那些对你来说显而易见的东西。提前回答五个问题只花你 30 秒；事后发现同样的遗漏，花费的是你的时间和 token，而且返工很痛苦。

还是不确定该交出什么？问 Claude。Claude 有记忆功能，可以搜索你过去的对话，所以你可以问它你最常做哪些任务，以及哪些任务值得在 Claude Cowork 里试试。

我仍然会用 Chat 的场景

我依然大量使用 Chat 来讨论定位问题、在下定决心之前压力测试一个想法，或者问一些随机问题，比如我家狗为什么总舔床。

重点不在于 Chat 是“过时的东西”。Chat 适用于产出是你脑中一个想法的场景，而 Claude Cowork 适用于产出是你要交给别人的东西的场景。

去做点什么吧

挑一个你每周都会做的重复性任务，试着用 Claude Cowork 完成它，看看结果如何。最初几个任务可能感觉有点别扭，但试过几次之后，你很快就会从“这要怎么用”变成“下一个该交给它什么”。
