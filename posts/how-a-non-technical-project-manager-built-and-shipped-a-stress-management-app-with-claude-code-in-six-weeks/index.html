一位不懂技术的项目经理如何用 Claude Code 在六周内开发并上线一款压力管理应用

Kostiantyn Vlasenko had never written a line of code when he set out to build Respiro. Just over a month later, his product was live on the App Store.

在"Day zero: founder stories"（第零日：创始人故事）系列中，我们讲述全球最有趣、最振奋人心的初创公司背后的构建者。本文的主角是 Claude Opus 4.6 Hackathon 的获奖者、Respiro 的创造者 Kostiantyn Vlasenko。

在加入本次采访视频通话的十五分钟前，Kostiantyn Vlasenko 感到有些紧张。不过他满脑子都在组织想说的话，以至于并没有察觉到自己的焦虑——但他的手机察觉到了。

"应用检测到了这一点并提醒我：'伙计，你可以去做一次简短的方块呼吸练习。方块呼吸之前帮你缓解过压力。'"他说。

这款应用 Respiro 正是 Vlasenko 的作品。虽然做了十年项目经理，但在 2026 年 2 月决定为 Built With Opus 4.6 Claude Code Hackathon 构建一个项目之前，他从未发布过一行代码。一个月后，Respiro（一款以科学为依据的压力管理 iOS 应用）已经上架 Apple App Store，拥有数百名用户，背后运行着一套由 15 个以上专业子智能体组成的架构——全部由 Vlasenko 自己构建和调度。 

这一切都靠 Claude Code 完成，只用了 72 小时，没有团队，也没有编程经验。 

没有应用能解决的问题

作为 Mythical Games 的项目经理，常驻基辅的 Vlasenko 十年来一直在应对干系人压力、团队动态和产品发布的连轴转。他发现呼吸技巧和正念有助于控制压力水平；他找不到的，是一款能在压力真正袭来的时刻及时介入的压力管理工具。

"现有的应用可以在晚上十点提醒我做几组深呼吸之类的，但它们不理解我此刻正处在压力中，"他解释道。当他正在乌克兰西部山区度假时，这个想法豁然清晰：做一款能从你的个人设备实时检测压力信号的应用，并在你最需要的时刻用引导式正念呼吸练习进行干预。唯一的问题是：他不会做应用。

像管理人一样管理智能体

那时，Vlasenko 已在用 Claude 自动化一些工作事务，比如更新 Jira、把会议纪要发到 Slack，并且刚开始使用 Claude Code CLI。"后来我想，好吧，我熟悉我的团队成员是怎么用 Claude 写代码的，我为什么不能也这么做？"他说。 

他很快意识到，自己的项目管理背景比编码能力更重要。"我有大量管理真人的经验，"他说，"我意识到这其实是一回事，只不过是在我的 IDE 里管理智能体，而且我真的很惊讶这竟然这么容易。"

Vlasenko 笑称自己的第一个提示词基本上就是"嘿 Claude，给我做一个能让我少点压力的应用"，但即便如此，他说最初的结果仍让他惊叹："哇，太厉害了。它不只存在于我的脑子里，它此刻就在我的手机里，而且能用！"

但 Vlasenko 没有止步于此。他用 Claude 研究了智能体系统的原理、哪些 Apple API 可以为他的压力检测逻辑提供数据，然后让 Claude 帮忙搭建了一套多智能体架构：TCA 架构师智能体、Swift 开发者智能体、Metal 专家、代码审查员等等，跨不同模块并行工作。 

Claude 还让转型毫无痛感：当 Respiro 最初基于 React Native 的 MVP 因为 Vlasenko 没有 Android 手机可供测试而变得棘手时，他用 Claude Code 在几个小时内从零开始用 Swift 重写了整个应用。 

他算了一下，从最初的想法到功能完整、可上架 App Store 的 Respiro，总共用了不到六周。

从 Claude Code 代码到 App Store

做应用是一回事，发布它则是另一回事，而 Vlasenko 从未涉足过 Apple Developer Program。他让 Claude 一步步带他走完了这个时而令人迷惑的流程。

"当我卡住的时候，我就截个图问 Claude：'嘿，这里我该按哪个？'"他说。设置 Sentry 日志和 Amplitude 分析等其他第三方服务时，他用的也是同样的办法。"我会告诉 Claude：我完成登录了，这是 API key，99% 的情况下 Claude 一次就搞定，"Vlasenko 说。至于剩下那 1%，他接着说："我只需要把第一个提示词里的需求说得更清楚一点，再试几次，Claude 就能给我想要的结果。"

事实上，Vlasenko 认为 Claude 的视觉能力是最被低估的功能。"你把截图发给 Claude 分析，它会告诉你它看到了什么。然后你就可以让 Claude 带你走过再复杂的 UX，"他解释道，"比如我得在 Meta 上创建一个 API token，我在他们的界面里完全迷路了，但 Claude 真的能看懂，并把你需要去的每个地方都指引到位。"

推广 Respiro 同样有 Claude 相助。当 Vlasenko 需要数据分析时，Claude 不止于接入 Amplitude 的基础 SDK，还搭建了完整的用户漏斗、留存指标以及日活、月活的实时追踪。当他需要内容时，Claude 开始替他写博客文章、帮他做 TikTok。Claude 还提出了一条 Vlasenko 自认绝不会想到的增长策略：联系心理学家和正念导师，请他们向自己的客户推荐 Respiro。他试了，成了。从业者真的开始推荐这款应用。

进入工作时的创始人模式

Vlasenko 在构建 Respiro 中练就的本领并没有只用在副业上。如今在 Mythical Games 的本职工作中，他也在提交代码发布、直接上线功能。更进一步，他成了自己在构建 Respiro 过程中打磨出的开发流程的内部布道者，把自己的 Claude 文件夹和工作流分享给了工程团队。

"他们中的大多数人事后回来对我说：嘿，这套工作流比我现在用的强多了！"他说。结果是，Mythical 现在有了一个完全通过 Claude 交付工作的小型内部团队。不过 Vlasenko 也注意到，对所有人来说这都不是一次毫无摩擦的转变。"对一些工程师来说，放弃完全掌控每一行代码的心态很难，"他说，"对我来说就容易多了，因为我没有深厚的编程背景，这对我来说就像一种自然而然的工作方式。"

对 Vlasenko 而言，构建 Respiro 的经历抹掉了可能与不可能之间的界限。他正在为应用的下一个版本开发语音引导练习和动作练习，依照的是 Claude 帮他写的路线图，并且在结束一天的本职工作后，还要再投入七八个小时的编码会话。

"我想说，Claude Code 是我的新爱好（戒不掉的那种），"他说。
