你可能已经注意到：如果不加引导，让一个 LLM 去做落地页，它几乎总是 Inter 字体、白底紫色渐变、寥寥几个动画。

问题出在哪？分布收敛（distributional convergence）。在采样时，模型基于训练数据中的统计模式预测 token。安全的设计选择——那些放之四海皆准、不得罪任何人的方案——在网络训练数据中占主导。没有方向时，Claude 就从这个高概率的中心地带采样。

对于构建面向客户产品的开发者来说，这种千篇一律的审美会削弱品牌识别度，让 AI 生成的界面一眼可辨——也一眼可弃。

可引导性的挑战

好消息是，只要提示得当，Claude 的可引导性（steerability）极强。告诉 Claude"避免 Inter 和 Roboto"或"用氛围感背景代替纯色"，效果立竿见影。这种对引导的敏感本身是个特性：它意味着 Claude 能适应不同的设计语境、约束和审美偏好。

但这带来一个现实难题：任务越专门化，你需要提供的上下文就越多。对于前端设计，有效的指导涵盖排版原则、色彩理论、动效模式和背景处理。你需要在多个维度上指明要避开哪些默认选项、偏好哪些替代方案。

你可以把这一切塞进系统提示词，但这样一来，每个请求——调试 Python、分析数据、写邮件——都会背着前端设计的上下文。于是问题变成：如何恰好在需要时为 Claude 提供领域专属的指导，而不给无关任务带来常驻的上下文开销？

Skills：动态上下文加载

这正是 Skills 的设计初衷：按需交付专门上下文，而没有常驻开销。一个 Skill 是一份文档（通常是 markdown），包含指令、约束和领域知识，存放在指定目录中，Claude 可以通过简单的文件读取工具访问。Claude 可以借助这些 Skills 在运行时动态加载所需信息，渐进式地增强其上下文，而不是把所有内容预先加载。

当配备了这些 Skills 以及读取它们的必要工具后，Claude 就能根据手头任务自主识别并加载相关 Skill。例如，被要求做落地页或创建 React 组件时，Claude 可以加载前端设计 Skill，即时应用其中的指令。核心心智模型就是：Skills 是按需激活的提示词和上下文资源，为特定任务类型提供专门指导，而不产生常驻的上下文开销。

这让开发者既能收获 Claude 可引导性带来的红利，又不必为了塞进跨任务的杂糅指令而撑爆上下文窗口。正如我们此前解释的，上下文窗口中 token 过多会导致性能下降，因此保持上下文窗口精简聚焦，对于激发模型的最佳表现极为重要。Skills 通过让有效提示词变得可复用、可情境化，解决了这个问题。

为更好的前端产出而提示

通过创建一个前端设计 Skill，我们可以在不产生常驻上下文开销的前提下，解锁 Claude 显著更好的 UI 生成效果。核心洞见是：像前端工程师那样思考前端设计。你越能把审美层面的改进映射到可实现的前端代码，Claude 就执行得越好。

基于这一洞见，我们确定了几个针对性提示行之有效的方向：排版、动效、背景效果和主题。这些都可以干净地转化为 Claude 能写出的代码。在你的提示词中落地这些内容并不需要详尽的技术指令，只要用有针对性的语言引导模型在这些设计维度上更批判性地思考，就足以激发更强的输出。这与我们在上下文工程博客文章中给出的建议高度一致：在合适的"高度"上提示模型，避开两个极端——既不是指定精确色号这类低空硬编码逻辑，也不是默认对方有共同背景的高空泛泛而谈。

排版

眼见为实，先从排版入手，把它看作可以通过提示影响的一个维度。下面的提示词专门引导 Claude 使用更有趣的字体：

<use_interesting_fonts>
Typography instantly signals quality. Avoid using boring, generic fonts.

Never use: Inter, Roboto, Open Sans, Lato, default system fonts

Here are some examples of good, impactful choices:
- Code aesthetic: JetBrains Mono, Fira Code, Space Grotesk
- Editorial: Playfair Display, Crimson Pro
- Technical: IBM Plex family, Source Sans 3
- Distinctive: Bricolage Grotesque, Newsreader

Pairing principle: High contrast = interesting. Display + monospace, serif + geometric sans, variable font across weights.

Use extremes: 100/200 weight vs 800/900, not 400 vs 600. Size jumps of 3x+, not 1.5x.

Pick one distinctive font, use it decisively. Load from Google Fonts.
</use_interesting_fonts>

主题

另一个可以提示的维度，是借鉴知名主题和美学风格的设计。Claude 对流行主题有着丰富的理解；我们可以利用这一点，把我们希望前端呈现的具体美学传达给它。举个例子：

<always_use_rpg_theme>
Always design with RPG aesthetic:
- Fantasy-inspired color palettes with rich, dramatic tones
- Ornate borders and decorative frame elements
- Parchment textures, leather-bound styling, and weathered materials
- Epic, adventurous atmosphere with dramatic lighting
- Medieval-inspired serif typography with embellished headers
</always_use_rpg_theme>

一个通用提示词

同样的原则适用于其他设计维度：为动效（动画和微交互）做提示，能为静态设计增添打磨感；引导模型选择更有趣的背景，则能创造纵深和视觉趣味。这正是综合性 Skill 大显身手之处。

把这一切融会贯通，我们开发了一个约 400 token 的提示词——足够精简，加载时不会撑爆上下文（即使作为 Skill 加载也一样）——却能在排版、配色、动效和背景上显著改善前端输出：

<frontend_aesthetics>
You tend to converge toward generic, "on distribution" outputs. In frontend design,this creates what users call the "AI slop" aesthetic. Avoid this: make creative,distinctive frontends that surprise and delight.

Focus on:
- Typography: Choose fonts that are beautiful, unique, and interesting. Avoid generic fonts like Arial and Inter; opt instead for distinctive choices that elevate the frontend's aesthetics.
- Color & Theme: Commit to a cohesive aesthetic. Use CSS variables for consistency. Dominant colors with sharp accents outperform timid, evenly-distributed palettes. Draw from IDE themes and cultural aesthetics for inspiration.
- Motion: Use animations for effects and micro-interactions. Prioritize CSS-only solutions for HTML. Use Motion library for React when available. Focus on high-impact moments: one well-orchestrated page load with staggered reveals (animation-delay) creates more delight than scattered micro-interactions.
- Backgrounds: Create atmosphere and depth rather than defaulting to solid colors. Layer CSS gradients, use geometric patterns, or add contextual effects that match the overall aesthetic.

Avoid generic AI-generated aesthetics:
- Overused font families (Inter, Roboto, Arial, system fonts)
- Clichéd color schemes (particularly purple gradients on white backgrounds)
- Predictable layouts and component patterns
- Cookie-cutter design that lacks context-specific character

Interpret creatively and make unexpected choices that feel genuinely designed for the context. Vary between light and dark themes, different fonts, different aesthetics. You still tend to converge on common choices (Space Grotesk, for example) across generations. Avoid this: it is critical that you think outside the box!
</frontend_aesthetics>

在上面的例子中，我们首先给 Claude 提供关于问题本身和我们要解决什么的一般性背景。我们发现，为模型提供这类高层背景是校准输出的有效提示技巧。接着，我们列出前面讨论过的那些设计改进向量，并给出针对性建议，鼓励模型在所有这些维度上更有创造性地思考。

我们还在结尾附加了额外指导，防止 Claude 收敛到另一个局部最优。即使明确要求避开某些模式，模型仍可能默认选用其他常见选项（比如排版用 Space Grotesk）。最后那句"跳出框框思考"的提醒，强化了创造性变化。

用 Skills 提升 claude.ai 中 Artifacts 的质量

设计品味并不是唯一的限制。Claude 在构建 Artifacts 时还面临架构层面的约束。 Artifacts 是 Claude 创建并显示在聊天旁边的可交互、可编辑内容（如代码或文档）。

除了上文探讨的设计品味问题，Claude 在 claude.ai 中生成优秀前端 Artifact 的能力，还受到另一个默认行为的限制。目前，当被要求创建前端时，Claude 只会构建一个内含 CSS 和 JS 的单个 HTML 文件。这是因为 Claude 知道，前端必须写成单个 HTML 文件，才能被正确渲染为 Artifact。

正如你会预期：如果一位人类开发者只能把 HTML/CSS/JS 写进单个文件，那也只能做出非常初级的前端。我们由此推测，如果给 Claude 指令让它使用更丰富的工具链，它就能生成更出彩的前端 Artifact。

于是我们创建了 web-artifacts-builder Skill，它利用 Claude操作计算机的能力，引导 Claude 使用多个文件和现代 Web 技术（如 React、Tailwind CSS 和 shadcn/ui）来构建 Artifact。在底层，该 Skill 提供了一些脚本，(1) 帮助 Claude 高效搭建基础 React 仓库，(2) 在编辑完成后用 Parcel 把所有内容打包成单个文件，以满足单 HTML 文件的要求。这正是 Skills 的核心好处之一——通过让 Claude 调用脚本来执行样板操作，Claude 得以在提升可靠性和性能的同时，把 token 用量降到最低。

有了 web-artifacts-builder Skill，Claude 可以调用 shadcn/ui 的表单组件和 Tailwind 的响应式网格系统，打造更完整的 Artifact。

用 Skills 优化 Claude 的前端设计能力

这个前端设计 Skill 展示了关于语言模型能力的一个更普遍的原则：模型往往具备超越其默认表现的能力。Claude 有很强的设计理解力，但分布收敛让这份理解在没有引导时被掩盖。虽然你可以把这些指令加进系统提示词，但这意味着每个请求都背着前端设计上下文，即便这些知识与手头任务无关。而使用 Skills，则能把 Claude 从一个需要持续指导的工具，变成一个为每项任务都带来领域专长的伙伴。

Skills 的高度可定制性——你可以创建契合自身需求的定制版本。这让你能定义希望固化进 Skill 的具体原语，无论是公司的设计系统、特定的组件模式，还是行业专属的 UI 惯例。通过把这些决策编码进 Skill，你把智能体思维的组成部分变成了整个开发团队都能复用的资产。Skill 成为可持续沉淀和扩展的组织知识，确保跨项目的一致质量。

这一模式并不限于前端工作。任何 Claude 产出平庸但其实理解更深远的领域，都是开发 Skill 的候选。方法是一致的：识别收敛的默认行为，提供具体的替代方案，在合适的高度上组织指导，并通过 Skills 让它可复用。

对前端开发来说，这意味着 Claude 无需逐次提示词工程就能生成有辨识度的界面。要开始实践，请探索我们的前端设计 cookbook，或试试我们在 Claude Code 中的全新前端设计插件。
