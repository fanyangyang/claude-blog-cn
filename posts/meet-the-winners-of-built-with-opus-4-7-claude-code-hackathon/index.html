Built with Opus 4.7 Claude Code 黑客马拉松获胜者专访

From medical training and electronics repair to coding education and factory maintenance, see the projects built by the winners of our latest virtual hackathon.

上周，我们举办了 Claude Build Day——我们最新的黑客马拉松，构建者们齐聚旧金山，用 Claude Opus 4.8 把想法变成现实。 

在等待他们的作品揭晓之前，我们和 Built with Opus 4.7 黑客马拉松的获胜者聊了聊他们的项目。他们的作品覆盖了医学训练、电子产品维修、计算机科学教育、互动娱乐、家庭维修和工厂维护等领域。 

祝贺各位获胜者和所有参与者！希望他们的想法能给你带来启发。

第一名：Medkit，Bedirhan Keskin

Bedirhan Keskin 是一位常驻伊斯坦布尔的医生转型的软件工程师，他用 Claude Managed Agents 构建了 Medkit：一款面向住院医师和初级医生的学习工具，在一个游戏化的医疗诊所中模拟真实的患者接诊。

“当你独自一人待在急诊科，外面还有 50 位患者在等候，而这时你意识到有些病例你在医学院里从未练过，你只能在真实的患者身上实时练习，”Bedirhan 说。 

借助 Medkit，医学生可以对模拟患者进行诊断和治疗练习，用这款工具采集病史、开化验单、读影像、下诊断、开处方。最后，一个智能体评分器会按照与执业医师考试考官相同的已发布临床指南，对整个接诊过程进行评估。

Bedirhan 在四个独立的 Claude Code 会话中构建 Medkit（语音引擎、内容生成、3D 游戏层和核心应用），让每个会话的上下文保持干净，同时推进所有部分。他奉行“能说就不打字”的方式，几乎全部通过语音完成工作。 

Medkit 已经开始获得关注，三家医学院院系和一家制药公司（均位于伊斯坦布尔）将在未来几周内启动试点。  

给其他构建者的建议：把 Claude 当作思考伙伴，而不只是编码智能体。 

Bedirhan 最初的本能是自己托管语音引擎，但 Claude 建议使用云服务商来加快速度。“我最看重 Claude 的一点是，它不只是代码生成器，而是一个思考伙伴，帮我看到那些我原本会错过的选项，”他说。

第二名：Wrench Board，Alexis Chapellier

来自法国 Reignier-Ésery 的 Alexis Chapellier 从事电子产品维修多年，之后创建了 RepairMind——一个面向维修店的 AI 管理平台。他的 Opus 4.7 黑客马拉松项目 Wrench Board 帮助独立技师攻克复杂维修。用户放入一张电路原理图和一块板视图（boardview），描述故障症状，智能体就会构建统一的电气图谱，在上面进行推理，指出需要探测的准确焊盘，读取测量值，并不断更新假设，直到诊断出问题所在。

Alexis 在 Claude Design 中完成了 Wrench Board 的原型设计，把应用的职责拆分开（设计、原理图摄取、板视图、诊断智能体），先为每一部分产出规格说明，再产出实施计划。随后他在 Claude Code 的多智能体模式下执行，调试期间并行运行五六个智能体，每个领域配一个专属智能体，在每一步都进行基准测试。 

Alexis 押下的重注是 Opus 4.7 理解视觉原理图的新能力；他说，当自己让模型追踪一块主板上的供电通路时，他知道这个赌注赢了。

“我看着 Wrench Board 的板视图一步步亮起来，箭头出现，元件被指认，名称浮现。那一刻我明白，这个想法立住了，”他说。

Wrench Board 的下一阶段是建立一个电子维修社区：既有愿意试用这款应用的维修者，也有能用实战经验反哺工具的专家。他的 Claude 额度将投给 RepairMind、第一批用户，以及目前正在推进的所有基础设施。 

“这场黑客马拉松证明，一个从维修店里走出来的自学成才者，也能在五天里发布一套雄心勃勃的系统，”Alexis 说。参赛时他正在申请“过渡期生计工作”。他还说：“Claude Code 放大的是任何一个既有想法、又有执行毅力的人，无论起点在哪里。”

给其他构建者的建议：在头脑风暴阶段深入挖掘，并且敢于反驳模型。 

Alexis 使用 Superpowers——一个集成在 Claude 中的 skills 框架，它把“先头脑风暴、后制定计划”的步骤结构化，有时他会并行运行多个头脑风暴，在多条战线上同时推进。他从 Claude Design 起步，然后用内置按钮把项目直接移交给 Claude Code，并且在模型说“不行”的时候继续施压。 

“黑客马拉松期间，Claude 好几次告诉我说，这个或那个在有限的时间里做不完。但实际上，我的时间很充裕，”他说，“你得知道怎么对它说：我反正要试一试。”

第三名：Maieutic，Paula Vásquez-Henríquez 

Paula Vásquez-Henríquez 在智利康塞普西翁的 Universidad del Desarrollo 教授计算机科学。她说，过去两年，她看到越来越多学生考试通过了，却不理解自己写的代码。

“现在学生用 AI 量产代码，但他们完全不知道代码在做什么，”她说。“他们从没学会精确地陈述问题、在编码前草拟计划，也没学会批判性地阅读自己的代码、发现它在哪里偏离了本意。自动补全在他们还没把问题想完整之前就交付了能跑的代码，于是那个元认知循环——那种‘思考自己的思考’、真正造就程序员的过程——永远闭合不了。他们毕业时能生成代码，却无法对代码进行推理。” 

Paula 目前正在攻读人工智能方向的博士学位，研究学生与 AI 的交互模式。她参加这次黑客马拉松，是想同时从学生和教师两个视角解决这个问题。

Maieutic 是一款旨在让学生在关键时刻慢下来的 IDE。学生必须先用自然语言描述程序应该做什么，才能开始写代码；Claude 会提出有针对性的澄清问题，并且在规格说明足够详细——详细到合格的程序员无需猜测就能实现——之前，编辑器一直保持锁定。 

之后学生可以开始写 Python，但自动补全是关闭的；聊天面板会直接回答参考资料类问题，但对推理类问题则以反问回应而不是给出修改，拒绝替学生思考。 

作为工具核心的 Intent-Diff Review（意图差异审查）让 Claude 把规格说明与最终代码进行对比，将每一处分歧归类为漂移（drift）、修订（revision）或缺陷（bug），然后抛出一个中立、不带指责的提问，促使学生自己解释问题所在。 

对教师而言，一个实时仪表盘为每个学生显示一行认知状态的一句话总结（例如“规格说明写了三遍，仍未考虑空输入”）。 教师可以点击单个学生，查看其与 Claude 的具体交互；系统还会分析整个班级，识别并呈现全班共有的误解，方便教师弥合这些差距。

黑客马拉松结束后，休斯顿大学的研究者已经联系她商讨合作发表论文，Paula 也把奖金额度投入到工具的进一步开发中。她说，黑客马拉松那一周让她看到：从理解一个问题到为它发布一个工具之间的鸿沟，已经坍缩了。 

“我是智利康塞普西翁的教育者，不是硅谷的，”她说，“我在一周内发布了一个可用的全栈产品，因为这些工具让我能坚守在自己真正专长的角色里，其余的由它们来处理。离真实问题最近的人，如今可以直接为这些问题构建解决方案了。” 

给其他构建者的建议：构建之前先思考。 

这个项目正是 Paula 对自己哲学的亲身实践：构建之前先写规格。“Maieutic 的诞生，是因为学生们直接跳去写代码；而我之所以把它做好了，恰恰是因为拒绝让自己也这么做，”她说。她花了整整两天做纯思考工作，先写出设计规格和技术规格，然后才写下一行代码。 

“当时那两天写规格感觉很慢——黑客马拉松里‘立刻开始交付’的压力是真实存在的——但正是它们让这一周剩下的时间能够飞速推进，”她说。

Opus 4.7 最具创意奖：Virtual Puppet Theater，Rene Hangstrup Møller

全栈开发者 Rene Hangstrup Møller 被 Opus 4.7 的空间推理能力所吸引，构建了 Virtual Puppet Theater（虚拟木偶剧院）——一个基于浏览器的应用，把摄像头画面和语音变成一场动态的互动木偶戏。一个实时动画木偶镜像用户的动作，另一个 AI 驱动的伙伴木偶与用户插科打诨；语音指令还能即时变换场景、生成 3D 道具。

Rene 在完整流程中使用 Claude：概念讨论、规划和代码编写，而他本人负责导演、架构、审查和决策。应用基于 Bun、Vite 和 TypeScript，使用 MediaPipe 手部追踪（运行在 WASM 中）和 Three.js 以 60 fps 渲染 3D 木偶舞台。一个小型 WebSocket 服务器通过 Anthropic SDK 连接 Claude Opus 4.7，驱动 AI 木偶的对话并即时生成 3D 道具；语音输入由 Web Speech API 处理，输出使用 ElevenLabs（浏览器语音合成作为兜底）。Opus 的空间推理能力经过基于截图的反馈循环打磨，负责视觉输出。

Virtual Puppet Theater 除了开放式游玩之外没有任何目标，Rene 说他对这个获奖项目也没有产品化的打算。对他而言，这是为了学习和乐趣。“我让我最小的儿子试玩，他玩得不亦乐乎，”Rene 说。“看着他与木偶互动、描述场景、被回应逗得咯咯笑，这就是我需要的全部用户验证。” 

他还说，Virtual Puppet Theater 的源代码已在 GitHub 上以 MIT 许可证开源，“如果有人想把它继续发扬光大的话”。

给其他构建者的建议：如果你要参加黑客马拉松，请为录制演示视频留出时间。

‍“制作一段 3 分钟的视频，花的时间远超你的想象，”Rene 说。他最终是卡着黑客马拉松截止时间，用 Claude 和 Hyperframes 完成了 Virtual Puppet Theater 视频的剪辑制作。“黑客马拉松 Discord 里的很多人都提醒过这一点，他们说得对。下次，我会把最后那一整天专门留给演示视频的制作。”

“持续思考”奖：MaestrIA，Benjamin Torralbo

Benjamin Torralbo 从小跟随父亲 Juan Rodrigo Torralbo 学艺，他的父亲是智利奇洛埃岛（Chiloé）一位持有认证的 Maestro Mayor 级木匠。“我父亲有 30 年的手艺，修复过列入联合国教科文组织名录的教堂，但在智利的体系里依然是个隐形人，就像成千上万的其他手艺人一样，”Benjamin 说，“而另一边，需要修理房屋的普通人不知道哪里坏了、要花多少钱、该找谁、有没有被宰。”

他的 MaestrIA 黑客马拉松项目同时解决了这两端：作为一个 Web 应用，它既让普通人获得大师级的家庭维修诊断，也为手艺人提供了展示专业能力的途径。

使用 MaestrIA 时，用户拍下问题照片，用语音或文字描述，并分享位置。Claude 实时流式输出推理过程，在照片上叠加动态边界框，随后给出结构化的诊断：什么坏了、材质是什么、严重程度 1–5、项目预算和工期估算。接着，智能体会渲染一张按工种筛选的附近 maestro（师傅）地图，另一个智能体则起草一条待发送的 WhatsApp 消息。 

MaestrIA 的技术核心是一个 JSON 文件，被注入到每一次诊断中。它包含 17 条诊断规则、7 种奇洛埃本土木材、16 个本地行话词汇、19 项基准价格和 9 种这一行的常见失误，全部提炼自 Benjamin 对父亲数小时的访谈。在不改动系统提示词的情况下，仅这一个文件就让他的评测成绩提高了七个百分点（以一位人类大师的判断为准，从 74% 提升到 81%）。正是靠它，MaestrIA 才能诊断出“红柏木外墙的返潮”，而不是笼统的“木材损坏”。 

Benjamin 没有任何编程经验，他说自己的角色是工地监工，监督 Claude 的技术执行。“在写任何功能之前，我让 Claude Code 先设计规格、分阶段行动计划和安全模型：防提示词注入的输入过滤、速率限制、来源验证，以及作为唯一事实来源的 Zod schema，”他说，“然后我逐个 diff 审查每项功能。” 

Benjamin 希望 MaestrIA 能扩展到新建工程、五金店集成、正式报价、合同、评价和一套认证体系。最终，每个工种都会有自己的 Maestro Mayor 编码在内，包括木匠、建筑师、水暖工、电工和泥瓦匠。 

他的奖金额度将用于开发应用、把父亲的公司数字化为一个试点项目，以及他自己的技术成长。“Claude Code 让一个来自奇洛埃、毫无编程经验的 20 岁年轻人，构建出他自己的父亲都能用的软件，还能帮助智利另外 28 万像他父亲一样的 maestro，”他说，“它也为数百万一直有好想法却无从实现的人打开了大门。”

给其他构建者的建议：先做评测，再做功能。 

“我做的最重要的一件事，就是围绕 12 个真实案例构建了一套可审计的 9 维度评测，标准答案由我父亲记录，”Benjamin 说，“是那套评测，而不是我的直觉，告诉我什么行、什么不行。如果再参加一次黑客马拉松，评测会是我的第一次 commit。”

Claude Managed Agents 最佳应用奖：ARIA，Idriss Benguezzou & Adam Hnaien

大多数工厂都有那么一位老师傅，光凭机器的声音就能判断它快要坏了。获得 Claude Managed Agents 最佳应用奖的项目 ARIA（Adaptive Runtime Intelligence，自适应运行时智能）把一位资深维护工程师的直觉，变成了一套平价、部署快速、持续盯守工厂机器的 AI 系统，一旦出现故障迹象，立即生成定制的诊断和维修方案。

使用 ARIA 时，维护工程师上传一份厂商 PDF，回答四个通俗的校准问题，15 分钟内就能完成工厂画像。此后，五个智能体盯守实时信号。一旦某个智能体检测到故障或预判故障将至，它就会生成一份工单，分析部件、故障模式、紧急程度、所需零件和干预窗口。

这个项目的两位构建者都有工厂一线经验，他们在黑客马拉松的组队 Discord 频道里相识。Idriss Benguezzou 是一位法国工业软件工程师，拥有数据/AI 硕士学位，此前已经把这个想法和大部分架构酝酿了一段时间。Adam Hnaien 是一名自学成才的工科学生，熟悉 Claude Code 和多智能体工作流，他一眼就看出 ARIA 是工业维护领域一个有价值的解决方案。 

Idriss 和 Adam 把黑客马拉松的第二天全部花在规划上：用一块 GitHub Project 看板，在写下第一行代码之前就敲定了每个里程碑、每个 issue 和每条验收标准。“我们想从 M2 开始就火力全开，”Adam 说，“一天的规划，让我们这一周剩下的时间都在执行，而不是即兴发挥。”

两人估计，Claude Code 写了大约 80% 的原始代码行，而领域逻辑和设计决策则由他们亲手完成。Idriss 负责阈值判定、知识库 schema 和异常检测，因为“提示词没法替你知道一名维护技师真正看的是什么”。Adam 则负责 UX、视觉语言和 ARIA 的“星座”概念，因为“品味是提示不出来的”。 

智能体基础设施则交给了 Managed Agents。“如果没有 Claude Managed Agents，我们那一周就得去搭建 Anthropic 已经托管好的基础设施：沙箱化的 Python 环境、安全执行、会话持久化、MCP 调度，”Adam 说，“而我们把那一周花在了围绕这套基础设施构建产品上。这就是五天发布 ARIA 和五周发布 ARIA 的区别。” 

黑客马拉松结果公布后，正好在解决这类问题的公司主动联系了他们。Idriss 将把 ARIA 的智能体架构、知识库 schema 和信号管线整合进他自己的工业物联网平台，他的额度将用于更多的构建和实验。至于 Adam，他计划继续探索工业智能体 AI 领域的机会，并用 API 额度持续构建和实验。

给其他构建者的建议：让 Claude 来审计。在构建下一个东西之前，先让 Claude 检查你已经构建的东西有没有问题，Idriss 说。“这个循环被低估了。”
