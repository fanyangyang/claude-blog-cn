Claude 模型详解：如何为你的场景选择最合适的模型

阅读英文原文 →

我们的建议：聪明地起步

我们最常听到的问题之一是"这个工作负载该选哪个模型？"随着我们发布了越来越多的模型级别和版本，答案也变得更细致了。

本文会讲清楚这些细节，包括每个模型级别的介绍、选模型时最该问的问题，以及其他最佳实践。

不过先暂时放下这些细节：我们的默认建议是，从当前最强的一般可用（GA）模型起步，再用 effort 等级去调节性能和成本。 

更智能的模型单次任务成本（cost-per-task）往往更低，尤其在较低的 effort 等级下，即便其单价（price-per-token）更高。这是因为更强的模型通常用更少的轮次和更短的思考时间就能把大多数任务做对。从小模型起步还有一个问题：模型能力不行还是配置出了问题，会变得更难区分。 

当然，如果使用场景对延迟或成本更敏感，你可以逐步测试更低级别的模型，直到找到最合适的组合。 

也有一些组织会选择从性价比最高的模型起步，逐级向上换，直到满足质量要求。我们的模型选择文档中同时收录了这两种思路。

Claude 模型家族

Claude 模型家族是 Anthropic 的 AI 模型阵容——Fable、Opus、Sonnet 和 Haiku——每一级都在智能、速度和成本之间有不同的取舍。选得对，就是让模型匹配任务。

Mythos / Fable

Mythos 是 Anthropic 最强的模型级别，在各领域都具备前沿能力。这一级别的模型尤其擅长编程、长时间运行的智能体任务，以及解决 AI 之前还无法可靠处理的问题。 

Mythos 级别以同一底层模型的两种封装形式发布。Claude Mythos 面向处理两用性网络安全和生物学工作的受信任组织；Claude Fable 则封装了额外的安全防护，可安全供大众使用。两者都要求有限数据保留（limited data retention）才能安全使用。

Opus

Opus 是我们面向高推理强度企业任务的强力模型级别。Opus 模型在关键行业基准上稳居领先行列，例如衡量知识工作的 GDPval-AA 和衡量智能体编程的 Terminal-Bench 2.1。

Opus 和 Fable 之间的选择从表面上看可能不太分明，因为两者都擅长编程、长时间运行的智能体任务和知识工作。但在实际场景中，Fable 这类更大的模型往往拥有更多的智慧、创造力和写作功底，尽管其基准分数与 Opus 等模型相近。

一个大致的经验法则：如果你的评估或内部测试显示 Opus 在某些任务上吃力，那就用 Fable。如果 Opus 已经能达到质量标准，那么它在速度和价格上的优势可能使它成为更好的选择。

Sonnet

Sonnet 是我们面向日常任务的多面手模型级别。Sonnet 在性能、成本和速度之间取得了平衡，适用于最广泛的一般性场景，包括多智能体编排中高并发的子智能体（sub-agent）。 

Haiku

Haiku 是我们成本最低、速度最快的模型级别。Haiku 模型专为延迟和成本敏感的高频工作负载而设计。

如何为你的工作负载选择最合适的 Claude 模型

我们的模型级别并不专攻某一类工作。我们不会推荐一个模型级别做金融、另一个做科研。每一个 Claude 模型都在编程、智能体任务、知识工作等方面训练到位。 

各模型级别的主要区别，在于它们能可靠完成多么困难的问题，以及这种能力在价格和速度上的代价。选择模型时，请问自己：

这个任务有多难？如果它通常很耗时、涉及多个步骤，或是此前没人解决过的问题，那么更强的模型级别是合适的选择。

延迟要求如何？如果模型用于高频、面向客户的工作负载，Sonnet 往往是最佳选择。 

访问限制是什么？Mythos 仅向 Project Glasswing 下的组织开放。而且并非所有组织都会向所有角色开放全部模型级别。 

单位经济模型如何？生产环境的高调用量可能更适合低级别模型，尤其是当评估显示这些任务能被令人满意地完成时。各模型的每 token 定价不同，其单次任务成本也会因能力和 effort 等级而异。

effort 等级同样会影响质量、速度与成本的平衡。高级别模型配高 effort 提供最佳性能，而高级别模型配低 effort 有时比小模型更高效。

用 advisor 策略组合各模型的长处

advisor 策略允许更快、更便宜的执行模型去调用更智能的模型来检查其计划、评估其工作，从而提升整体表现。

这种只在需要时让执行模型获得指导的方法，能带来大幅的性能提升。例如，在 SWE-bench Pro 上，配备 Fable 5 顾问的 Sonnet 5 能达到 Fable 5 分数的 10% 以内，而价格只有全程使用 Fable 5 的 63%。

评估和基准测试如何帮助选型

判断模型能力是否满足需求，常见方法有两种：使用标准基准测试，以及自定义评估（evals）。 

基准测试是一组预先确定的、通常针对特定领域的任务或场景，带有已知答案。它们可以作为跨模型级别、跨厂商评估能力的方向性参考。但评估 Opus 和 Fable 这类强大模型时会遇到难题：它们几乎能解出测试中的所有问题（通常称为"饱和"）。

在这些情况下，我们建议组织用真实工作负载试用模型，或用自建的评估来测试，再决定哪个模型是正确选择。通常，评估是一组从生产环境中提炼出的精选问题——包括现有工具搞不定的困难任务——并附带由你的团队定义的成功标准。

前沿模型的能力和创造力正是在这里开始与群雄拉开差距、并彼此分出高下。我们已就构建自定义智能体评估的最佳实践写过大量文章。

做出聪明的选择

AI 模型选型没有放之四海而皆准的方案，这正是我们提供多个模型级别的原因。归根结底，选模型的最佳方式是理解每个模型级别的基本特性，并深入理解你自己的使用场景。这意味着要构建、维护和部署高质量的评估。
