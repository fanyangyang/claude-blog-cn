循环（Loop）入门

眼下关于循环工程（loop engineering）或"设计循环"而非给编码 agent 写提示词的讨论很多。如果你在 X 上花些时间想弄清楚循环到底是什么，会找到好几种不同的答案。

在 Claude Code 团队，我们把循环定义为 agent 反复执行工作周期，直到满足停止条件。我们基于以下几点把循环分为几种类型：

  • 如何触发
  • 如何停止
  • 使用哪种 Claude Code 原语
  • 每类循环最适合什么类型的任务。

我们将介绍主要的循环类型、各自的适用场景，以及如何在控制 token 用量的同时保持代码质量。并非所有任务都需要复杂的循环；从最简单的方案开始，再有选择地使用这些模式。

回合制循环

  • 触发方式：用户提示词。
  • 停止条件：Claude 判断任务已完成，或需要更多上下文。
  • 最适合：较短、不属于固定流程或日程的任务。
  • 控制用量：写更具体的提示词，并用 skills 加强验证，减少回合数。‍

你发出的每条提示词都会开启一个手动循环，每一回合都由你来指挥。Claude 收集上下文、采取行动、检查工作，必要时再重复，然后给出回复。我们把这叫做 agentic loop。

例如，让 Claude 做一个点赞按钮。它会读你的代码、改一处、跑测试，再交出它认为能用的结果。然后你手动检查，再写下一条提示词。

你可以把手工检查步骤写进 SKILL.md，让 Claude 自己把更多工作从头到尾验完，从而改进验证这一步。（要在 skills、hooks 和 subagents 之间做选择，见我们的 steering Claude Code 指南。）

这里应包含能让 Claude 看见、度量或交互结果的工具或 connectors。检查越定量，Claude 就越容易自验。

例如，在 SKILL.md 里你可以写：

--- 
name: verify-frontend-change 
description: Verify any UI change end-to-end before declaring it done. 
--- 

# Verifying frontend changes 
Never report a UI change as complete based on a successful edit alone. Verify it the way a human reviewer would: 

1. Start the dev server and open the edited page in the browser. 

2. Interact with the change directly. For a new control (button, input, toggle): click it, confirm the expected state change, and screenshot before/after. 

3. Check the browser console: zero new errors or warnings. 

4. Use the Chrome Devtools MCP, run a performance trace and audit Core Web Vitals.

If any step fails, fix the issue and rerun from step 1 — do not hand back partially verified work.

目标制循环（/goal）

  • 触发方式：实时发出的手动提示词。
  • 停止条件：目标达成，或达到最大回合数。
  • 最适合：有可验证退出条件的任务。
  • 控制用量：设定具体的完成标准，并明确回合上限，例如 "stop after 5 tries."

有时一个回合不够，尤其是更复杂的任务。Agent 能迭代时表现更好。用 /goal 定义怎样算完成，就能延长 Claude 继续迭代的时间。

你定义了成功标准之后，Claude 就不必自己判断什么叫"够好"然后提前结束循环。每次 Claude 想停下来，评估模型都会核对你的条件，再把它送回去继续干，直到目标达成，或达到你设定的回合数。

这就是为什么确定性标准特别有效，比如通过的测试数量，或清掉某个分数门槛。

例如：

/goal get the homepage Lighthouse score to 90 or above, stop after 5 tries.

时间制循环（/loop 和 /schedule）

  • 触发方式：指定的时间间隔。
  • 停止条件：你取消它，或工作完成（PR 合并、队列清空）。
  • 最适合：周期性工作，或对接外部环境 / 系统。
  • 控制用量：拉长间隔，或按事件而不是按时间来响应。

有些智能体工作是周期性的：任务本身不变，变的只是输入。比如每天早上汇总 Slack 消息。另一些工作依赖外部系统，对接的简单办法是按间隔检查，再对变化做出反应。比如一条可能收到 code review 或 CI 失败的 PR。

对这类情况，可以用 `/loop` 按间隔重跑一条提示词来触发 Claude。例如：

/loop 5m check my PR, address review comments, and fix failing CI

`/loop` 跑在你的电脑上，关机它就停。用 `/schedule` 建一条 routine，可以把循环挪到云上。

主动式循环

  • 触发方式：事件或日程，实时没有人在场。
  • 停止条件：每个任务在目标达成时退出。routine 本身一直跑到你关掉为止。
  • 最适合：定义清楚的周期性工作流：bug 报告、issue 分诊、迁移、依赖升级等。
  • 控制用量：把 routine 路由到更小、更快的模型，把最强的模型留给需要判断的环节。

上面这些原语，再加上 Claude Code 的其他能力，比如 auto mode 和 dynamic workflows （research preview），可以组合成面向长时间工作的循环。

例如，处理进来的反馈时，你可以用：

  1. `/schedule` （research preview）跑一条 routine，检查有没有新报告
  2. `/goal` 定义怎样算完成，并用 skills 记下如何验证
  3. Dynamic workflows 编排多个 agent，分别做分诊、修复和评审修复
  4. Auto mode 让 routine 跑下去，不必停下来问权限

拼起来，一条提示词可以长这样：

/schedule every hour: check #project-feedback for bug reports. /goal: don't stop until every report found this run is triaged, actioned, and responded to. When fixing a bug, use a workflow to explore three solutions in parallel worktrees and have a judge adversarially review them.

保持代码质量

循环产出的质量取决于它周围的系统。设计系统时：

  • 先把代码库本身保持干净：Claude 会跟随代码库里已有的模式和约定。
  • 给 Claude 一种自验工作的方式：用 skills 把对你和团队来说怎样算好写下来。
  • 让文档容易够到：框架和库的文档里有最新的最佳实践。
  • 用第二个 agent 做 code review：带着全新上下文的评审者偏见更少，也不受主 agent 推理的影响。你可以用内置的 `/code-review` skill，或 GitHub 上的 Code Review。写代码的循环需要检查代码的循环，见 how Anthropic secures an AI-native SDLC。

当某一次结果没达到标准时，不要只修这一处，试着把它写进系统，让以后每一轮迭代都更好。

管理 token 用量

要管理 token 用量，循环应有清楚的边界：

  • 为任务选对原语和模型：更小的任务不需要多个 agent 或循环。有些任务可以用更便宜、更快的模型。
  • 定义清楚的成功和停止条件：具体写出怎样算完成，让 Claude 更快到达解（但不要太快）。
  • 大规模跑之前先试点：Dynamic workflows 可以拉起上百个 agent。先在一小片工作上估用量。
  • 确定性工作用脚本：跑脚本比一步步推理更便宜。例如，一个 PDF skill 可以自带填表脚本，Claude 每次直接跑，而不用重新推导代码。
  • 不要比需要的更频繁地跑 routine：让间隔匹配你在盯的东西变化的频率
  • 查看用量：`/usage` 命令按 skills、subagents 和 MCP 拆开近期用量，不带参数的 `/goal` 显示目前的回合数和 token 用量，`/workflows` 显示每个 agent 的 token 用量，你可以随时停掉一个 agent。

你的 model and effort level 选择，是循环成本最大的杠杆之一。

开始使用

总结一下：

要开始用循环，先看你已经在做的工作。挑一项你自己是瓶颈的任务，问哪一块可以交出去：你能写出验证检查吗？目标够清楚吗？工作是按日程到来的吗？

有了想法就跑循环，观察结果，看它卡在哪里或越界到哪里，然后放心去迭代它。

更多信息见 Claude Code 文档中的 running agents in parallel, 以及 loop、schedule、goal 和 dynamic workflows 页面。要让检查跨会话可复用，见 building verification loops in Claude Code with skills。
