Outtake 如何在 Claude 上构建网络犯罪调查员

在我们的系列文章 《创业公司如何用 Claude 构建》（How startups build with Claude）中，我们聚焦创业公司如何用 AI 变革所在行业。本文将分享 Outtake 如何构建一个自主网络犯罪调查员，它能检测、调查并瓦解数字威胁——从克隆的登录页面到整张对抗性网络。

即便有强大的防护措施和管控手段，不法分子仍可以把 AI 伪装成看似无害的用途，借以掩盖恶意意图。代码生成平台可以炮制出以假乱真的登录门户，智能体化的营销工具可以为钓鱼攻击的分发提供动力，图像生成能力则可以伪造身份。传统网络安全防御已经难以招架。

"如果你戴上坏人的帽子想一想，现在其实是发动攻击的大好时机，"AI 网络安全平台 Outtake 的创始人兼 CEO Alex Dhillon 说，"有了 AI，平均而言攻击不仅执行得更快，而且能攫取更深层的访问权限。"

Outtake 将完整的数字信任攻击链统一到单一防御体系之下，利用成群的 AI 智能体自主检测、调查并瓦解针对客户的威胁——其客户包括领先的 AI 实验室、大型对冲基金和美国联邦机构。 

下面是 Outtake 团队近期基于 Claude，使用 Claude Code 和 Agent SDK 构建 Recon Agent（侦察智能体）——一个可长时间运行的自主网络调查员——的过程。

智能体化的攻击需要智能体化的防御

攻击者在攻击一家公司时，通常遵循相同的流程：武器化公开数据 → 搭建仿冒诱饵 → 渗透内部系统。这一流程已被 AI 大幅加速。

在攻破任何系统之前，他们会搜集组织及其高管、员工的公开信息。

然后把这些情报变成诱饵，比如一个带欺诈性登录页面的假网站，诱骗受害者交出凭证。通过这些诱饵获得的访问权限，帮助攻击者突破边界防线，触达组织最有价值、最敏感的资产。

 
这个三段式流程是可预测的，但传统安全工具每次只守住其中一段：

  • 威胁情报工具监控公开数据阶段，
  • 品牌保护工具盯防仿冒行为，
  • 端点工具守卫内部系统。 

Outtake 的 Recon Agent 调查的是仿冒事件背后的整张网络。举例来说，它不只是下线一个克隆的登录页面，而是从仿冒事件中收集并归类证据。 

它顺着这些线索追查关联基础设施——比如一个自称"客服"的假 Telegram 账号——并用图谱把这张对抗性网络绘制出来。最后一步，智能体产出一份报告，解释调查过程、威胁行为者的画像，以及重建出的攻击者行为时间线。 

为了执行这套复杂的工作流，Recon Agent 能够读、写并运行代码。它甚至可以直接与恶意登录页面交互，看看窃取来的凭证最终流向了哪里。 

这类调查可能要求智能体长时间自主运行。智能体会话的中位时长为 16 分钟，但经常延长到一小时以上；迄今为止最长的一次，是在持续两个小时的智能体工作后才返回结果。

Outtake 如何用 Claude 构建复杂的长时间运行智能体

Outtake 大约分四个阶段构建了 Recon Agent。每个阶段都是先弄清一次好的调查长什么样，再逐步把这种判断交给智能体。

第一步：先成为专家。

在构建智能体的任何部分之前，Outtake 的工程师自己先跑真实的网络调查，并向客户和设计伙伴抽取领域专长。 

目标是定义"好"长什么样。对这类调查来说，这意味着弄清哪些证据重要、如何组织它们，以及可执行的结论与猜测之间差在哪里。这个标准成了他们在后续每个阶段都会回头对照的固定参照点。 

"构建长时间运行智能体最重要的一点是，你必须真正理解好长什么样？ 智能体应该在做什么？"Outtake 智能体平台工程负责人 Jack Hayford 说，"因为归根结底，你要确保智能体每一次都能做到这一点。"

第二步：在 Claude Code 中做原型

起初，Outtake 团队用传统智能体框架，逐步自动化他们正在标准化的调查。 

他们很快意识到，Recon Agent 不能只是一个简单的调查员。它需要能写代码、跑代码、当场造工具，并且真正与恶意域名交互。 

"每一次调查都不同，而且技术很深，"Hayford 说。"智能体需要编码肌肉和能力，Claude Code 是一个很强的初始 harness，让我们验证这些假设，并越做越多实验。"
正是在 Claude Code 里做原型的过程中，他们锤炼出核心设计原则：在编排层把智能体约束得很紧（「调查一个域名时总是做 X、Y、Z」），但凡需要判断的地方，就留给它自由发挥。

第三步：升级到生产级 harness

"我们很喜欢 Claude Code 引入的那些模式，但我们需要额外访问更底层的原语，而这些东西我们并不打算自己造，"Hayford 说。

用 Claude Agent SDK 把 Recon Agent 带进生产环境，是自然的下一步。把 skills 和模式从 Claude Code 带过来，确保团队在获得对 Recon Agent 记忆、上下文和文件系统更紧控制的同时，不会掉速度，也不必在智能体循环和会话处理上重新发明轮子。

第四步：用 evals 驱动紧密的迭代循环。 

在网络安全里，能便宜、迅速地迭代尤为关键，因为攻击者一旦得知防御工具存在，就会立刻调整。团队从一开始就接入了智能体 evals，并做出一套能同时跑许多场景的强 eval 套件。这让他们能安全、有把握地做大改动，比如模型升级和整套记忆系统重构。 

这也让团队把自己从智能体循环里抽了出来。例如，当 Recon Agent 完成一次调查并回报说，如果当时有某个它没有的工具会做得更好，另一个编码智能体就会读这些建议、写出新工具，并建一个测试场景来试。 

直到最后，人才介入看结果：有了那个工具，智能体的调查是更好了，还是没有？"我们才是瓶颈，当你构建这些又长又复杂的智能体时，反馈循环必须自动化，这一点非常重要。它快得多，作为开发者也更有成就感，"Hayford 说。

构建长时间运行智能体的心得

在智能体的早期，构建者会用硬编码、确定性、一步一步的路径预先写好智能体行为，以免它脱轨。如今，繁复的工作流正在被 harness 取代：一个由记忆、工具、skills 和护栏组成的支撑环境。

以下是 Outtake 团队在落地 Recon Agent 构建过程中的一些收获。

工具：一个文件系统和 bash 就够了

文件系统让记忆能在压缩之后仍然存活。智能体通常会被配上非常具体、精细的工具，但给它一个文件系统，再加上写、读和跑代码的能力，能帮它应对障碍。 

"把这些极其强大、开放式的工具和能力交给智能体，是一次巨大的跃迁。我们观察到不少情况：某个工具因为网络抖动之类的原因失败了，智能体就会找到合适的变通办法继续往下走，"Hayford 说。"因为我们构建的其余 harness 足够强，也因为它用这些强大、开放式的工具给了智能体即兴发挥的空间，它仍然能走到成功的结果。"

提示词是建议

提示词在需要时提供灵活性，但能硬编码的地方就硬编码，以保证稳定。"当你构建这些会随时间变复杂的长时间运行智能体时，提示词就是建议，"Hayford 说。"当智能体没有按你想的做，人的自然反应是去改智能体里最可塑性的那一块。往系统提示词里塞一句『当 X 发生时，务必做 Y』一开始也许管用，但随着这个智能体跑得更久，那条提示词里的每一个字最终都可能被忽略。"
正确的做法是围绕这种可能性来构建：找出智能体每一次都应该做的事，把它做成智能体护栏。"把这些东西从提示词里抽出来，放进 harness，"他说。"现在智能体不用再想这件事了，它有更多上下文空间和注意力，可以放在真正能发挥的地方。" 

进一步阅读 引导 Claude 的最佳实践，以及每种方法的上下文成本和权威性。 

Evals 是为了速度，不只是可靠性

把人工"复盘"当作路线图，走向能收紧开发周期的自动化 evals。 常规看法是，evals 是可靠性的质量门槛。但对长时间运行的智能体来说，更大的回报是速度。 

早期，每次 Recon Agent 跑完，团队都会人工复盘它的表现。但读一份智能体 30 分钟里做的每一件事的逐字稿，既折磨人，也无法规模化。 

"在现代智能体开发中，评估输出是循环里最贵的一步，"Jack 说。 

Eval 不过是那种复盘的结构化、可打分、可自动化版本。一旦你把"好"长什么样编成可重复的检查，就可以让一个智能体坐上裁判席，去读那份 30 分钟逐字稿并给这次运行打分。

"我觉得有些工程师对构建 evals 有顾虑，因为它听起来像是要造一个完美用例，"Jack 说。"从一开始就构建某种版本的 evals，会让你把那个智能体造得更快，无论它们有多正式或『完美』。"

保护你的智能体

提示词注入是真实威胁，所以把智能体放进沙箱或给它装甲至关重要。Outtake 团队选择 Claude，部分原因就是它对抗提示词注入的强度。 

"安全是我们构建 Recon Agent 的一大要点，"Hayford 说。"我们给了它文件系统和 bash，又把它送进对抗环境，所以必须解决的最重要问题，是造出一种 blastbox：既能把智能体和敏感内部隔开，又不真正妨碍它。" 

他们的做法假定智能体可能被劫持，于是周围的系统被设计成能把损害关住。不过，安全因智能体而异，取决于它们的用途，并非所有智能体都适合做 blastbox 候选。 

Outtake 现在正在智能体伸向互联网的精确位置给信任打分，实现一个检查点，评估智能体即将触达的东西：『这个页面是仿冒吗？是恶意软件吗？它现在是不是在试图对智能体做提示词注入？』随着智能体穿越越来越对抗的互联网，这也许正是它们需要的装甲。
