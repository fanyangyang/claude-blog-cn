在前沿工作的 AI 原生者

想窥见工作的未来，就去看看今天的创业公司在怎么运转。于是我们这么做了。

我们与十几家高速成长的创业公司交流，了解他们如何使用 agentic coding 工具来构建产品、扩张公司。这些创业公司正在改写规则：谁可以参与构建、什么该被淘汰，以及如何在“怎么构建”与“构建什么”之间打造飞轮。

而他们的发布节奏，像极了规模十倍于自己的组织。

ClickHouse30%多发布的功能
Omni2–3x工程生产力
Clay100%bug 分诊自动化
Artemis Security6,000+每周 PR 数

在这份指南中，我们将深入这些组织的独特实践，学习他们赖以快速发布并保持竞争优势的法则。

在这个过程中，我们也将逐渐看清一个问题的答案：如果一家组织从零开始、以 Claude Code 为基础构建整个产品开发生命周期，会是什么样子？

五条法则

  1. 人人皆可发布
  2. 自动化繁琐之事
  3. 信任，但要验证
  4. 为重构而构建
  5. 原型、内部试用、产品化

01

人人皆可发布

Agentic coding 降低了参与门槛，让最理解问题的人可以直接发布修复的第一版。

Agentic coding 降低了非技术员工构建产品的门槛。有了 Claude Code，即使不精通编程语言、不会用 IDE，也能创建可用的功能。

“不仅工程师的产出多了很多，非技术的人（比如我）也开始突然发布 UI 改动和其他产品改进。”Mads Lunau Liechti · 联合创始人，Parahelp

对创业公司创始人来说，这好处显而易见。其一，他们没有大竞争对手那样的人手，必须“全员上阵”。但创始人看中的不只是产能——这些团队里的非技术成员还带来了领域专长。

“Claude Code 改变了在 Crosby 当律师的意义。律师们有最好的产品洞察，因为他们就是用户。看他们大展身手真是太棒了。”Ryan Daniels · 联合创始人兼 CEO，Crosby

Heidi 的联合创始人兼 CEO Thomas Kelly 医生也表达了同样的看法。

“对我们来说，Claude Code 解决了‘传话走样’的问题。过去一个新想法在团队里的流转路径是：有想法的人告诉 PM，PM 告诉设计师，设计师再告诉工程师……想法的精髓不可避免地在链条中流失。等东西发布出来，往往已经不是提出者脑中的样子，而且一耗就是几周。Claude Code 把这条链条压缩了。真正理解问题的人可以直接提 PR，在设计者和工程师的专业最关键的部分把他们拉进来。”Dr. Thomas Kelly · 联合创始人兼 CEO，Heidi

说“人人皆可发布”发个 LinkedIn 很漂亮，但实际怎么运作？市场团队在审批 pull request 吗？法务团队在钻研不稳定测试的二分定位吗？

我们得到的答案是：分工依然存在。市场人员仍专注市场，开发者仍专注开发。但那个至关重要的第一步——把一个想法变成可运行的原型、从 0 到 1——对所有人开放。

我们还看到，最有效的创业公司会建立机制，让这类贡献成为体系化的常态，而不是听凭运气或个人雄心。

建立连接

期望员工使用 AI 是一回事，让他们用上 Claude Code 和所需工具是另一回事。

“我们其实没有回避（非技术员工做贡献），而是主动拥抱。我们的判断是，每一种角色都在变成某种意义上的工程角色，因为你完全可以为它构建软件……所以我们招的是喜欢动手折腾、对构建有兴趣的人。”Kareem Amin · 联合创始人兼 CEO，Clay

在 Crosby，团队不是把律师带到 Claude Code 面前，而是把 Claude Code 带到律师面前——把它接到律师熟悉、每天使用的工具和操作系统上。

提示：Claude 无法理解它看不到的东西。扩展 Claude 价值最有效的方式之一，就是把它连接到事实来源（source of truth）和团队每天使用的工具上。
MCP 是一个开源的 AI 工具集成标准，让 Claude Code 能访问你的工具、数据库和 API。每当团队发现自己在把某个工具里的信息复制粘贴给 Claude 时，就值得考虑加上这类连接。
当已有成熟的命令行工具（gh、kubectl、bq、psql）且你希望 Claude 与工程师面对同一份事实依据时，通过 CLI 连接往往更省 token。

站会展示

想法终归需要被给予进入优先级排序的机会，组织资源才能帮它走向市场。对产品经理来说这条路很清晰——那本来就是他们的工作——但对非技术员工就没那么清晰了。

Clay 设立季度评审，原型在那里被讨论，有机会进入正式路线图。Clay 的一位市场团队成员就是这样构建了一个自主 agent：它会访问你的网站、填写你的线索收集表单、测算响应耗时、给体验打分，并生成一份性能报告。

Omni 有一个专门的 Slack 频道展示 Claude 生成的原型，贡献者包括资深技术人员在内的所有人。他们还践行着“人人皆可发布”的对偶命题——“人人都要见客户”。

尽管工程师天然不会主动亲近客户电话，Omni 依然刻意安排他们直面客户，因为这能更快闭合反馈环。Chris Merrick · 联合创始人兼 CTO，Omni

共享 skills

“人人皆可发布”与“东拼西凑”之间的界线可能很薄。功能原型无论出自谁手，最终都要整合进一个浑然一体的产品。这正是 skills 的用武之地——这些可复用的指令文件沉淀了团队的标准与上下文，能在流程日益民主化的同时确保开发不跑偏。

“团队里任何人都可以参照我们的设计系统，用 Claude Code 起草产品组件、营销物料或演示材料。会触碰产品的 AI 必须达到高得多的标准，而 Claude Code 帮我们更精准地达到它。”Heidi 的 Thomas Kelly 医生说。

它们还能让新开发者和非技术员工快速上手、迅速跑起来。

“……我们还有一个 Claude Code skills 的 GitHub 仓库，作为共享知识库，能快速引导一个 Claude Code 会话掌握 Emergent 的既有信息，比如数据库（和数据仓库）位置、一些 schema（信息）、整体公司背景……与其在这里追求完美，不如接受上下文文件略有滞后——只要 agent 能快速验证并自我纠正就好。”Mukund Jha · 联合创始人兼 CEO，Emergent
“我们的工程师用 Claude Code 搭建了一个内部专属 agent 市场，按角色组织——工程、交付、销售各自都能拿到为自己真实工作方式量身定制的工具。”Jack O'Hara · 创始人兼 CEO，Translucent

提示：Skills 可以通过目录（directory）在全公司共享，一个人的最佳实践就能即时传递给另一个人。在仓库的每个子目录放置 CLAUDE.md 文件，用于该子目录专属、每次都生效的编码约定。Skills 则用于按需触发的流程性工作流。更多信息请阅读：Steering Claude Code: when to use CLAUDE.md, skills, hooks, and subagents。

02

自动化繁琐之事

由 agent 负责生命周期中机械的 80%，工程师把时间花在真正需要判断力的场景上。

自工业革命以来，所有公司都在寻求通过技术提效，但这些创业公司的与众不同之处在于采纳的速度和深度。

这些创始人相信 AI 是其使命中不可或缺的部分。许多人明确表示：机械的 80% 由 agent 负责，工程师把时间花在真正需要判断力的场景上。

“所有人都在抢着做 AI 产品，但很少有人在重构公司实际的运转方式。后者才是更大的破局点。Artemis Security 是一家 AI 原生公司在运营，而不是一家碰巧用了 AI 的公司。这极大提升了我们的速度，让我们能帮助客户以机器速度拦截攻击。”Shachar Hirshberg · 联合创始人兼 CEO，Artemis Security

具体而言，我们看到他们比其他公司更深度地把 AI 融入 SDLC 各阶段，也构建了更多专门设计的 agent 来端到端承接周期性任务。来看两类例子。

AI 原生的 SDLC

这些受访创业公司中的许多都建立了机制，加速团队进入 agentic coding 流程的磨合。例如在 Emergent，Mukund 告诉我们：“入职第一天，新员工只需让 Claude 读对的 markdown 文件，就能引导搭建整套开发环境。如果 Claude 在入职过程中发现任何损坏或过时的内容，它会顺手更新那个文件。”

提示：Code Review（research preview）是 Claude Code 中托管的 多 agent 服务。它会对你在启用仓库中的 PR 自动执行评审。你可以手动修复发现并推送，也可以（在配置好 GitHub Actions 后）在发现处评论 @Claude 来闭环。

这些工程师必须快速上手，因为这些团队发布得飞快。

“这里的工程师在调度 agent 舰队，生产数据问题发现的当天就把修复发上线，同时推进多个 PR。有位工程师用一个约 13 张工单的项目让 Claude subagent 并行跑，每个负责一张工单和它的 PR。”Tanay Tandon · CEO 兼创始人，Commure

在这些组织里，Claude Code 不仅帮忙写代码，也负责评审代码。“我们按既定的技术与合规框架跑自动化代码评审，标记关键问题，并在任何东西发布前把建议的改动路由给对应的评审人。”Heidi 的 Kelly 医生说。

其中一些组织还针对代码评审、测试和 CI 构建了自定义 agent。这些创业公司在构建循环（loop）而非仅仅部署代码上倾注了大量心力。

“我最喜欢的是‘Translucent 代码评审员’，它会围绕一次改动展开多路分析、从多个角度评审，然后像我们某位资深工程师那样综合结论——但比任何个人都快。”Translucent 创始人 Jack 说。

Clay “……构建了一个处理 bug 分诊的 agent，从第一遍筛选到给出修复的代码改动建议。”Kareem 说。

提示：过去几个月，Claude Tag 一直是 Anthropic 内部 CI/CD 故障值班的第一响应人。在近期每一次有情况报告的事故中，第一份情况报告都出自 Claude 之手，通常在 15 分钟内就发布首轮分析。
Claude Tag 拥有自己的服务账号，以及 Anthropic CI 工程师所需的 Datadog、Grafana 等工具的访问权限。常备指令以 markdown 文件的 skills 形式提交在 GitHub 仓库里。这样多个队友可以协作迭代，变更管理也和代码一样。

‍

这一点在 ClickHouse 体现得最为极致。联合创始人兼 CTO Alexey Milovidov 介绍说，这家数据库公司几乎把每个 SDLC 阶段都变成了自主循环。两个分别用于修复不稳定测试和补齐缺失测试覆盖的专用 agent，如今是 ClickHouse 仓库贡献榜的第 2 和第 3 名。另一族 agent 负责运维，而团队正是用 Claude Code 来构建和迭代这些 agent 本身。

用 agent 加速流程

另一个一致的模式是：这些创业公司不仅在开发工作中用 Claude Code 里的 agent 循环提速，还在创建 agent 来加速那些重复且往往枯燥的流程。

被加速的常是例行工作，好让团队把更多注意力放在竞争优势、客户关系和营收增长上。我们看到的被 Claude 加速的最常见流程之一，是自助式数据分析。

这些公司几乎每一家都有某种机制，能用新鲜数据（包括非结构化数据）快速决策——支撑创业公司生命中至关重要的方向调整。

例如，Clay 构建了内部数据分析 agent；Heidi 用 Claude Code 把客户和临床医生的反馈与使用数据归类，浮出对产品洞察重要的信号。

ClickHouse 和 Omni 发布的产品则把这类 AI 数据分析直接打包其中，全部由 Claude 驱动。

其他例子还有：用 subagent 摘要数千份法律文件（Crosby）、扫描理赔数据标记跨站点异常（Commure）、持续挖掘医院财务数据寻找任何分析师团队都来不及发现的预警信号（Translucent）。

提示：Dynamic workflows 可以让多个 subagent 并行分析海量数据，或对另一个 agent 的工作做对抗性评审。使用 Claude Opus 或 Claude Fable 这类模型时，直接说“展开多个 subagent”或“用一个 workflow”即可。

03

信任，但要验证

除非有可靠的手段来监控和验证结果，否则谈不上自动化。

这条法则是法则二“自动化繁琐之事”的必要推论：除非有可靠的手段监控和验证结果，否则谈不上自动化一个流程。

Artemis Security 联合创始人 Dan Shiebler 说，他们之所以能提部署速度，正是因为“我们在测试基础设施、代码库组织和团队知识体系上做了深度投入，agent 才能端到端交付。这就是我们与 Claude 一起打造的飞轮：用正确的方式组织你的代码库、知识库和团队，每一次贡献都会复利叠加。”Dan Shiebler · 联合创始人，Artemis Security
“起初我们给了 Claude 完全自主权，然后它干了 AI 常干的事：飞快交付看起来合理的代码。问题在于它以看似正确、实则错误的方式偏离了我们的架构。于是我们……把每一条不变量都写了下来。我们怎么界定问题。无论如何都必须成立的条件是什么。如何证明一个东西真的有效，而不是相信一个自信的回答。整整 567 行，写满这支团队的思考方式。”Victor Hunt · 联合创始人兼 CEO，Zingage

提示：把不可动摇的约束放进仓库根目录的 CLAUDE.md。Claude 在每次会话开始时都会读它，你的架构规则、安全边界和不容妥协的底线就会随每个会话同行。

需要说明的是，这些创业公司没有一家是让 agent 直接合入 main 然后听天由命的。他们中许多身处强监管行业，需要强有力的治理框架。Cainex 是“agent + 确定性校验”结合的绝佳例子：读取病历并生成驱动医院账单的编码。

“在医疗编码里，一个错误的编码不是笔误，而是账单与合规事件。仅这一件事就决定了我们怎么构建产品。”Uriah Israel · 联合创始人兼 CTO，Cainex

“Claude Code 为我们跑的是这样一个循环：agent 处理一个批次，审计员在内部应用里评审产出。他们看到的不只是编码，还有模型的推理过程，两样都可以批注……所有内容都有版本、可审计。”他说。

“然后 Claude Code 接手。它直接从数据库读取原始预测，连同每一条更正和批注。每条更正都按涉及的编码类别打了标签，所以 Claude Code 知道面对的是诊断问题、手术操作问题还是别的类别，可以直接去查管辖该类编码的指引。

从那里，它找到 agent 指令中导致错误的部分并修订，遇到真正的新情况就撰写新指引。每一次修改都基于带版本的指令集，并针对曾经出错的记录做测试。我们强制执行的规则是：修原则，不修个案。”他继续说道。

“然后是回测。一条记录可以有不止一种可接受的编码，所以不能做字符串匹配。校验把我们已接受的编码集合做语义匹配，再结合一个裁判判断‘这是真错误，还是只是另一条有效路径’，Claude Code 还会在其上加自己的比对。

它把候选改动跑遍黄金集加随机抽样，在任何东西发布前暴露回归。返回的是一份短清单：建议的修改、它没能解决的记录、以及它想得到解答的问题。工程师把时间花在真正困难的案例上，而不是那机械的 80%。”他说。

这个医疗账单专属流程中，有大量可供创始人们借鉴的普适经验。

例如，Cainex 让领域专家定期评审并引导 Claude 的推理，并确保这些引导成为自我改进循环的一部分。但专家们并非逐例修错——他们的引导被纳入自我改进循环。用 Uriah 的话说：“修原则，不修个案。”

提示：循环（loop）是不断重复工作周期直至满足停止条件的 agent。它们是让 Claude Code 承担更自主、更长周期工作的有效方式。你可以用 skills 定义 agent 需要满足的标准（定义得越清晰越好），让 agent 迭代直到达成目标。
例如，很多组织都建了不稳定测试 agent 或循环，因为停止条件清晰且自包含：agent 重跑测试直到通过，就能自己验证修复。

‍

另一个经验是对维护高质量评测“黄金集”的执着——即一组经过人工核实的问答对，用来验证 agent 的准确性。每家创业公司都应为自己的关键用例维护多套评测集并定期更新，以便防止漂移、评估未来的模型。

“（Claude Code）也改变了我们管理模型迭代速度的方式。新的视频和图像模型源源不断。每一个都需要新的 skills、评测、路由逻辑和上线前测试。Claude Code 把这个周期从几天压缩到几小时，让我们能在同一次会话里发现生产问题并部署修复……当你面对的是人手十倍于你的公司，这种杠杆改变一切。”Alex Mashrabov · 联合创始人兼 CEO，Higgsfield

提示：团队刚开始构建 agent 时，靠手工测试、内部试用加上直觉，往往能走出很远。破绽通常出现在用户反馈“改完之后 agent 变差了”，而团队只能瞎猜乱试、无从验证。团队分不清真实回归与噪声，无法在发布前自动跑几百个场景测试改动，也无法度量改进。更多信息请阅读：Demystifying evals for AI agents。

Uriah 的最后一点是，这个过程需要下功夫。“它一开始没这么干净。我们的第一版过拟合了：它靠把具体案例硬编码来‘修复’问题，我们在攒补丁，而不是变聪明。我们改了方法，强制要求泛化为通用原则，并限制一次改动里能塞进多少具体个案。”

提示：AI agent 不是确定性的，但许多强监管工作要求流程每次都一模一样。Claude Code 提供了把前沿智能与确定性流程结合起来的能力。
Hooks 是在 Claude Code 生命周期固定节点触发的用户自定义命令，可以作为硬性关卡。无论模型怎么决定，它们每次都会执行。例如：拦截一次没过 lint 的写入、要求提交前测试通过、或在任何内容离开沙箱前剥离密钥。
Dynamic workflows 以确定性的编排、相互独立的上下文窗口和聚焦的目标来调度 subagent。/goal 适合长而复杂的任务——Claude 可能在那种任务里过早宣布完工、评审时偏袒自己的结论、或偏离最初的目标。

为重构而构建

团队能依赖的模型能力持续变化，所以很少有东西被当作永久的。

这些 AI 原生创业公司中的许多都处在持续再造的状态。

AI 既常在他们构建的产品核心，也在他们构建产品的方式之中。既然模型能力持续演进，那些开创性的功能和关键脚手架一旦沦为沉没成本就被果断舍弃。这些组织中的许多把这种不断的重建视为竞争优势的一部分。

“我们在 Clay 的做法是：你把它构建一遍，然后再构建一遍，再构建一遍。到第四次构建时，你已经知道需要的一切，就能一次做对。所以我们不一定是把东西扔掉，我们只是重建它：这一次带着更清晰的认识。”Kareem 说。

“重构不是在新路径发布时完成的，而是在旧路径消失时才算完成。拆除（teardown）以前总在优先级之争里落败：它枯燥，又交付不了功能。”Commure 联合创始人 Tanay 说，“现在 Commure 的一位工程师只要调用一个 Claude skill，大意是‘对每一个已全量发布的功能开关，开一个 PR 移除它及关联代码’，然后评审返回的结果。过去吞噬大量开发周期的迁移工作，现在就是一次规划加一次扇出，几个小时搞定。”

提示：用 git worktrees 在仓库的隔离副本里跑重构，当前版本毫发无伤。Claude Code 可以帮你创建——你会得到运行在 v1 旁边的 v2，对两者跑评测，新版本胜出才合并。这正是让“构建四次”变得便宜的原因。

每个关联的 worktree 都是一个普通目录，有自己的检出分支；三者共享 acme-web 内部唯一的 .git 对象存储。

Kareem 还把 Clay 护城河的一部分描述为不断重建、演化并打造自我改进循环的能力。

“我认为当下任何公司的护城河都是：它必须能自我改进。所以 Clay 是一台自学习的营收引擎。你用得越多，我们就越清楚你最好的客户是谁、你该说什么、什么有效、什么无效，而这些也在随时间变化。”他说。“这场竞赛说到底，是谁能最快抵达分发……这样你才能帮助每一位（客户），从而自我改进。”

在 2026 年 5 月的 Code with Claude 活动上，Harvey 应用 AI 负责人 Niko Grupen 谈到，每一波新的模型能力——涌现式推理、agentic 自动化、规划与编排——都要求平台做一次彻底的重新架构。

“如果你六个月前问我的架构长什么样，我的回答会跟今天的截然不同。如果我们当初不愿意说‘嘿，我们要把这套东西废掉、转向 agent 原生’，我们的平台现在根本不可能有这些能力。”Niko Grupen · 应用 AI 负责人，Harvey

在同一场活动上，Cognition 联合创始人 Walden Yan 说：

“当下构建 AI 的生活方式，就是接受你今天构建的东西很可能在六个月到一年内被废弃……（Devin）在两年前那批模型上根本做不出来，（但我们的赌注是）今天也许不行，但很快就行。”Walden Yan · 联合创始人，Cognition

提示：对于非平凡的重写，让 Claude Code 以plan mode（--plan 或按 Shift+Tab）启动。Claude 会先探索代码库、提出重构方案，然后才动手写代码——你批准或纠偏。这是拦截“即将偏离你架构的重构”最便宜的位置。

05

原型、内部试用、产品化

用 AI 构建帮助这些创业公司用 AI 打造颠覆性产品——这是他们流程核心的飞轮。

这些创业公司中的许多都在开发流程的核心装有一个关键飞轮：用 AI 构建，帮助他们用 AI 打造颠覆性产品。

当开发者推进自己的 agentic coding 实践时，他们对模型能力有了更扎实的把握，也能洞察前沿的 harness 设计如何演进。然后他们可以把这些启发用到自己的 agent 和产品里。

“我们从（Anthropic 的）文件 vs. 嵌入方案中获得了启发，这让我们敢于在自己的产品里保持简单。我们避开了 RAG 流水线会带来的一大堆复杂性。”Omni 的 Chris 说。“我们还看到 Claude Code 的 harness 如何让用户并行做事，并把其中一些概念改编进了我们自己的 UI。”

这也帮助他们保持对自家产品性能的敏感。

“因为我们的应用构建器背后用的也是 Anthropic 模型，所以每当我们在产品上看到某个行为……我们可以通过 Claude Code 在本地快速调试，判断这是模型行为还是 harness 问题。这极大改善了我们的分诊周期。”Emergent 的 Mukund 说。

我们反复听到的模式是：用 Claude Code 构建一个内部 agent，先内部试用（dogfood），再根据反响升级为面向客户的产品——通常借助 Claude API、SDK 或 Claude Managed Agents。

“我们（在产品里）构建了自己的 AI agent，供团队直接交互，包括 SQL 控制台里的 agent 和一个 AI SRE。我们用 Claude Code 来构建和迭代这些 agent 本身。驱动客户 AI 体验的工具，部分正是用 AI 构建的。”ClickHouse 的 Alexey 说。
