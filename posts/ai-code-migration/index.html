Anthropic 如何用 Claude Code 执行大规模代码迁移

阅读英文原文 →

代码迁移——把生产代码库移植到一门新语言的项目——直到不久前还是以年计的工程。

就在上个月，Anthropic 的几位开发者用 Claude Fable 5、Claude Opus 4.8 和dynamic workflows，完成了 10 个代码包的迁移，每个包从几万行到几十万行代码不等。本文将介绍其中两个案例，以及从这些项目中总结出的最佳实践。

Bun 联合创始人、Anthropic 技术团队成员 Jarred Sumner 使用 Claude Code 把 Bun 从 Zig 迁移到了 Rust。不到两周产出了上百万行代码，合并前 Bun 现有测试套件在 CI 中 100% 通过。合并后暴露出 19 个回归，均已修复。Rust 版本已于六月随 Claude Code 发布。 

Anthropic Labs 联合负责人 Mike Krieger 在一个周末把一个 Python 代码库迁移成了 16.5 万行 TypeScript。整个过程动用了数百个智能体、八个阶段关卡、三轮对抗性审查，以及最后一轮一致性检查——把每条命令的输出与 Python 原版逐一比对。 

Claude Code 的新能力改变了这些被长期搁置项目的账本。以下是我们如今使用的六步流程，提炼自这些迁移项目的经验。

核心洞见是：你不去修代码，你去修产出这套代码的流程（循环）。

什么是 AI 代码迁移？

AI 代码迁移是指用 AI 智能体把生产代码库移植到新语言或新框架。工程师不再逐文件手工翻译，而是编写迁移规则和验证循环；智能体随后不断翻译、编译、测试，直到新代码的行为与原版一致——把以年计的项目压缩到以周计。

为什么迁移语言、何时迁移

在讲怎么做之前，值得先聊聊何时做和为什么做，因为围绕这类项目的假设已经变了。 

团队发起迁移，是因为从最初构建到今天，技术格局变了：要么某个已知的权衡开始掣肘，要么出现了更好的路线，要么原有生态在萎缩。 

比如，Jarred 当年选择 Zig，是因为它在 C 级性能之外还极为简洁，对于"前 LLM 时代、在奥克兰狭小公寓里打算一年写完 Bun 的独立创始人"来说非常理想。这种简洁附带着已知的取舍，他在这里写到了。 

时间快进到 2026 年。Bun 的 CLI 月下载量已超过 1000 万，并被 Claude Code 大量使用。 

就在上个季度，这些取舍还不足以让人下决心冻结路线图、为一个多季度的项目投入资源。语言迁移固然能带来更小、更快、更安全的系统，但没人愿意买单。

软件工程师还得面对这类昔日巨石工程固有的职业风险：你可能要维护两套并行代码库几个季度甚至几年，而如果最终结果只做到 90% 的一致性，你手上的烂摊子比开工时还大。

而现在，最坏的情况不过是删掉分支、重来一次。

当然，仍然需要有说得通的业务理由。百万行级的迁移虽然不再像过去那样在四年项目周期里烧掉 300 万到 400 万美元的工程资源，但仍要花上几万到几十万美元甚至更多。例如，Bun 的迁移消耗了 59 亿未缓存输入 token 和 6.9 亿输出 token——按 API 价格约合 16.5 万美元。Mike 迁移的主体部分消耗了 2700 万 token。

不过，迁移的理由不再非得是生死攸关。更新日志里一年的内存 bug 补丁，或者一个长期存在的瓶颈，现在就足以立项。

编译步骤正是 Mike 项目的动因。他团队维护的内部工具以单一二进制文件的形式交付给用户。用 Python 工具链产出这个二进制，每个平台大约要 8 分钟，每次发布在构建矩阵上的总等待时间达 30 分钟。迁移之后，同样的编译只需约 2 秒，二进制启动速度快了 6 倍，团队还得以砍掉一条独立的部署管道。

为什么 AI 改变了代码迁移的账本

Claude Fable 5 是我们最强的一般可用（GA）模型。Fable 和 Opus 4.8 尤其擅长用子智能体（subagent）去委派、指挥和验证并行工作流，并能为既定目标寻找多条路径。 

大型代码迁移是这些先进模型格外有效的用武之地，原因如下：

  • 工作是可并行的。任务可以拆到数千个独立单元（如文件和 crate）上执行，智能体可以同时开工，而不是一个等一个。
  • 上下文清晰而完备。旧代码就是给模型的绝佳规格说明。它同时也是构建翻译智能体行动指南的核心参照。
  • 自带裁判。很多大型代码库都带有测试套件，智能体可以用它来验证自己的工作。当验证标准客观时，智能体的表现最好，因为模型可以对着一个 ground truth 连续打磨几天，无需人来仲裁质量。
  • 待办队列自动生成。编译器或测试一旦失败，失败项就成了智能体下一个要修的任务。
  • 要求一致性与边界情况处理。整个流程的设计让漂移无处藏身：审查者引用规则来支撑每一条发现，于是违规不再是悄悄的偏离，而是队列里的一个任务项。而当智能体真的撞上一个边界情况，修复方案就会变成之后所有智能体都要遵守的规则。

正如下文将看到的，Mike 和 Jarred 都在迁移过程的关键步骤用到了 Fable，尤其是顾问模式（advisory pattern）——用多个模型级别组合来优化 token 消耗。
