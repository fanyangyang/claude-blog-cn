用动态过滤提升网页搜索的准确率与效率

阅读英文原文 →

与 Claude Opus 4.6 和 Sonnet 4.6 一同发布的，还有全新版本的网页搜索和网页抓取工具。Claude 现在可以在网页搜索过程中原生地编写并执行代码，在结果进入上下文窗口之前先进行过滤，从而提升准确率和 token 效率。

带动态过滤的网页搜索

网页搜索是一项 token 消耗极高的任务。使用基础网页搜索工具的智能体需要先发起查询，把搜索结果拉入上下文，再从多个网站抓取完整的 HTML 文件，然后对所有内容进行推理，最后才能作答。但搜索引入的上下文往往并不相关，反而会降低回答质量。
为了提升 Claude 在网页搜索上的表现，我们的网页搜索和网页抓取工具现在会自动编写并执行代码来对查询结果进行后处理。Claude 无需对完整 HTML 文件进行推理，而是在将搜索结果载入上下文之前动态过滤，只保留相关内容，其余全部丢弃。
我们此前已经发现这项技术在其他智能体工作流中同样有效，并已在 API 中原生支持了代码执行和程序化工具调用等工具。现在，我们把同样的技术带到了网页搜索和网页抓取中。

评估 Claude 的网页搜索能力‍

我们在仅启用动态过滤（不启用其他工具）的条件下，对 Sonnet 4.6 和 Opus 4.6 的网页搜索能力进行了评估。在 BrowseComp 和 DeepsearchQA 两项基准测试中，动态过滤平均带来 11% 的性能提升，同时输入 token 减少了 24%。
BrowseComp：搜索网络寻找唯一答案‍

BrowseComp 测试智能体能否在众多网站之间穿行，找到一条被刻意藏得很难在线查到的特定信息。动态过滤显著提升了 Claude 的准确率：Sonnet 4.6 从 33.3% 提升到 46.6%，Opus 4.6 从 45.3% 提升到 61.6%。
‍

DeepsearchQA：搜索网络寻找多个答案‍

DeepsearchQA 向智能体提出拥有多个正确答案的研究型问题，所有答案都必须通过网络搜索找到。它考察的是智能体能否系统地规划并执行多步搜索而不遗漏任何答案。该基准使用“F1 分数”衡量，兼顾精确率和召回率——既反映返回答案的准确性，也反映搜索的完整性。

动态过滤将 Claude 的 F1 分数从 52.6% 提升到 59.4%（Sonnet 4.6），从 69.8% 提升到 77.3%（Opus 4.6）。

Token 成本会因模型需要编写多少过滤代码而异。按价格加权的 token 消耗在两项基准中均对 Sonnet 4.6 有所下降，但对 Opus 4.6 有所上升。为了更准确地了解你自己的成本，我们建议用一组能代表你的智能体在生产环境中可能遇到的网页搜索查询来评估此工具。

客户聚焦：Quora

Poe（来自 Quora） 是最大的多模型 AI 平台之一，通过单一界面让数百万用户用上 200 多个模型。Quora 内部团队发现，启用动态过滤的 Opus 4.6“在与其他前沿模型的对比测试中，在我们内部的评测里取得了最高准确率”，产品与研究负责人 Gareth Jones 表示。“这个模型的表现就像一位真正的研究人员，会编写 Python 来解析、过滤和交叉核对结果，而不是在上下文里对原始 HTML 进行推理。”

网页搜索与抓取工具中的动态过滤

在 Claude API 上将新的网页搜索和网页抓取工具与 Sonnet 4.6 和 Opus 4.6 配合使用时，动态过滤将默认开启。对于复杂的网页搜索查询——例如在技术文档中筛查内容或核实引用文献——你可以期待与上述结果相近的性能提升。

在 API 中的用法如下：

{
  "model": "claude-opus-4-6",
  "max_tokens": 4096,
  "tools": [
    {
      "type": "web_search_20260209",
      "name": "web_search"
    },
    {
      "type": "web_fetch_20260209",
      "name": "web_fetch"
    }
  ],
  "messages": [
    {
      "role": "user",
      "content": "Search for the current prices of AAPL and GOOGL, then calculate which has a better P/E ratio."
    }
  ]
}

代码执行、记忆等更多工具正式发布

我们还将若干工具升级为正式版（GA），帮助智能体在 token 密集型任务上表现更好：

  • 代码执行：为智能体提供一个沙箱，在对话过程中运行代码，用于过滤上下文、分析数据或执行计算。
  • 记忆：通过持久化文件目录在多轮对话间存储和检索信息，智能体无需把所有内容都留在上下文窗口中也能保持上下文。
  • 程序化工具调用：以代码方式执行复杂的多工具工作流，让中间结果不进入上下文窗口。
  • 工具搜索： 从大型工具库中动态发现工具，无需把所有工具定义都载入上下文窗口。‍
  • 工具使用示例：直接在工具定义中提供示例调用，展示用法模式并减少参数错误。
