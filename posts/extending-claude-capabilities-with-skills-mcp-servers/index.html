用 Skills 和 MCP 服务器扩展 Claude 的能力

Learn how skills and MCP work together to build agents that follow your workflows and use external systems and platforms effectively.

自发布 Skills 以来，我们从客户那里听到的最常见的两个问题是："Skills 和 MCP 如何协同工作？什么时候该用哪一个？"

Model Context Protocol（MCP）负责将 Claude 连接到第三方工具，而 Skills 则教会 Claude 如何用好这些工具。将两者结合，你就可以构建遵循团队工作流的智能体，而不是那些需要不断纠正的通用流程。

例如，一个连接到 Notion 的 MCP 可以让 Claude 搜索你的工作区。再加上一个会议准备 Skill，Claude 就知道该从哪些页面获取内容、如何组织准备文档的格式，以及你的团队交付会议纪要遵循什么标准。这个连接因此从"可用"变成了"好用"。

在本文中，我们将拆解 Skills 与 MCP 之间的关系、如何将两者结合以构建遵循你工作流、产出一致结果的智能体，并通过几个真实案例演示它们在实践中如何配合。

理解 Skills 和 MCP

假设你走进一家五金店，想修理一个坏掉的柜子。店里应有尽有（木工胶、夹具、替换铰链），但该买哪些材料、怎么用，是另一个问题。

MCP 就像是获得了店内所有货架的通行权，而 Skills 则像是一位经验丰富的店员。如果你不知道需要哪些材料、也不知道怎么用，再全的库存也帮不上忙。Skill 就像那位热心店员，带你走完整个修理流程，指出正确的耗材，并演示规范的操作手法。

更具体地说：MCP 服务器让 Claude 能访问你的外部系统、服务和平台，而 Skills 则提供 Claude 有效使用这些连接所需的上下文，教会 Claude 在拥有访问权限之后该做什么。
没有 Skills 提供的上下文，Claude 只能猜测你想要什么。有了 Skill，Claude 就可以按照你的既定打法行事。

为什么 Skills 和 MCP 是绝配

MCP 负责连接：以安全、标准化的方式访问外部系统。无论你要连接 GitHub、Salesforce、Notion，还是自己的内部 API，MCP 服务器都赋予 Claude 触达你的工具和数据的能力。

Skills 负责专长：把原始的工具访问转化为可靠结果的领域知识和工作流逻辑。一个 Skill 知道何时查询 CRM、在结果中寻找什么、如何格式化输出，以及哪些边界情况需要特殊处理。
这种分离让架构保持了可组合性。一个 Skill 可以编排多个 MCP 服务器，而一个 MCP 服务器也可以支撑数十个不同的 Skill。新增一个连接，已有的 Skills 就能将其纳入；优化一个 Skill，它便适用于所有已连接的工具。

将 Skills 和 MCP 结合，你会得到：

清晰的发现路径：Claude 不再瞎猜去哪里找。一个会议准备 Skill 可以指定：先看项目页面，再看此前的会议纪要，最后看干系人档案。一个研究 Skill 可以规定：先从共享网盘开始，与 CRM 交叉比对，再用网络搜索补齐缺口。Skill 把"哪类任务该用哪些信息源"这类机构知识沉淀了下来。

可靠的编排：多步骤工作流变得可预期。没有 Skill 时，Claude 可能在还没确认信息齐全之前就先拉取数据并排版。Skills 显式定义了执行顺序，因此 Claude 每次都会以相同的方式执行工作流。

稳定的输出质量：产出真正符合标准。泛泛而出的结果总需要返工修改。Skills 为你的团队定义了什么叫"完成"：正确的结构、恰当的详略程度、面向受众的正确语气。

随着时间推移，团队会积累出一系列相互关联的 Skills 和连接，赋予 Claude 在其特定领域的专业能力。

Skills 与 MCP 可能重叠之处‍

MCP 服务器中可能包含指令，形式为工具使用提示和常见任务的提示词。这让工具相关的知识贴近工具本身。不过，这些指令在设计上应保持通用。

经验法则：MCP 中的指令负责如何正确使用该服务器及其工具；Skill 中的指令负责在特定流程或多服务器工作流中如何使用它们。

例如，一个 Salesforce MCP 服务器可以规定查询语法和 API 格式。而一个 Skill 则会规定先查哪些记录、如何与 Slack 对话交叉比对近期上下文，以及如何为团队的 pipeline 评审组织输出格式。
组合 MCP 服务器与 Skills 时，要当心指令冲突。如果 MCP 服务器要求返回 JSON，而你的 Skill 要求格式化为 markdown 表格，Claude 就只能靠猜。让 MCP 负责连接，让 Skills 负责呈现、顺序和工作流逻辑。

Skills 与 MCP 结合使用的真实案例

接下来看看 Skills 和 MCP 在真实工作流中如何组合。我们将走两个例子：金融分析师为公司估值拉取实时市场数据，以及项目经理使用 Notion 的 Meeting Intelligence Skill 做会议准备。

在这两个案例中，MCP 服务器提供了工具的访问能力，而 Skills 定义了用这些工具做什么。

金融分析：公司估值自动化 Skill

Anthropic 发布了一组预构建 Skills，覆盖常见的金融工作流，其中包括可比公司分析（comparable company analysis）。可比公司分析是一种标准估值方法。做可比公司分析的分析师要花数小时从多个来源拉取财务指标、套用同一套估值方法论，并按合规标准排版输出。这项工作重复、易错，正是那种最能受益于 Skills 与 MCP 协同的工作流。

Skill：可比公司分析自动完成这一估值工作流，从多个数据源拉取数据、统一套用方法论，并按特定标准排版输出。

MCP 服务器：连接 S&P Capital IQ、Daloopa 和 Morningstar 获取实时市场数据

工作流：

  1. Skill 确定要查询哪些数据源（发现）
  2. MCP 连接拉取实时财务数据
  3. Skill 套用方法论并排版输出（编排）
  4. Skill 依据合规要求进行校验（质量）

会议准备：Notion 的 Meeting Intelligence Skill

会议准备很繁琐。你需要从多个地方拉取上下文——项目文档、此前的会议纪要、干系人信息——然后综合成一份预读材料和一份议程。这类多步骤流程，往往每次都要重新向人解释一遍。

Skill：Meeting Intelligence 定义了要搜索哪些页面、如何组织输出、包含哪些章节

MCP 服务器：Notion 连接，可搜索、读取和创建页面

工作流：

  1. Skill 确定要搜索的相关页面，包括项目、历次会议、干系人信息（发现）
  2. MCP 连接在 Notion 中检索并获取内容
  3. Skill 组织两份文档：内部预读材料和对外议程（编排）
  4. MCP 连接将两份文档保存到 Notion，结构清晰并相互链接
  5. Skill 确保输出符合格式规范（质量）

何时用 Skills，何时用 MCP

‍Skills 和 MCP 解决的是不同的问题，但面对一个具体工作流要选哪个，并不总是一目了然。

什么情况用 Skills

Skills 用来沉淀那些原本只存在于你脑子里、或者每当新人加入团队就要重新讲一遍的知识。它们最适合：

  • 涉及工具的多步骤工作流：从多个来源拉取内容再生成结构化文档的会议准备
  • 对一致性要求高的流程：每次都必须遵循相同方法论的季度财务分析、设有强制检查点的合规审查
  • 希望沉淀并分享的领域专长：研究方法论、代码评审标准、写作规范
  • 希望在人员流动后仍能延续的工作流：以可复用指令形式沉淀下来的机构知识

什么情况用 MCP 服务器

MCP 拓展了 Claude 可以访问和使用的范围。当你需要以下能力时，请使用 MCP：

  • 实时数据访问：搜索 Notion 页面、读取 Slack 消息、查询数据库
  • 在外部系统中执行操作：创建 GitHub issue、更新项目管理工具、发送通知
  • 文件操作：读写 Google Drive、访问本地文件系统
  • API 集成：连接尚无 Claude 原生支持的服务

如果你要解释的是如何做某件事，那是 Skill。如果你要的是让 Claude 访问某个东西，那是 MCP。

常见问题

Skills 会取代 MCP 吗？

不会。Skills 和 MCP 解决不同的问题。MCP 提供与外部工具和数据的连接，Skills 提供如何有效使用这些连接的流程性知识。最强大的工作流往往两者都用。

一个 Skill 可以使用多个 MCP 服务器吗？

可以。单个 Skill 可以同时协调多个 MCP 服务器。一个技术竞争分析 Skill 可以同时在 Google Drive 中搜索内部研究、从 GitHub 拉取竞争对手的代码仓库，并通过网络搜索收集市场数据。

一个 MCP 服务器可以配套多个 Skills 吗？

可以。一个 Skill 可以放大单个 MCP 连接的价值。Notion 就展示了这种模式：会议准备、研究、知识沉淀、从规格到实现，各有独立的 Skills——在此查看。
