集中管理 MCP 连接器的授权

Admins can now provision MCP connectors for their whole organization through their identity provider, starting with Okta. Users get connector access automatically on first login, with authorization configured centrally by their organization.

管理员现在可以通过身份提供商为整个组织开通 MCP 连接器，率先支持 Okta。用户首次登录即可自动获得连接器访问权限，授权由组织统一配置。

连接器让 Claude 在工作中更有用——它们把团队已在使用的工具中的上下文交给 Claude。在此之前，启用连接器需要两个步骤的操作：管理员先为组织启用连接器，然后每位用户再各自完成授权。 

企业托管授权简化了第二个步骤。管理员只需授权一次连接器，用户通过他们已有的 IdP 组和角色继承访问权限，第一次打开 Claude 时连接器就已就位。对最终用户而言，这就是零接触的连接器配置。

企业托管授权是 Model Context Protocol 的企业托管授权扩展的首个实现。它建立在开放标准之上，因此任何连接器都可以支持——包括你自己的团队构建的自定义连接器——并且对所有 Claude 客户都以同样的方式运作。

工作原理

将你的身份提供商连接到 Claude，并选择要为组织启用哪些 MCP 连接器。员工登录时，他们的连接器已经就绪。访问权限在 Claude 对话、Claude Code 和 Cowork 中保持一致。

对管理员来说，这将 MCP 访问管理并入了管理技术栈其余部分的同一套工作流：开通一次，按组划定范围，通过 IdP 管理撤销。由于向 IdP 校验访问权限毫无摩擦，管理员可以缩短访问令牌的有效期而不影响生产力——因此当某人被注销账号时，其连接器访问权限会迅速过期，而不是残留在一个旧令牌上。访问经由你已经信任的身份提供商进行，因此连接器与其他所有系统一样处于相同的安全和访问控制之下，而无需单独监控一个额外的暴露面。

管理员还可以强制要求连接器只能通过 IdP 建立连接，从而将工作用途与个人用途干净地分开，防止有人误将个人账号关联到工作工具上。

与生态系统共同构建 

企业托管授权横跨三类群体：掌管访问权限的身份提供商、支持该标准的 MCP 提供商，以及在团队中部署托管连接的 Claude 客户。

身份提供商。发布时支持 Okta，更多身份提供商即将支持。

MCP 提供商。Asana、Atlassian、Canva、Figma、Granola、Linear 和 Supabase 在发布时即支持企业托管授权，Slack 即将支持。

Claude 客户。 Hubspot、Ramp 和 Webflow 等组织正在其团队中推广企业托管授权。

开始使用

企业托管授权现已对 Claude Team 和 Enterprise 计划的客户以 beta 形式提供。前往我们的帮助中心了解更多，并申请访问以开始使用。 

任何身份或 MCP 提供商都可以通过实现 MCP 授权规范的开放 扩展，来加入对企业托管授权的支持。提交意向以加入 beta 请点这里。
