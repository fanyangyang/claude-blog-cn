Datadog 如何为 Claude Code 打造一把“万能机床”

智能体、机械化与工业化

Datadog 的所有工程师都在用 AI 编码工具写生产代码，其中至少三分之二由 Claude Code 驱动。借助 Claude Code，他们在自己的软件开发生命周期中形成了四类各具特色的个性化流程：

  • 定向修改： 数十个棘手的 bug 修复、性能优化，以及与现有服务的桥接。 
  • 大型重构：三天内重构一个自研 protobuf 解析器，以及用不到三个月把一个指标控制面从 FoundationDB 迁移到 Postgres。 
  • 替换大型组件：新的分片算法和自动扩缩容的重新设计。 
  • 构建整套系统：用 Postgres 替换 MongoDB、BYOC 控制平面，以及从零搭建数据摄取管道。

然而，随着工作沿着这张地图铺开，他们发现：一个轴线上，生成变得越来越复杂；另一个轴线上，验证变得越来越模糊。 

心流问题

对工程师而言，心流（flow）过去意味着意图与代码之间的直接联系。你理解问题、写代码、测试、审查、发布、运维，如此往复。有了智能体之后，这层抽象正在快速改变。 

“你不再是写代码的人，而是塑造工作的人。你要决定智能体应该看到什么、该有哪些工具、成功是什么样子、失败该如何被发现……这就像所有人都被连升三级变成了管理者，而他们当初选择做工程师，可没打算干这个。”Datadog 工程副总裁 Sesh Nalla 说。

借助 Claude Managed Agents 等方案，Datadog 的会话运行时间更长，有时长达数天。每个智能体都会发明自己的工具、自己的胶水代码和自己的约定。这些智能体变得有用得多，但需要人类来弥合智能体执行方式与为人类设计的工具之间的鸿沟。

机床（machine tool）是制造业中常见的夹具、工装、量具和铣床。它们生产精确、可复用的零件，再由这些零件组装成更大、更复杂的机器——发动机、飞机、核反应堆、登月舱。零件变得可组合、可检查、可替换，正是工业化的突破点。

Temper 是 Sesh 对 Datadog 尝试的描述——为智能体系统打造一把万能机床。换句话说，就是智能体以安全、精确的方式构建所需之物的最小内核。

“正是在这个节点，我意识到我们需要一些更结构化的东西。”Sesh 说，“如果智能体将要构建和运营我们系统的大部分、我们数据库的大部分——这些都是关键任务系统——它们就需要有机床概念的等价物。对 Datadog 来说，Temper 就是那把机床。”

通往 Temper 的路

机械化意味着现在更多工作由智能体来做。工业化则意味着工作变得可重复、可验证、可控制和可规模化。在 Datadog，这并非一蹴而就：通往 Temper 的路上，先经过了 Courier、BitsEvolve 和 Helix 三个项目。每一个都暴露出下一个项目的瓶颈，也让他们敢于把野心再放大一档。

2024 年，他们推出了 Courier，一套分布式队列系统。完全手写、从零开始，花了一年。

“难点不在于做出零件，而在于让零件之间的交互变得可观察、可测试、可验证。”Sesh 说，“所以我们在形式化建模和仿真上非常严格……找出那些一旦出错就代价高昂或难以回退的部分，并在那里提高严谨程度。” 

2025 年 9 月，他们做了 BitsEvolve，一套闭环进化优化 harness。一个模型委员会生成代码变体。一层层 benchmark、测试和生产可观测性决定谁留下来。 

“这是我第一次隐约看到，软件的某些部分可以像活的有机体一样被培育——通过带反馈的变异，以及适应，一点点长出来。”Sesh 说。 

问题在于：进化只能和它所适应的环境一样好，而 BitsEvolve 的瓶颈就在这条反馈回路上。随后他们做了 Helix，一套可与 Kafka 对标的流服务。大部分构建由 Claude Code 完成，一个人掌舵。 

“让我们难以置信的是，几天之内我们就有了一套功能完整、可与 Kafka 对标的系统。”Sesh 说，“[它建得很快]，我们开始对它做影子流量，并看到了便宜 2 到 5 倍的机会。”

但把它送进生产，还要走长得多的路：运维上的硬化只能靠时间、靠不止一个人积累，而这项工作至今仍在推出过程中。 

“瓶颈又一次挪了位置：智能体已经能构建系统的大部分……但人类仍要通过为人类设计的工具和机制，协调把工作送进生产。”Sesh 说。

Datadog 需要一种办法，让智能体在经过验证、由策略驱动的运行时环境里自己造工具。那个运行时就是 Temper。

Temper

智能体产出代码的速度，已经快过任何团队能手工审查的速度，但它们也会出错。 

对 Sesh 来说，智能体生成的东西和通过验证的东西之间的缝隙，正是失败模式堆积的地方。不过，只是把智能体包在一套传统代码库外面，等于把这当成吞吐量问题，并没有真正合上验证这条缝。

Temper 把这个等式反过来：智能体不再产出应用代码，而是产出规格。内核读每一份规格，经过四层分析验证，再部署规格所描述的运行系统。因为规格既是被证明的制品，也是被执行的制品，已验证的东西和正在运行的东西之间不会漂移。

“Temper 改变了系统的中心。智能体不再需要为每个局部需求不断发明互不衔接的工具。相反，它把意图和问题域写成精确的规格描述。它是机床，和夹具或 CNC 机床是同一个意思：你给它们螺纹该是什么样的规格。它极其可重复。你可以跑它们，也可以用它们造飞机和这类复杂的东西。”Sesh 说。

所以在这种情形下，智能体不会每次都即兴拼出最终机制。它可以先写出精确描述，再和 Temper（或类似 Temper 的机制）一起迭代，先让东西跑起来，再把它变成可重复、可检查、可复用的东西，这样你才能真正围着代码库建一座软件工厂。

每一项能力由三份契约描述：

  • 行为：必须成立的状态、转换、前置条件和安全属性。 
  • 数据契约：实体类型、它们的属性，以及每种类型支持的动作，以机器可解析的形式发布，让智能体不必读文档就能发现完整 API。
  • 授权：默认拒绝、基于范围的批准；拒绝会被记成待决决策，人类可以批准并热加载进策略引擎。

每一份规格都要先通过四层彼此独立的检查，内核才会加载它。符号推理证明每条 guard 可满足、每条不变量是归纳的。穷尽状态探索会访问每一个可达状态。 

确定性仿真用带种子的故障注入跑真实的生产代码路径——丢包、延迟、乱序、崩溃——这样同一颗种子下，失败可以精确复现。 

随机属性测试大约会跑一千条伪随机动作序列，并把任何违规收缩成最小反例。对一份小规格，整条级联远不到一秒就能跑完。

Helix 的暗工厂

Simon Willison 让 dark factory（暗工厂）这个词流行起来，指的是智能体在虚拟工厂地板上继续工作、现场没有人类的软件过程。在 Helix 的暗工厂里，Temper 扮演三个角色。 

它是托管智能体的智能体控制平面——会话、角色、工作队列、生命周期。它是造工具层，让智能体能用小型 Temper 应用桥接 SDLC 工具链（Git、CI、部署）。它也是 Helix 控制 API，也就是数据平面周围那层用来驱动工作负载的生命周期表面。

“让人意外的是，它开始显得比智能体基础设施更通用。很多软件，你眯着眼看，其实就是围着数据库 API 转的控制逻辑：状态、围绕变更的策略、生命周期转换、与外部系统的集成。Temper 可以是万能的，意思是它能用在任何具有我描述的那种形状的软件上。”Sesh 说。

为什么不直接做一套 CRUD 应用？

“Claude Code [用 TypeScript 或 Python 做 CRUD 应用] 做得非常好。不过在普通 CRUD 应用里，控制逻辑散落在路由、数据库约束、服务代码、后台任务和文档里。测试和覆盖率也许不错，但运维模式——通常以状态机的形式出现——在代码库里是隐式的。”Sesh 说。

“Temper 把那台状态机变成显式的。智能体产出的是精确描述，而不是任意代码。编译步骤在 LLM 外面，就像你把 Rust 代码交给 Rust 编译器。转换表是数据，不是埋在服务方法里的意大利面控制流。智能体可以在安全约束下动态改它，并且热加载，不必走 CI。”他解释道。

接下来往哪走

Temper 背后的想法是：每一件制品都应当小到能装进你脑子里。航空和金融系统这类高保证软件，几十年来一直是这样做的；但在智能体出现之前，用人类去达到那种严谨程度，对一般软件来说成本太高。

工业革命之所以成为可能，是因为机床让零件变得可组合、可检查、可替换，于是我们才能造出越来越大、越来越复杂的机器。 

“如果智能体能够以这种纪律，在工厂里自主构建软件，也许我们不必停在暗工厂。这样做出的软件，开始像一个我们可以培育、栽培，并通过反馈、选择和适应来演化的有机体。”Sesh 说。

观看完整场次，看现场演示，以及更深入的讨论：Datadog 如何做出 Temper 这套受约束的框架，把一次性的智能体工具变成安全、可复用的组件，并在会话和团队之间复利。
