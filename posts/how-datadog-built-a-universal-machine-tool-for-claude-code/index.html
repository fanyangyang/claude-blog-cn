Datadog 如何为 Claude Code 打造一把“万能机床”

阅读英文原文 →

智能体、机械化与工业化

Datadog 的所有工程师都在用 AI 编码工具写生产代码，其中至少三分之二由 Claude Code 驱动。借助 Claude Code，他们在自己的软件开发生命周期中形成了四类各具特色的个性化流程：

  • 定向修改：数十个棘手的 bug 修复、性能优化，以及与现有服务的桥接。 
  • 大型重构：三天内重构一个自研 protobuf 解析器，以及用不到三个月把一个指标控制面从 FoundationDB 迁移到 Postgres。 
  • 替换大型组件：新的分片算法和自动扩缩容的重新设计。 
  • 构建整套系统：用 Postgres 替换 MongoDB、BYOC 控制平面，以及从零搭建数据摄取管道。

然而，随着工作沿着这张地图铺开，他们发现：一个轴线上，生成变得越来越复杂；另一个轴线上，验证变得越来越模糊。 

心流问题

对工程师而言，心流（flow）过去意味着意图与代码之间的直接联系。你理解问题、写代码、测试、审查、发布、运维，如此往复。有了智能体之后，这层抽象正在快速改变。 

"你不再是写代码的人，而是塑造工作的人。你要决定智能体应该看到什么、该有哪些工具、成功是什么样子、失败该如何被发现……这就像所有人都被连升三级变成了管理者，而他们当初选择做工程师，可没打算干这个。"Datadog 工程副总裁 Sesh Nalla 说。

借助 Claude Managed Agents 等方案，Datadog 的会话运行时间更长，有时长达数天。每个智能体都会发明自己的工具、自己的胶水代码和自己的约定。这些智能体变得有用得多，但需要人类来弥合智能体执行方式与为人类设计的工具之间的鸿沟。

机床（machine tool）是制造业中常见的夹具、工装、量具和铣床。它们生产精确、可复用的零件，再由这些零件组装成更大、更复杂的机器——发动机、飞机、核反应堆、登月舱。零件变得可组合、可检查、可替换，正是工业化的突破点。

Temper 是 Sesh 对 Datadog 尝试的描述——为智能体系统打造一把万能机床。换句话说，就是智能体以安全、精确的方式构建所需之物的最小内核。

"正是在这个节点，我意识到我们需要一些更结构化的东西。"Sesh 说，"如果智能体将要构建和运营我们系统的大部分、我们数据库的大部分——这些都是关键任务系统——它们就需要有机床概念的等价物。对 Datadog 来说，Temper 就是那把机床。"
