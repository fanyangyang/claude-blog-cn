在 Claude Developer Platform 上管理上下文

阅读英文原文 →

今天，我们在 Claude Developer Platform 上推出了管理智能体上下文的新能力：上下文编辑（context editing）和记忆工具（memory tool）。

结合我们的最新模型 Claude Sonnet 4.5，这些能力让开发者能够构建可长时间运行任务的 AI 智能体，性能更高，且不会触及上下文上限或丢失关键信息。

上下文窗口有上限，而真实的工作没有

随着生产环境中的智能体处理越来越复杂的任务、产生越来越多的工具结果，它们常常会耗尽有效上下文窗口——开发者不得不在截断智能体记录和牺牲性能之间艰难抉择。上下文管理从两个方面解决了这个问题，帮助开发者确保只有相关数据留在上下文中，而宝贵的洞见得以跨会话保留。

上下文编辑会在接近 token 上限时，自动清理上下文窗口中过期的工具调用和结果。随着智能体执行任务并不断积累工具结果，上下文编辑会移除陈旧内容，同时保留对话流程，从而有效延长智能体无需人工干预的运行时间。这还能提升模型的有效性能，因为 Claude 只需关注相关上下文。

记忆工具让 Claude 能够通过基于文件的系统，在上下文窗口之外存储和查阅信息。Claude 可以在存储于你自己的基础设施、跨对话持久存在的专用记忆目录中创建、读取、更新和删除文件。这使得智能体能够随时间积累知识库、跨会话维护项目状态，并引用此前的经验教训，而不必把所有内容都留在上下文里。

记忆工具完全通过工具调用在客户端运行。存储后端由开发者管理，因此数据存储在哪里、如何持久化，都完全处于开发者的掌控之中。

Claude Sonnet 4.5 为这两项能力带来了内建的上下文感知——在整个对话过程中跟踪可用 token，从而更有效地管理上下文。

这些更新组合起来，形成了一套能提升智能体表现的系统：

  • 通过自动从上下文中移除过期的工具结果，支持更长的对话
  • 通过将关键信息保存到记忆来提升准确性——并让这些经验在连续的智能体会话间延续

构建长时间运行的智能体

Claude Sonnet 4.5 是世界上构建智能体的最佳模型。这些功能为长时间运行的智能体解锁了新的可能——处理整个代码库、分析数百份文档，或维护庞大的工具交互历史。上下文管理在此基础之上，确保智能体既能高效利用扩展后的容量，又能处理超出任何固定上限的工作流。使用场景包括：

  • 编程：上下文编辑清理旧的文件读取和测试结果，而记忆保留调试洞见和架构决策，使智能体能在大型代码库上工作而不丢失进度。
  • 研究：记忆存储关键发现，上下文编辑移除旧的搜索结果，逐步积累知识库并让性能随时间提升。
  • 数据处理：智能体把中间结果存入记忆，同时上下文编辑清理原始数据，从而处理原本会超出 token 上限的工作流。

上下文管理带来的性能提升

在一套用于评估智能体式搜索的内部评测集中，我们测试了上下文管理如何提升智能体在复杂多步任务上的表现。结果显示出显著收益：记忆工具与上下文编辑结合，性能较基线提升了 39%；仅使用上下文编辑也带来了 29% 的提升。

在一项 100 轮的网络搜索评测中，上下文编辑让智能体得以完成原本会因上下文耗尽而失败的工作流，同时将 token 消耗降低了 84%。
