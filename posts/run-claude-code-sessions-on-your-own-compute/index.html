在你自己的算力上运行 Claude Code 会话

Self-hosted environments are in public beta. Run Claude Code sessions on your own infrastructure, inside your network and next to your internal services.

现已进入公开测试：自托管环境让你可以在自己的基础设施上运行 Claude Code 会话。从网页、移动端、桌面或例程启动一次会话，它会在你的网络内部运行，紧挨着你的内部服务、工具链和安全控制，而不是跑在 Anthropic 托管的基础设施上。

对大多数企业，我们强烈建议使用我们的托管方案，运维更简单，无需自行运行或维护基础设施。自托管环境面向那些因网络、工具或合规要求，必须把 agent 执行留在自己控制的基础设施上的团队。如果走这条路，请规划工程人力来负责搭建和持续维护。

为什么要自托管

在预览计划中，我们看到组织采用自托管环境主要出于几个原因：

  • 网络访问：会话在你的网络内部运行，可以访问内部服务、数据库和 registry，而无需把它们暴露到公网
  • 可定制：在环境中预装编译器、SDK 和内部 CLI，让每次会话一开始就能构建
  • 合规：源代码和构建产物留在你控制的基础设施上

数据留在你的基础设施上

仓库检出、构建产物、密钥，以及会话创建或修改的任何文件，都留在你所配置的基础设施上。

对话本身，包括提示词、回复和工具结果（其中可能包含 Claude 读取的代码），会发送给 Anthropic 做推理；会话记录会被保存，以便从任意界面继续。

工作原理

使用自托管环境时，你部署一组 runner。这些长时进程领取会话，并为每个 session 启动一个 Claude Code 进程。Runner 有两种模式。 

  1. Fixed：你保持固定数量运行，会话在它们之间分配。 
  2. On-demand：一个编排器监视排队中的会话，会话到达时启动 runner，工作结束后停止它们，让容量跟随需求。

Runner 可以服务多个会话，但每个会话都有自己的检出，因此开发者和账户之间的工作保持隔离。所有受支持界面上的会话都会路由到同一个环境，因此你只需配置一次，团队从哪里启动会话都能用。

说明：自托管环境不同于 Remote Control。后者让开发者从手机或浏览器继续跑在自己机器上的会话。使用 Remote Control 的会话会在那台机器停止运行会话时结束，并且绑定到运行 claude 的用户；而自托管环境把会话跑在平台团队运营的共享基础设施上，任何用户都可以使用。

开始使用

自托管环境以公开测试形式向 Claude Team 和 Enterprise 计划的组织开放。默认关闭，使用 ZDR 的组织不可用。

请规划由平台、开发者体验或开发者生产力团队负责搭建和持续运营，包括构建和维护 runner 镜像、更新 runner，以及在使用 on-demand 模式时运行编排器。

了解更多请参阅 文档。可通过 GitHub 或你的 Anthropic 客户团队反馈。
