Anthropic 销售团队如何用 Claude Managed Agents 重建获客流程

Anthropic 的销售拓展负责人 Carl Johnson 分享了，一个由 Claude 驱动的购买智能体现如今如何回答大部分入站客户，以及这如何改变了我们销售团队的工作方式。

作为一位销售负责人，我很痛心地承认，不久前，那些想为公司购买 Claude 的人，并没有足够快地得到他们需要的答案。他们填写了我们的「联系销售」表单，却要等太久才能收到回复，有时甚至要等好几天。他们的问题大多很简单：套餐多少钱、是否有最低席位限制，或者我们能否满足 HIPAA 的合同要求。答案其实都在我们的文档和支持文章里，但客户想要的是有人能快速带他们走一遍流程。

于是我们用 Claude Managed Agents（测试版）构建了一个购买智能体，它能把客户从「我想为公司购买 Claude」一路带到完成购买。如今，这个购买智能体每天承接数千次对话，回答客户最紧迫的问题，并引导他们完成结账。被升级转交给我们的团队的客户，到来时已经受过教育、更准备好做出购买决定：他们转化为商机的概率是旧表单线索的两倍以上，成交速度也快了大约五天。我们特意把这种体验设为自愿选择，也就是说，客户在开始时可以根据自己的偏好，决定是想和智能体交谈还是和销售代表交谈。

旧的获客流程为什么会出问题

在构建购买智能体之前，我们的获客流程相当直接。买家填写一份表单。线索被分配给一位业务拓展代表，由他进行资格认定，再转交给客户经理。当团队能和每一位对产品感兴趣的人交谈时，这套流程依然行之有效。 

我们每月有数万个入站请求，而入站 BDR 团队根本忙不过来。代表们整天都在回答文档里已经覆盖的问题，而我们也没有有效的方式触达队列里的所有客户。这不是我们希望给客户的体验。

我们希望每一位客户都能在任何时间、用任何语言得到有见地的回答，并且能按照他们偏好的方式购买——而这往往意味着不需要和销售代表交谈。我们希望代表们把时间花在那些他们能改变结果走向的对话上。

一个填补空白的购买智能体

我们把智能体部署在客户原本就会提问的地方：在我们的联系销售页面和定价页面、产品内部，以及我们的邮件里。任何客户都能在我们的 Claude.ai 产品中找到这个购买智能体，它是一种简单的聊天体验，帮助客户弄清楚哪种套餐最适合他们。客户描述他们团队的需求，智能体追问几个问题，然后回答关于定价、安全和数据的问题，最后推荐合适的套餐和席位数量。每段对话都以三种方式之一结束：

  • 购买。买家直接进入结账流程。
  • 转交。对于更大或更复杂的交易，智能体会连同完整的对话详情一起，把买家转交给销售代表。
  • 快速回答。有时候客户需要的只是一个答案。

我们构建智能体的方式，与销售代表的工作方式保持一致，也就是理解客户想要解决什么问题、他们目前使用 Claude 的情况如何，以及我们怎样才能最好地帮助他们。

为什么我们选择 Claude Managed Agents？ 

在底层，购买智能体很简单：一段提示词、一组工具，再加上运行在 Claude Managed Agents 上的 Claude。因为这个平台负责托管、会话管理和工具编排，我们的工程师把时间花在了与销售团队一起设计购买体验上，而不是搭建基础设施。

我们最终选择 Managed Agents，原因如下： 

  • 快速上线生产。一位工程师仅用几周时间，就在 Managed Agents 上构建出了最初的购买智能体。 
  • 技术与非技术贡献者都能参与。工程团队负责代码，但销售和内容负责人直接在 Console 中审查并编辑系统提示词。改动会先进入我们的预演智能体，这样任何人在改动触达客户之前都能先试一下。
  • 聚焦业务领域，而不是底层框架。Managed Agents 负责运行智能体循环、会话和托管。我们把时间花在提示词、工具和知识库上——这三样才是销售特有的东西。
  • 版本管理让迭代成本更低。每次对智能体的改动都会保存为独立版本。内部测试大约一周后，我们就用到了 v7，并且上线后每周都在持续推送提示词改动。需要时，我们可以轻松地把新会话指回之前的版本。 
  • 灵活支持更多用例。如今，客户是在我们的网站上发现这个智能体的。Managed Agents 支持定时运行，这为我们探索其他类型的客户互动提供了路径。 

我们在构建购买智能体中学到的东西

给 Claude 一个目标，而不是一堆规则。向智能体解释目标，比给出一长串详细指令效果更好。例如，「你的目标是理解客户需求、认定潜在客户资格，并推荐最佳套餐」这样简单的一句话，比把每条资格要求都列成流程图更有效。 

少即是多。我们尝试了不同长度、复杂度和结构的提示词，发现「少即是多」这条准则最有效。如今的模型能理解复杂而微妙的目标，并能从目标倒推。在实践中，这意味着不要挡在 Claude 前面——给它成功所需的知识和上下文，比如基于席位的定价涵盖哪些内容、计费周期在什么时候运转。

让领域专家参与开发循环。在一个智能体编码正在加速开发周期的世界里，这一点变得越来越有价值。由于使用 Managed Agents 和 Claude Code 节省了时间，我们的工程师得以花更多时间与销售团队一起打造以客户为中心的体验。我们能够尽早且频繁地测试智能体，从而快速迭代。

关注什么对客户才是对的。智能体常常会把小团队指向我们的 Team 套餐而不是 Enterprise，因为在某些情况下那才是正确的答案。我们决定把这当作一个特性。买到了合适套餐而不是被向上销售的买家，更有可能留下来并获得更好的体验。

把每一次从智能体转交给代表都当作反馈。每次智能体把买家转交给代表时，它都会说明原因。早期，这些原因大多是因为客户还无法通过我们的自助服务产品自行完成某些事情。这些原因塑造了我们改进体验的方式，而需要人来帮助成交的对话占比，已经下降了一半左右。

客户体验发生了哪些变化 

如今，智能体每天承接数千次对话，全天候运转。客户能立刻得到问题的答案，而不再需要等待预约电话，或花好几天来回发邮件。我们很多客户其实更喜欢和智能体而不是真人交谈，因为在问题出现时，智能体能快速给出有依据的答案。我们许多新的自助式 Enterprise 客户在购买前都会和购买智能体交谈，而我们发现，那些事先和智能体聊过的客户，对自己所买的东西理解得更清楚。

智能体如何改变了我们的销售组织

智能体改变了我们代表们每天的精力投向。如今，我们把团队大部分时间和精力，用于在客户购买旅程的更早阶段教育客户、进行更多实时的客户对话，以及把时间花在线下活动上。 

最具影响力的变化是：我们的代表如今能获得更有信息量的线索，线索转化为销售商机的概率比旧的联系表单更高，而且成交速度快了大约五天。代表开始对话时，已经知道客户需要什么、客户被告知过什么，以及我们怎样才能最好地帮助他们。

例如，我们的一位内部销售代表 Ojas，过去成交一笔交易大约要来回发 10 封邮件；现在大约 6 封就够了。自从推出购买智能体以来，他已经能把已成交订单的产出提升到 2.5 倍，因为智能体让他能够专注于那些已经受过良好教育、准备好成交、只需要有人帮他们跨过终点线的客户。 

不久之前，获客还是我们团队应付不过来的一个队列。现在，它成了任何买家在任何时间都能发起的对话，我们的代表也把时间花得更高效了。购买智能体只是我们朝着在整条客户关系链上部署智能体迈出的第一步。
