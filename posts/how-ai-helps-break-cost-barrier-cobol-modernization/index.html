用 AI 进行 COBOL 现代化：打破成本壁垒

COBOL 无处不在。据估计，美国 95% 的 ATM 交易都由它处理。每天有数千亿行 COBOL 代码在生产环境中运行，支撑着金融、航空和政府机构的关键系统。
尽管如此，能读懂它的人数却在逐年减少。

构建这些系统的开发者多年前就已退休，他们掌握的机构知识也随之流失。生产代码在过去几十年间被反复修改，但文档却没有跟上。与此同时，新的 COBOL 人才几乎无从补充——只有少数几所大学还在教授 COBOL，能读懂它的工程师一个季度比一个季度难找。

面对这些障碍，组织该如何在不丢失数十年积累的可靠性、可用性和数据的前提下实现系统现代化？又如何确保不出任何差错？

什么是 COBOL 现代化？

COBOL 现代化是指对遗留 COBOL 应用进行更新的过程——可以是将它们迁移（rehost）到新的基础设施上、重构代码、用 Java 等现代语言重写，或者彻底替换整个系统——同时保留其中沉淀了数十年的业务逻辑。成本一直是最大的障碍：弄清楚代码到底做了什么，是最昂贵的一步。

为什么 COBOL 现代化与众不同

COBOL 现代化与常见的遗留代码重构有本质区别。你不是在把熟悉的代码更新为更好的模式，而是在对尼克松还在任上时构建的系统做逆向工程，还原其中的业务逻辑。你要理清演化了数十年的依赖关系，翻译如今只存在于代码本身的机构知识。 

过去，一个 COBOL 系统的现代化往往需要成群结队的顾问花上数年时间梳理工作流。其结果是周期漫长、成本高昂，鲜有组织愿意承接。

AI 改变了这一切。

Anthropic 的智能体编程工具 Claude Code 可以自动化探索与分析阶段，而这正是 COBOL 现代化中最耗精力的环节。这类工具可以：

  1. 在数千行代码之间映射依赖关系
  2. 为早已无人记得的工作流编写文档
  3. 识别出人类分析师需要数月才能浮现的风险 
  4. 为团队提供做出明智决策所需的深度洞察

有了 AI，团队可以在几个季度内（而非几年）完成 COBOL 代码库的现代化。

COBOL 现代化的四种路径：迁移、重构、重写、替换

大多数现代化项目会从四种路径中选择。

‍迁移（Rehosting）将 COBOL 原封不动地搬到更便宜的基础设施上——速度快，但可维护性问题依然存在。

‍重构（Refactoring）在不改变行为的前提下重组代码结构。重写（Rewriting）则将其转换为 Java 或 Python 等现代语言——收益最高，但历来成本和风险也最高。

‍替换（Replacing）是在有合适的商业产品时，直接用其替换原有系统。AI 改变最大的是重写路径的经济学，这也是本文余下部分的重点。

AI 如何改变 COBOL 现代化

AI 擅长简化那些曾经让 COBOL 现代化成本高到令人却步的任务。有了它，你的团队可以专注于战略、风险评估和业务逻辑，而由 AI 自动完成代码分析与实施。

自动化探索与发现

AI 的第一步是通读你的整个 COBOL 代码库，并绘制出其结构图。 

它会识别程序入口点，追踪经由子程序调用的执行路径，映射模块之间的数据流，并为跨越数百个文件的依赖关系编写文档。 

这种映射远不止简单的调用关系图。共享数据结构、在模块间造成耦合的文件操作、影响运行时行为的初始化序列——这些隐式依赖不会出现在静态分析中，因为它们涉及通过文件、数据库或全局状态共享的数据。它们恰恰也是 COBOL 现代化风险所在，因此自动化发现才如此重要：它能在这些隐藏关系在迁移过程中引发问题之前就把它们找出来。

工作流文档也会从这种分析中自然产出。 

通过追踪数据从输入到输出在系统中的流动路径，AI 可以为那些早已无人记得如何构建、但人人都在依赖的处理管线生成图表和文字说明。

风险分析与机会识别

代码库绘制完成后，AI 可以评估哪些组件可以安全迁移、哪些需要谨慎处理。高耦合的模块现代化风险更高；孤立的组件会浮现出来，成为优先独立现代化的候选；重复的逻辑指向重构机会；技术债累积的区域也会被提前记录在案，不至于在迁移时变成意外。

在专家监督下进行战略规划

这一阶段，人类判断变得不可或缺。你的 COBOL 工程师对监管要求、业务优先级、运营约束和风险容忍度的理解，是 AI 无法替代的。

规划阶段会制定一份详尽的路线图，对现代化工作做出战略性排序：

  • AI 根据分析中识别出的风险、依赖和复杂度，给出优先级建议。
  • 你的团队审阅这些建议，并结合业务价值、技术风险和组织优先级，决定先现代化哪些组件。
  • 也是在这个阶段，你的团队要为现代化后的组件定义目标架构、代码标准和集成要求。

代码测试与验证也要在任何代码改动之前确定下来：

  • AI 设计初步的功能测试，验证迁移后的代码与遗留 COBOL 产出完全一致的输出。 
  • 你的团队决定这些测试是否足够、哪些业务场景需要领域专家手工验证，以及现代化后的组件需要达到什么性能基准。

增量实施与持续验证

执行时每次只处理一个组件，每一步都有验证。AI 将 COBOL 逻辑翻译成现代语言，为留在原地的遗留组件创建 API 包装层，并搭建脚手架，让新旧代码在过渡期并行运行。

每一步要么成功并通过验证，要么在影响范围还很小时就被发现并纠正。 

你永远不会面临“一旦失败就要回滚数周工作”的大规模变更。随着团队看到现代化组件一个个通过测试，他们也会有信心去攻克系统中越来越复杂的部分。

开始你的 COBOL 现代化

上述方法适用于任何规模的 COBOL 系统。 

像 Claude Code 这样的工具可以自动化本文描述的大部分探索与分析工作，让你的团队获得规划和执行迁移所需的全面理解与信心。

从一个边界清晰、复杂度适中的单一组件或工作流入手。用 AI 对其进行彻底的分析和文档化，与你的工程师一起规划现代化方案，增量实施并在每一步进行测试，再仔细验证。 这既能建立组织信心，也会暴露出你的系统所需的调整。

COBOL 现代化的经济学已经改变。AI 通过自动化过去需要顾问大军完成的工作，让成本变得可行，同时解放你的工程师，让他们去做那些真正需要领域专长的迁移决策。‍
