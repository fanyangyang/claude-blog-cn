深入理解 Skills：它与提示词、Projects、MCP 和 subagents 的对比

Skills are an increasingly powerful tool for creating custom AI workflows and agents, but where do they fit in the Claude stack? We explain what tool to use when - and how they all work together.

自推出 Skills 以来，很多人希望了解 Claude 的 agentic 生态中各个组件是如何协同工作的。

无论你是在 Claude Code 中构建复杂工作流、用 API 打造企业级解决方案，还是在 Claude.ai 上提升个人生产力，弄清楚什么时候该用哪个工具，都能彻底改变你与 Claude 协作的方式。

本指南将逐一拆解每个构建模块，解释各自的使用时机，并展示如何组合它们来打造强大的 agentic 工作流。

认识你的 agentic 构建模块

什么是 Skills？

Skills 是包含指令、脚本和资源的文件夹，Claude 会在与任务相关时动态发现并加载它们。可以把它们理解为专业培训手册，赋予 Claude 特定领域的专长——从操作 Excel 表格到遵循你组织的品牌规范。

Skills 的工作方式：当 Claude 遇到一个任务时，它会扫描可用的 Skills，寻找相关的匹配项。Skills 采用渐进式披露（progressive disclosure）：元数据先加载（约 100 token），刚好让 Claude 知道某个 Skill 何时相关。完整指令在需要时加载（<5k token），捆绑的文件或脚本则仅在必要时加载。

何时使用 Skills：当你需要 Claude 稳定高效地执行专门任务时，请选择 Skills。它们非常适合：

  • 组织级工作流：品牌规范、合规流程、文档模板
  • 领域专长：Excel 公式、PDF 处理、数据分析
  • 个人偏好：笔记体系、编码模式、研究方法

示例：创建一个包含公司配色、字体规则和排版规范的品牌规范 Skill。当 Claude 制作演示文稿或文档时，会自动应用这些标准，你不必每次都重新说明。

什么是提示词（prompts）？

提示词是你在对话中用自然语言向 Claude 下达的指令。它们是临时性的、对话式的、反应式的——你在当下提供上下文和方向。

何时使用提示词：以下场景请使用提示词：

  • 一次性请求："总结这篇文章"
  • 对话式调整："把语气改得更专业一些"
  • 即时上下文："分析这份数据并找出趋势"
  • 临时指令："把这些整理成项目符号列表"

示例：

请对这段代码进行一次全面的安全审查。我希望看到：

1. 常见漏洞，包括：

  • 注入缺陷（SQL、命令、XSS 等）
  • 身份验证与授权问题
  • 敏感数据暴露
  • 安全配置错误
  • 访问控制失效
  • 加密相关缺陷
  • 输入校验问题
  • 错误处理与日志问题

2. 针对发现的每个问题，请提供：

  • 严重程度（Critical/High/Medium/Low）
  • 代码中的位置（行号或函数名）
  • 为什么它是安全风险、可能如何被利用的解释
  • 具体的修复建议，尽可能附上代码示例
  • 预防类似问题的最佳实践指引

3. 代码背景：[描述代码的功能、语言/框架以及运行环境，例如："这是一个 Node.js REST API，负责用户身份验证并处理支付数据"]

4. 其他考虑事项：

  • 是否存在 OWASP Top 10 漏洞？
  • 代码是否遵循 [特定框架/语言] 的安全最佳实践？
  • 是否有已知存在漏洞的依赖项？

请按严重程度和潜在影响对发现进行排序。

小技巧：提示词是你与 Claude 交互的主要方式，但它们不会跨对话保留。对于重复性的工作流或专门知识，可以考虑把提示词沉淀为 Skills 或项目指令。

何时改用 Skill：如果你发现自己在多次对话中反复输入同一个提示词，就该创建一个 Skill 了。把诸如"按照 OWASP 标准审查这段代码的安全漏洞"或"把这份分析整理成执行摘要、关键发现和建议"这类经常出现的指令转化为 Skill，可以免去每次重新解释流程的麻烦，并保证执行的一致性。

什么是 Projects？

Projects 在所有付费 Claude 计划中可用，它们是自带聊天历史和知识库的独立工作区。每个项目拥有一个 200K 的上下文窗口，你可以在其中上传文档、提供背景信息，并设置对该项目内所有对话生效的自定义指令。

Projects 的工作方式：你上传到项目知识库的所有内容，都会对项目内的所有聊天可用。Claude 会自动利用这些上下文，给出更充分、更切题的回答。当项目知识接近上下文上限时，Claude 会无缝启用检索增强生成（RAG）模式，将容量最多扩展 10 倍。

何时使用 Projects：在以下需求时选择 Projects：

  • 持久上下文：应当为每一次对话提供背景的知识
  • 工作区组织：为不同事项划分独立的上下文
  • 团队协作：共享知识与对话历史（Team 和 Enterprise 计划）
  • 自定义指令：项目特定的语气、视角或方法

示例：创建一个"Q4 产品发布"项目，放入市场调研、竞品分析和产品规格。该项目内的每次聊天都能使用这些知识，你不必重新上传或重新解释背景。

何时改用 Skill：Projects 为某项具体工作（你们的代码库、一项研究计划、一个持续的客户项目）提供持久上下文；Skills 教会 Claude 如何做事。一个 Project 可能装着产品发布的全部背景资料，而一个 skill 可以教会 Claude 你们团队的写作规范或代码审查流程。如果你发现自己在多个 Projects 之间复制同样的指令，那就是该创建 skill 的信号。

什么是 subagents？

Subagents 是专门的 AI 助手，拥有自己的上下文窗口、自定义系统提示词和特定的工具权限。它们在 Claude Code 和 Claude Agent SDK 中可用，独立处理具体任务并将结果返回给主 agent。

Subagents 的工作方式：每个 subagent 都按自己的配置运行——你定义它做什么、如何解决问题、可以访问哪些工具。Claude 会根据它们的描述自动把任务委派给合适的 subagent，你也可以显式指定某个 subagent。

何时使用 subagents：以下场景请使用 subagents：

  • 任务专门化：代码审查、测试生成、安全审计
  • 上下文管理：让主对话保持聚焦，把专门工作分流出去
  • 并行处理：多个 subagent 可以同时处理不同侧面
  • 工具限制：把特定 subagent 限制在安全操作内（例如只读访问）

示例：

Create a code-reviewer subagent with access to Read, Grep, and Glob tools but not Write or Edit. When you modify code, Claude automatically delegates to this subagent for quality and security review without risking unintended code changes.

何时改用 Skill：如果多个 agent 或对话需要同样的专长——比如安全审查流程或数据分析方法——请创建 Skill，而不要把这些知识内置到一个个 subagent 里。Skills 可移植、可复用，而 subagents 是为特定工作流量身定制的。要教给任何 agent 都能用的专长，用 Skills；需要独立执行任务并配合特定工具权限和上下文隔离时，用 subagents。

什么是 MCP？

Model Context Protocol（MCP）是一个开放标准，用于把 AI 助手连接到数据所在的外部系统——内容仓库、业务工具、数据库和开发环境。

MCP 的工作方式：MCP 提供了一种标准化的方式，把 Claude 连接到你的工具和数据源。你不需要为每个数据源单独构建定制集成，只需面向单一协议开发。MCP server 暴露数据和能力；MCP 客户端（比如 Claude）连接这些 server。

何时使用 MCP：当你需要 Claude 做以下事情时，选择 MCP：

  • 访问外部数据：Google Drive、Slack、GitHub、数据库
  • 使用业务工具：CRM 系统、项目管理平台
  • 连接开发环境：本地文件、IDE、版本控制
  • 集成自定义系统：你的专有工具和数据源

示例：通过 MCP 把 Claude 连接到公司的 Google Drive。Claude 就可以搜索文档、读取文件、引用内部知识，无需手动上传——连接持久存在并自动更新。

何时改用 Skill：MCP 把 Claude 连接到数据；Skills 教会 Claude 拿这些数据做什么。如果你是在解释如何使用某个工具或遵循某套流程——比如"查询我们的数据库时，总是先按日期范围过滤"或"用这些特定公式格式化 Excel 报表"——那是 Skill。如果你需要 Claude 首先访问数据库或 Excel 文件，那是 MCP。把两者搭配使用：MCP 负责连接，Skills 负责流程知识。

Agentic 工作流示例：研究 agent

让我们构建一个组合了多个构建模块的完整研究 agent。这个例子展示如何组装并激活一个用于竞争分析的 agent。

第 1 步：搭建你的 Project

创建一个"竞争情报"项目并上传：

  • 行业报告和市场分析
  • 竞品产品文档
  • 来自 CRM 的客户反馈
  • 以往的研究总结

添加项目指令：

从我们产品战略的视角分析竞争对手。重点关注差异化机会和新兴市场趋势。呈现结论时附上具体证据和可执行的建议。

第 2 步：通过 MCP 连接数据源

为以下服务启用 MCP server：

  • Google Drive（访问共享研究文档）
  • GitHub（审查竞争对手的开源仓库）
  • 网络搜索（获取实时市场信息）

第 3 步：创建专门的 Skills

创建一个"competitive-analysis"skill：

# My Company GDrive Navigation Skill

## Overview
Optimized search and retrieval strategy for Meridian Tech's Google Drive structure. Use this skill to efficiently locate internal documents, research, and strategic materials.

## Drive Organization

**Top-level structure:**
- `/Strategy & Planning/` - OKRs, quarterly plans, board decks
- `/Product/` - PRDs, roadmaps, technical specs
- `/Research/` - Market research, competitive intel, user studies
- `/Sales & Marketing/` - Case studies, pitch decks, campaign materials
- `/Customer Success/` - Implementation guides, success metrics
- `/Company Ops/` - Policies, org charts, team directories

**Naming conventions:**
- Format: `YYYY-MM-DD_DocumentName_vX`
- Final versions marked with `_FINAL`
- Drafts include `_DRAFT` or `_WIP`

## Search Best Practices

1. **Start broad, then filter** - Use folder context + keywords
2. **Target document owners** - Sales materials from Sales/, not root
3. **Check recency** - Prioritize documents from last 6 months for current strategy
4. **Look for "source of truth"** - Files with `_FINAL`, `_APPROVED`, or in `/Archives/Official/`

## Research Agent Workflow

1. Identify topic category (product, market, customer)
2. Search relevant folder with targeted keywords
3. Retrieve 3-5 most recent/relevant documents
4. Cross-reference with `/Strategy & Planning/` for context
5. Cite sources with file names and dates

接下来会发生这些事：

常见问题

Skills 是如何工作的？

Skills 使用渐进式披露来保持 Claude 的高效。在处理任务时，Claude 先扫描 Skill 的元数据（描述和摘要）以识别相关匹配项。如果某个 Skill 匹配，Claude 再加载完整指令。最后，如果该 Skill 包含可执行代码或参考文件，这些只在需要时才加载。

这一架构意味着你可以准备大量 Skills，而不会撑爆 Claude 的上下文窗口。Claude 会在需要的时候，精确地取用需要的内容。

Skills 与 subagents：该用哪个

使用 Skills 的场景：你希望任何 Claude 实例都能加载并使用的能力。Skills 就像培训材料——它们让 Claude 在所有对话中都更擅长特定任务。

使用 subagents 的场景：你需要为特定目的设计、能独立处理工作流的完整自足 agent。Subagents 就像拥有自己上下文和工具权限的专职员工。

组合使用的场景：你希望 subagent 拥有专门技能。例如，一个代码审查 subagent 可以使用针对语言最佳实践的 Skills，把 subagent 的独立性与 Skills 的可移植专长结合起来。

Skills 与提示词：该用哪个

使用提示词的场景：你下达一次性指令、提供即时上下文，或进行来回对话。提示词是反应式的、临时的。

使用 Skills 的场景：你有会反复用到的流程或专长。Skills 是主动式的——Claude 知道何时应用它们——并且跨对话持久存在。

组合使用：提示词与 Skills 天然互补。用 Skills 提供基础专长，再用提示词为每个任务提供具体上下文和细化要求。

Skills 与 Projects：该用哪个

使用 Projects 的场景：你需要为某个特定事项的所有对话提供背景知识和上下文。Projects 提供始终加载的静态参考资料。

使用 Skills 的场景：你需要只在相关时才激活的流程知识和可执行代码。Skills 提供按需加载的动态技能，节省你的上下文窗口。

组合使用：你既想要持久上下文，又想要专门能力。例如，一个包含产品规格和用户调研的"产品开发"项目，搭配用于撰写技术文档和分析用户反馈数据的 Skills。

关键区别：Projects 说的是"你需要知道这些"。Skills 说的是"这些事要这么做"。Projects 提供你工作所依托的知识库；Skills 提供到处可用的能力——任何对话、任何项目。

Subagents 能使用 Skills 吗？

能。在 Claude Code 和 Agent SDK 中，subagent 可以像主 agent 一样访问和使用 Skills。这能形成强大的组合：专门的 subagent 借助可移植的专长。

例如，你的 python-developer subagent 可以使用 pandas-analysis Skill，按照你们团队的约定执行数据转换；而你的 documentation-writer subagent 使用 technical-writing skill，以一致的格式撰写 API 文档。
