像带新开发者一样上手 Claude Code：来自 17 年开发经验的心得

The methodology that onboards new developers to MacCoss Lab's 700,000-line codebase works on Claude Code, too. Here's how Brendan MacLean, a Claude Developer Ambassador whose lab is part of our Claude for Open Source program, did it.

Skyline 是由华盛顿大学 MacCoss 实验室首席开发者 Brendan MacLean 维护的开源蛋白质分析软件，自 2008 年以来一直处于活跃开发状态。Skyline 帮助研究人员检测和定量分析血浆、组织等样本中的蛋白质，这对生物标志物发现、疾病研究和药物开发至关重要。MacCoss 实验室的代码库包含超过 70 万行 C# 代码，由一个小团队维护了 17 年，每晚运行超过 20 万个自动化测试。

近三十年来，Brendan 一直是 Skyline 的连接组织，先后为实验室引入了数十名本科生、研究生和博士后。*  

随着开发者来了又走，代码库吸收了他们的贡献。到 2024 年，它背负上了长寿项目常见的那些包袱。随着人员更替，某些区域已经变得无人敢碰。

经过数十年培训实验室成员，Brendan 深知如何让研究人员快速上手实验室庞大的代码库。他没有料到的是，把同样的方法论应用到一个 AI 工具上，竟让 Skyline 的代码库重新变得可以驾驭。

同样的上手问题，另一种开发者

Brendan 一开始怀疑现代 AI 编程工具能否像那些专门为这门语言和这个环境打造的工具那样理解 C# 代码。

早期在浏览器中使用 Claude.ai 的实验印证了他的疑虑。他会描述一个问题，得到一段回复，再把一整个 C# 文件复制回自己的项目里，因此只能局限于那些无需引用项目代码就能描述清楚的孤立问题。 

"一旦改动变得越来越细碎，这个过程就变得非常繁琐。"Brendan 说。 

与 Claude.ai 的每次会话都像是从零开始，因为它完全不了解 Skyline 是什么、各个组件之间有何关联，也不知道 17 年的开发积累了什么。 

这正是 Brendan 在带新开发者时遇到的同样处境，这也给了他一个想法。 

"我可以像带一个实习开发者那样，通过 Claude Code 把 Claude 介绍给我的大型项目：讲解足够多的内容，让它成功完成一个有限范围的项目，并为下一轮迭代产出改进的上下文。"Brendan 说。

他把所有 AI 上下文移到了一个独立的仓库 pwiz-ai 中，与代码库分开维护，这样它就能适用于所有分支和时间点。根目录下的 CLAUDE.md 文件负责环境配置，并引导 Claude 查阅相关文档：可以把它理解为"地形概览"，而不是专业知识本身。 

专业知识存放在 skills 中——这是一种为 agent 赋予能力和专业知识的开放格式。例如，他的 debugging skill 旨在把 Claude 从他所说的"瞎猜乱试"模式中拉出来，促使它在尝试任何修复之前先做根因分析。Skills 可以手动或自动触发；Brendan 为最关键的几个 skill 设定了明确的触发条件——debugging skill 的描述写着"在调查 bug、失败或意外行为时必须加载（ALWAYS load）"。 

上下文建立之后，教 Claude 熟悉代码库调试细节的门槛就大大降低了。Claude 已经知道代码的作用，交互从理解出发，而不是从零开始。

"当初看来是个大问题的事——'Claude 无法真正了解我的大型项目'——如今越来越清晰：上下文只是另一个需要维护和扩充的产物。"Brendan 说。

减少技术债，加速开发

Skyline 有一个为期一年的项目——构建 Files View 面板：一个展示所有文档相关文件的新界面，带有文件系统监控和拖拽整理功能——在负责它的开发者离开后一直搁置。Brendan 带着 Claude Code 重新捡起了它。 

两周后项目完成，所有最终提交都由 Claude 共同署名。 

"以前遗留下来的这种半成品，通常最终的命运都是被废弃。"Brendan 说。在学术实验室里，开发者经常轮换——研究生毕业、博士后离开、实习生夏天结束就走。放在过去，任何进行到一半的工作都会被永久封存。

三年前，在失去负责维护的开发者后，Brendan 停止了为 Skyline 的夜间测试管理模块添加新功能。该模块用 Java 编写，是 LabKey Server 科学数据门户的一部分。最近，在请一位熟练的 LabKey 开发者用 Claude Code 编写了配置文档之后，Brendan 只花了不到一天就添加了他盼望多年的功能，还用 CSS 更新了页面布局——过去这类活他一直都是请设计师来做的。

新的基础设施也随之而来。 

Skyline 2000 多张教程图片的截图复现如今已完全自动化，几乎 100% 可复现，并通过 Claude Code 扩展了仅显示差异（diff-only）视图和像素变化放大功能，还让 Claude 用 C# 编写了一个 MCP 服务器，让它能够"看见"这些差异。Claude Code 每天早晨生成一份每日摘要，汇总从 Skyline 夜间测试基础设施中提取的测试失败、异常和未解决的支持讨论串，在 Brendan 坐下来开始工作之前就已送达他的收件箱。 

为了让这项能力成为可能，Claude 还用 Python 编写了对应的 MCP 服务器，从 LabKey Server 上的三个独立关系数据流、团队邮件以及 GitHub 上带发布标签的代码中提取数据。

Brendan 手下的开发者如今几乎不再亲自写代码，主要改为向 Claude Code 下达指令，并用这个工具自主生成自动化脚本和 MCP 实现。例如，实验室里一位曾对 agentic 编程工具持怀疑态度的开发者，构建并发布了一个全新的绘图扩展——用于可视化离子迁移数据的 mobilogram 面板——并将其归功于 Claude Code。 

"我几乎看到所有人都在接手那些有趣的新功能，放在以前，他们可能会因为深陷其他工作而觉得无暇尝试。"Brendan 说。

给维护遗留代码库的开发者的建议

基于 17 年的开发者带教经验和一年多将同样方法论应用于 Claude Code 的实践，以下是 Brendan 想对维护遗留代码库的开发者说的话。

上下文是你最好的朋友

Claude 生成的待办清单和计划不会跨会话保留。上下文才是能够留存的东西，而且需要刻意维护。这正是大多数开发者跳过的环节，也是大多数开发者的成效停滞不前的原因。

"要明白，如果你不记录'上下文'，Claude 就无从学习。别指望魔法。"Brendan 说。"要投入精力构建和维护你的上下文层。把它当作任何其他项目产物来对待：做版本管理、持续扩充、认真维护。"

Brendan 把 AI 上下文放在独立仓库里，是因为它的增长速度与代码不同，而且要适用于所有分支和时间点——放在代码仓库内部逐渐成了掣肘。把上下文放在同一个仓库里也是一种可行的选择；关键在于它要有版本管理、有人维护、需要时随时可用。 

投入构建你的 skill 库

用 skills 来沉淀领域知识，任何 Claude 实例都可以加载。Brendan 的 skills 遵循"引用而非复制"（reference do not embed）原则：每个 skill 都指向一个中央文档知识库，而不是复制内容，从而保持轻量、易于维护。 

他用得最多的包括：一个帮助 Claude 了解项目及其文档的 skyline-development skill；一个沉淀项目专属提交和 PR 规范的 version-control skill；以及一个旨在把 Claude 从"瞎猜乱试"模式中拉出来、促使它在尝试任何修复前先做根因分析的 debugging skill。

当数据访问是关键时，使用 MCP 集成

在 Claude 需要访问真实数据的地方构建 MCP 集成：测试结果、异常报告、支持讨论串。 

对开源项目而言，构建和维护上下文层的意义尤为重大。没有带教预算，没有写下来之外的机构记忆，也没有任何贡献者明年还在的保证。上下文一旦建成，就对每一位贡献者可用，并在项目的整个生命周期中持续存在——这是人类的机构知识永远做不到的。pwiz-ai 仓库本身就是一件开源产物——属于项目的上下文，而不属于任何一个贡献者，其寿命超过所有构建它的人。

十七年的带教，一个结论

你不会把一个 70 万行的代码库丢给一个新入职的人，然后指望他第一天就出成果。你会给他找一个范围有限的项目，带他走一遍，随着他理解的加深逐步扩大他的职责范围。 

正如 Brendan 所领悟的，你与 Claude 一起构建的上下文也是同样的道理。

工程师一旦对代码库足够熟悉，就能跨越分支和时间点开展工作。Claude 在获得足够的上下文和指引后，同样可以做到。
