为 Claude Code 带来 Code Review

Practical guidance on how to structure agent tasks using three common workflow patterns, with tradeoffs and benefits for each.

今天我们推出 Code Review，它会在每个 PR 上派遣一队 agent，找出那些走马观花式审查漏掉的 bug——它为深度而非速度而生。这正是我们在 Anthropic 几乎每个 PR 上都在运行的系统。现以 research preview 形式面向 Team 和 Enterprise 开放。

化解审查瓶颈

过去一年，Anthropic 每位工程师的代码产出增长了 200%。代码审查成了瓶颈，客户每周都在向我们反馈同样的问题。他们告诉我们，开发者分身乏术，很多 PR 只被草草扫过，而没有得到深入阅读。

我们需要一个可以放心托付给每个 PR 的审查者。Code Review 由此而来：深度、多 agent 的审查，能发现人类审查者自己也常常漏掉的 bug。相比现有的 Claude Code GitHub Action（仍将保持开源并持续可用），它是一个更彻底（也更贵）的选择。

我们在 Anthropic 几乎每个 PR 上都运行 Code Review。此前，只有 16% 的 PR 能获得实质性的审查意见，现在这一比例是 54%。它不会批准 PR——那仍然由人来决定——但它缩小了差距，让审查者真正能覆盖正在发布的内容。

工作原理

当 PR 被打开时，Code Review 会派遣一队 agent。这些 agent 并行寻找 bug、验证 bug 以过滤误报，并按严重程度对 bug 排序。最终结果会以一条高信息量的总览评论发布到 PR 上，并附上针对具体 bug 的行内评论。

审查力度随 PR 规模伸缩。大型或复杂的变更会获得更多 agent 和更深入的阅读；琐碎的变更则只做轻量过一遍。根据我们的测试，平均每次审查耗时约 20 分钟。

Code Review 实战

我们已在内部运行 Code Review 数月：在大型 PR（变更超过 1000 行）上，84% 能产出发现，平均 7.5 个问题；在 50 行以下的小型 PR 上，这一比例降至 31%，平均 0.5 个问题。工程师们基本认同它的发现：被标记为不正确的发现不足 1%。

在一个案例中，对某个生产服务的一行改动看起来稀松平常，属于通常会被快速批准的那类 diff。但 Code Review 将其标记为严重问题。这个改动本会破坏该服务的身份验证——这种失败模式在 diff 里很容易被读漏，但一经指出就显而易见。问题在合并前得到修复，工程师事后表示，他自己根本发现不了。

早期访问的客户也看到了类似的模式。在 TrueNAS 开源中间件的一次 ZFS 加密重构中，Code Review 发现了相邻代码中一个原本就存在的 bug：一处类型不匹配，会在每次同步时悄悄清空加密密钥缓存。这是 PR 恰好触及的代码中的一个潜在问题，人类审查者在浏览变更集时通常不会主动去查这类东西。

成本与管控

Code Review 以深度为优化目标，比 Claude Code GitHub Action 等更轻量的方案更贵。审查按 token 用量计费，平均约为 15–25 美元，并随 PR 的规模和复杂度而变化。

管理员有多种方式控制支出和使用：

  • 组织月度上限：为所有审查设定每月总支出上限
  • 仓库级控制：仅在选定的仓库上启用审查
  • 分析看板：跟踪已审查的 PR 数量、采纳率以及总审查成本

开始使用

Code Review 现已作为 research preview 的 beta 版面向 Team 和 Enterprise 计划提供。

  • 面向管理员：在Claude Code 设置中启用 Code Review，安装 GitHub App，并选择希望运行审查的仓库。
  • 面向开发者：启用后，新 PR 会自动运行审查，无需任何配置。
