用 Claude Agent SDK 构建智能体

The Claude Agent SDK is a collection of tools that helps developers build powerful agents on top of Claude Code. In this article, we walk through how to get started and share our best practices.

去年，我们与客户分享了构建高效智能体的经验。此后我们发布了 Claude Code，这套智能体式编程解决方案最初是为了提升 Anthropic 内部的开发者生产力而构建的。

过去几个月里，Claude Code 的角色早已不只是一个编程工具。在 Anthropic，我们一直在用它进行深度研究、视频制作和笔记记录等无数非编程场景。事实上，它已经开始支撑我们几乎所有主要的智能体循环。

换句话说，驱动 Claude Code 的智能体外壳（即 Claude Code SDK）也可以驱动许多其他类型的智能体。为了体现这一更宏大的愿景，我们将 Claude Code SDK 更名为 Claude Agent SDK。

在这篇文章中，我们将介绍为什么要构建 Claude Agent SDK、如何用它构建你自己的智能体，并分享我们团队在实际部署中总结出的最佳实践。

给 Claude 一台计算机

Claude Code 背后的核心设计原则是：Claude 需要程序员每天都在使用的那些工具。它需要能够在代码库中找到合适的文件、编写和编辑文件、对代码进行 lint、运行、调试、修改，有时还要反复迭代这些操作直到代码成功运行。

我们发现，让 Claude 获得用户计算机的访问权限（通过终端）之后，它就具备了像程序员一样写代码所需的条件。

但这也让 Claude Code 中的 Claude 在非编程任务上同样表现出色。有了运行 bash 命令、编辑文件、创建文件和搜索文件这些工具，Claude 可以读取 CSV 文件、搜索网络、构建可视化、解读指标，以及完成各种其他数字化工作——简而言之，就是打造拥有计算机的通用智能体。Claude Agent SDK 的核心设计原则正是给你的智能体一台计算机，让它们像人类一样工作。

创造新型智能体

我们相信，给 Claude 一台计算机将解锁构建比以往更强大智能体的能力。例如，借助我们的 SDK，开发者可以构建：

  • 金融智能体： 构建能理解你的投资组合和目标的智能体，通过访问外部 API、存储数据并运行代码进行计算，帮助你评估投资。
  • 个人助理智能体：构建能帮你预订差旅、管理日历的智能体，通过连接你的内部数据源并跨应用跟踪上下文，还能安排会议、整理简报等。
  • 客户支持智能体：构建能处理高模糊度用户请求（如客服工单）的智能体，通过收集和审阅用户数据、连接外部 API、回复用户消息，并在必要时升级给人工处理。
  • 深度研究智能体：构建能在海量文档中进行全面研究的智能体，通过搜索文件系统、分析和综合多个来源的信息、跨文件交叉比对数据，并生成详尽的报告。

还有更多可能。从根本上说，这个 SDK 提供的是一套原语，让你能为任何想要自动化的工作流构建智能体。

构建你的智能体循环

在 Claude Code 中，Claude 通常在一个特定的反馈循环中运作：收集上下文 -> 采取行动 -> 验证工作 -> 重复。

这也为思考其他智能体及其应具备的能力提供了一个有用的框架。为了说明这一点，我们将以如何在 Claude Agent SDK 中构建一个邮件智能体为例进行讲解。

收集上下文

开发智能体时，你不应只给它一个提示词：它还需要能够自行获取并更新自己的上下文。以下是 SDK 中的一些功能如何提供帮助。

智能体式搜索与文件系统

文件系统代表着可能被载入模型上下文的信息。

当 Claude 遇到日志或用户上传的文件等大文件时，它会借助 grep、tail 等 bash 脚本决定以何种方式将它们载入上下文。本质上，智能体的文件夹和文件结构本身就成了上下文工程的一种形式。

我们的邮件智能体可以把历史会话存储在一个名为 “Conversations” 的文件夹中。这样当被问及相关内容时，它就可以在其中搜索自己的上下文。

语义搜索

语义搜索通常比智能体式搜索更快，但准确度较低、维护难度更大、透明度也更差。它需要把相关上下文“分块”（chunking）、将这些块嵌入为向量，然后通过查询这些向量来搜索概念。考虑到这些局限，我们建议先从智能体式搜索入手，只有在需要更快的速度或更多变体时再引入语义搜索。

子智能体（Subagents）

Claude Agent SDK 默认支持子智能体。Subagents 之所以有用，主要有两个原因。第一，它们支持并行化：你可以同时启动多个子智能体处理不同的任务。第二，它们有助于管理上下文：子智能体使用各自独立的上下文窗口，只把相关信息（而非完整上下文）回传给编排者。这使它们非常适合处理需要从大量信息中筛选、而其中大部分并无用处的任务。

在设计邮件智能体时，我们可以赋予它“搜索子智能体”的能力。邮件智能体随后可以并行拆分出多个搜索子智能体——各自对邮件历史运行不同的查询——并让它们只返回相关摘录而非完整邮件往来。

压缩（Compaction）

当智能体长时间运行时，上下文维护就变得至关重要。Claude Agent SDK 的 compact 功能会在接近上下文上限时自动总结先前的消息，这样你的智能体就不会耗尽上下文。该功能构建于 Claude Code 的 compact 斜杠命令之上。

采取行动

收集完上下文之后，你需要为智能体提供灵活的行动方式。

工具（Tools）

工具是智能体执行任务的主要构件。工具在 Claude 的上下文窗口中占据显著位置，因而是 Claude 在决定如何完成任务时会优先考虑的动作。这意味着你在设计工具时要有意识地最大化上下文效率。更多最佳实践请参阅我们的博客文章 Writing effective tools for agents – with agents。

因此，你的工具应该就是希望智能体执行的那些主要动作。了解如何在 Claude Agent SDK 中制作自定义工具。

对于我们的邮件智能体，可以把 “fetchInbox” 或 “searchEmails” 等工具定义为其最主要、最频繁的动作。

代码生成

Claude Agent SDK 尤其擅长代码生成——这是有充分理由的。代码精确、可组合、可无限复用，是需要可靠执行复杂操作的智能体的理想输出形式。

在构建智能体时不妨思考：哪些任务用代码来表达会更有优势？答案往往会解锁巨大的能力。

例如，我们最近在 Claude.AI 上推出的文件创建功能就完全依赖代码生成。Claude 编写 Python 脚本来创建 Excel 电子表格、PowerPoint 演示文稿和 Word 文档，确保格式一致并实现用其他方式很难做到的复杂功能。

MCP

Model Context Protocol（MCP）为外部服务提供了标准化的集成方式，自动处理身份验证和 API 调用。这意味着你可以将智能体连接到 Slack、GitHub、Google Drive 或 Asana 等工具，而无需自己编写集成代码或管理 OAuth 流程。

对于我们的邮件智能体，可能需要 search Slack messages 来了解团队背景，或者 check Asana tasks 来查看是否已有人被指派处理某个客户请求。有了 MCP 服务器，这些集成开箱即用——你的智能体只需调用 search_slack_messages 或 get_asana_tasks 之类的工具，其余交由 MCP 处理。

不断壮大的 MCP 生态意味着，随着预构建集成的不断丰富，你可以快速为智能体添加新能力，从而专注于智能体行为本身。

验证你的工作

Claude Code SDK 通过评估自己的工作来完成智能体循环。能够检查并改进自身输出的智能体从根本上说更可靠——它们能在错误累积之前发现问题，在偏离方向时自我纠正，并在迭代中不断变好。

关键在于给 Claude 提供评估其工作的具体手段。以下是我们发现有效的三种方法：

定义规则

最好的反馈形式，是为输出定义清晰的规则，然后说明哪些规则没有通过以及原因。

代码 lint是一种极佳的基于规则的反馈，反馈越深入越好。例如，生成 TypeScript 再进行 lint 通常优于生成纯 JavaScript，因为它能提供多个额外的反馈层。

在生成邮件时，你可能希望 Claude 检查邮箱地址是否有效（无效则抛出错误），以及用户之前是否给对方发过邮件（发过则给出警告）。

视觉反馈

当使用智能体完成视觉类任务（如 UI 生成或测试）时，视觉反馈（以截图或渲染图的形式）会很有帮助。例如，发送 HTML 格式的邮件时，你可以对生成的邮件截图并回传给模型，进行视觉验证和迭代优化。模型随后会检查视觉输出是否符合要求。

例如：

  • 布局——元素位置是否正确？间距是否合适？
  • 样式——颜色、字体和格式是否与预期一致？
  • 内容层级——信息的呈现顺序和强调是否得当？
  • 响应式——看起来是否有破损或拥挤？（不过单张截图的视口信息有限）

使用 Playwright 之类的 MCP 服务器，你可以将这一视觉反馈循环自动化——对渲染后的 HTML 截图、采集不同视口尺寸，甚至测试交互元素——全部纳入智能体的工作流之中。

LLM 作为评审

你还可以让另一个语言模型根据模糊规则来“评审”智能体的输出。这种方法总体上并不十分稳健，且可能带来明显的延迟代价，但对于任何性能提升都值得付出成本的应用来说，它可能会有所帮助。

我们的邮件智能体可以安排一个独立的子智能体来评判草稿的语气，看是否与用户以往的邮件风格相符。

测试并改进你的智能体

在经历几轮智能体循环之后，我们建议对智能体进行测试，确保它为任务做好了充分准备。改进智能体的最好方法是仔细审视它的输出，尤其是失败的场景，并设身处地想一想：它是否拥有完成任务所需的合适工具？

在评估智能体是否胜任其工作时，还可以问自己这些问题：

  • 如果你的智能体误解了任务，可能是缺少关键信息。能否调整搜索 API 的结构，让它更容易找到需要知道的内容？
  • 如果你的智能体反复在某个任务上失败，能否在工具调用中加入一条形式化规则来识别并修复该失败？
  • 如果你的智能体无法修正自己的错误，能否给它一些更有用或更有创造性的工具，换一种方式解决问题？
  • 如果你的智能体性能随着功能增加而波动，请基于客户使用情况构建一个有代表性的测试集，用于程序化评估（evals）。

开始使用

Claude Agent SDK 让构建自主智能体变得更容易——它让 Claude 获得一台计算机，可以在上面写文件、运行命令并迭代自己的工作。

牢记智能体循环（收集上下文、采取行动、验证工作），你就能构建出易于部署和迭代的可靠智能体。
