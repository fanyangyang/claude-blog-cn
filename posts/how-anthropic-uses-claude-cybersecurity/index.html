Anthropic 网络安全团队如何用 Claude Code 打造威胁检测平台

Jackie Bow, technical lead for Anthropic's Detection Platform Engineering team, shares how her team uses Claude Code to build tools that automate alert triage, accelerate investigations, and transform how security analysts work.

在 Jackie Bow 的整个职业生涯里，她一直在想象这样的工具：能够接入真正要紧的上下文——不只是日志和告警，还有 Slack 对话、内部文档和机构知识，从而判断某个东西到底是真实威胁还是噪音——而且不需要人来承担手工翻查数据的重担。

加入 Anthropic 后，她终于有机会把它们造出来——与 Claude 搭档。Jackie 领导 Anthropic 的检测平台工程团队，专注于防御性网络安全：检测威胁、响应潜在入侵，而非探测漏洞。这项工作包括监控系统中的可疑活动、分诊安全告警，以及在异常演变为事件之前进行调查。

对于一家构建能力越来越强的 AI 模型的公司来说，这项工作是根基所在。Anthropic 的负责任扩展政策（Responsible Scaling Policy）把产品发布与安全承诺直接挂钩，这意味着 Bow 的团队帮助决定公司能安全地发布什么。

"我觉得这是安全工程师的黄金时代，"担任 Anthropic 检测平台工程技术负责人的 Bow 说，"我终于可以打造那些我一直希望自己能拥有的工具了。"

问题：淹没在数据和告警里

安全负责人对这种场景再熟悉不过了。

一条告警触发。分析师打开终端，开始那套熟悉的流程：在五六个工具之间来回切换，每个工具都有自己的查询语言和思维模型。他们必须同时精通多个平台，还要不断在不同界面和查询语法之间来回切换上下文。

每一次调查都像一场数据考古，把散落在互不相通的系统里的碎片拼起来。对大多数团队来说，简单的调查要花几个小时，复杂的可能拖上好几天。 

"一个人一天能看的告警就那么多，超量之后分析的细致程度就会下降，"Jackie 解释道。

她的团队决定改变这一点。他们问自己：什么在消耗我们的精力？哪些事情感觉在重复劳动？是什么妨碍我们做真正有影响力的工作？

答案很清晰。告警分诊在分析师判断威胁真假之前就能吃掉好几个小时；在互不相通的系统中做人工关联拖慢了一切；而在查询语言和界面之间不停切换上下文带来的认知负担，会随着一天的推进不断累积。

随着公司成长，攻击面在扩大，对安全团队的要求也在提高。

"不借助 Claude 这样的工具来增强，我们无法扩展到满足 Anthropic 的需求，"Jackie 说。

解决方案：Claude Looks Up Evidence（CLUE）

几个月时间里，Bow 的团队构建了 CLUE——一个重新定义安全团队调查威胁方式的检测与响应平台。CLUE 没有在技术栈上再叠一个仪表盘，而是提供了一个由 Claude 驱动的自然语言界面，通过工具调用直接连接 Anthropic 的内部系统。

用 Claude Code 构建 CLUE，把传统软件开发周期压缩了指数级的幅度，让他们在完成日常工作之余还有余力打造这套系统。Bow 的团队一天之内就跑起了概念验证；设计文档、开发步骤和实现一周之内全部完成。

"我们构建的很多东西，就是我们和 Claude Code 对话的过程，"Jackie 回忆道，"它既是设计伙伴，也是协作者。"

真正改变她认知的一刻，是她让 Claude Code 给 CLUE 界面加一个按钮。她原本以为又要陷入 JavaScript 框架和 CSS 调试的泥潭。Claude Code 立刻实现了这个功能，而且做得比她自己做的还好。

"那一刻我意识到，我不再被自己的技术能力限制住了。只要能想得到，我就能造出来，"她说。

CLUE Triage

告警涌入时，CLUE Triage 会在人类分析师看到它们之前完成第一轮分诊。Claude 使用工具从 Anthropic 各个系统为每条告警补充上下文，包括 Slack 消息、内部文档、代码仓库和数据仓库。它会给出处置判定：误报、真实威胁、恶意行为或预期行为。每条告警都会附上置信度评分，让分析师知道该把注意力放在哪里。

这个富化步骤解决了所有安全分析师都认识到的难题：告警抵达时都是孤立的信号。一次失败的登录，一个异常的 API 调用，一次配置变更。没有上下文，这些事件只是噪音；有了上下文（用户是谁、当时在做什么、是否符合其团队的既有模式），清晰的信号就会浮现。

"这些内部上下文正是缺失的那一块，它真正能让告警在你的环境里获得语境，"Jackie 解释道。

CLUE Investigate

有了 CLUE，安全分析师现在可以用自然语言查询所有安全关键日志。想知道"过去一天这个系统所有失败的登录记录"？直接问 CLUE，Claude 会执行必要的 SQL 查询。

"Claude 写精确查询的能力比人强得多，"Jackie 说。这个工具运行一个智能体循环：编排器向各个子智能体下达指令，它们并行执行查询、汇集发现，并把结果综合成条理清晰的调查摘要。过去需要数小时人工关联的工作，现在三四分钟就能完成。

数据也印证了这一点。在每次调查中，CLUE 平均执行 25 次工具调用和近 11 次查询——远超分析师手工合理执行的规模，而且精度更高。这些工具调用中的每一次，原本都需要打开一个单独的控制台或切换到另一个界面。

不过，真正的差异化优势是内部上下文。CLUE 通过工具直接连接 Anthropic 的系统，让 Claude 能访问外部安全平台永远无法触及的机构知识。告警触发时，Claude 可以查看 Slack，看团队是否讨论过计划内的维护；可以查询数据仓库，理解基线行为；可以检视代码仓库，弄清某项服务究竟做什么。

数据治理审查

团队用一个常见的数据治理场景演示了 CLUE 的能力：核查三名外包人员在过去两个月里是否访问过任何不该访问的文档。

据 Bow 介绍，这类调查通常至少需要半天的手工工作，包括查询访问日志、交叉核对权限、审查文档密级。而用 CLUE，Claude 读取请求、制定计划、生成详尽的查询，把技术复杂性都抽象掉。调查几分钟就结束了，产出一份摘要和建议，且每一次执行的查询都完全透明可查。

衡量影响

在着手构建 CLUE 时，团队想搞清楚的不只是"感觉更快了"，而是结果能不能量化。

误报更少：在 CLUE Triage 之前，大约三分之一的告警最终被证明是误报。如今这一比例降到了 7%，分析师可以把时间花在真正有价值的信号上。*

覆盖更广：可能比速度更重要的是团队如今有能力检查的范围。在使用 CLUE 之前，低置信度的信号根本无人查看，因为没有时间。现在，CLUE Triage 会对每一条涌入的告警做富化处理，批量处理还能应对数千条过去只会成为仪表盘里噪音的信号。

大规模节省时间：基于 30 天的使用数据，CLUE 自动化了大约 12000 次查询和 27000 次工具调用——这些工作若靠人工完成估计需要 1870 小时（234 人天）。相比人工分诊，这相当于节省 5 到 10 倍的时间。*

仍在学习如何衡量的部分：准确率比速度更难量化。团队会复核 CLUE 的处置判定并记录分歧，但他们仍在建立反馈闭环，以弄清 Claude 抓住了哪些分析师会漏掉的东西——反之亦然。调查记录帮得上忙：每一次调查都可以审计，查证 Claude 究竟看了什么、如何得出结论。

下一步：让 Claude 以 Claude 的方式调查

AI 研究领域有个概念叫"苦涩的教训（the bitter lesson）"——观察发现，把人类特定的推理方式硬编码进模型，效果总是不如赋予模型通用能力、让它们自己找到方法。Bow 和她的团队一直在思考这对检测与响应意味着什么。

"在 CLUE 开发早期，团队曾争论过要在多大程度上约束 Claude 的调查路径，"Bow 说。"SOAR 时代的直觉是：写好 playbook，定义每一步，让流程确定化。但我们不断注意到一件事：当我们给 Claude 探索的自由——给它工具和目标，而不是一串僵硬的步骤——它常常走出我们绝不会规定的调查路径。有时候，这些路径能挖出我们会错过的上下文。"

关键在于给 Claude 划定边界（能用哪些工具、能访问哪些数据），同时把策略留白。这一洞见决定了 CLUE 的下一步方向。

从被动到主动：今天，CLUE 响应告警——事件触发，Claude 调查。但这个架构支撑着更进一步的愿景：持续探索。Claude 智能体不必等待检测规则触发，而是可以主动搜寻可疑模式——那些不匹配任何已写规则的异常、单独看正常而聚合起来反常的行为。

从自身学习：团队保存了每一份调查记录。这些语料正在变成一个知识库，Claude 可以从中查询过往调查展开方式的模式。假以时日，CLUE 会积累起任何人类分析师都无法维持的组织记忆。

拥抱非确定性：传统安全工具把不一致视为缺陷，CLUE 却把它当作特性。同一条告警在不同日子可能被以不同方式调查，这没有问题——有时第二条路径能发现第一条遗漏的东西。团队正在试验并行运行多种调查策略并比较结果。

"安全运营版的苦涩的教训？我们花了多年构建把人类调查方式硬编码进去的系统。下一代工具应该赋予模型调查的能力，让它们找到比我们规定的更好的方法，"Bow 补充道。
