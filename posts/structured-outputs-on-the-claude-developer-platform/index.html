Claude 开发者平台上的结构化输出

阅读英文原文 →

更新：结构化输出（Structured outputs）现已在 Claude 开发者平台和 Amazon Bedrock 上原生正式发布（GA），支持 Claude Sonnet 4.5、Opus 4.5 和 Haiku 4.5。正式版新增了对更复杂 schema 的支持。（2026 年 2 月 4 日）

更新：现已在 Claude Haiku 4.5 上可用——支持 Claude 开发者平台（原生）和 Microsoft Foundry。（2025 年 12 月 4 日）

Claude 开发者平台现在支持 Claude Sonnet 4.5 和 Opus 4.1 的结构化输出（structured outputs）。该功能目前处于公开 Beta 阶段，可确保 API 响应始终符合你指定的 JSON schema 或工具定义。

借助结构化输出，开发者可以确保 Claude 的响应遵循预定义的 schema——无论是从图像中提取数据、编排智能体，还是与外部 API 集成——从而消除与 schema 相关的解析错误和工具调用失败。

构建可靠的应用

对于在生产环境中构建应用和智能体的开发者来说，数据格式中的单个错误就可能引发连锁故障。结构化输出通过保证响应严格符合你定义的结构来解决这一问题，且不影响模型性能。这使得 Claude 在对准确性要求极高的应用和智能体场景中值得信赖，包括：

  • 数据提取——下游系统依赖无错、一致的格式。
  • 多智能体架构——智能体之间一致的通信是高性能、稳定体验的关键。
  • 复杂搜索工具——多个搜索字段必须被准确填写并符合特定模式。

结构化输出有两种使用方式：配合 JSON 或配合工具使用。与 JSON 配合时，你在 API 请求中提供 schema 定义。与工具配合时，你定义工具规范，Claude 的输出将自动遵循这些工具定义。

最终结果是可靠的输出、更少的重试，以及一个不再需要故障转移逻辑或复杂错误处理的更精简的代码库。

客户聚焦：OpenRouter

OpenRouter 通过单一统一接口，为 400 多万开发者提供对所有主流 AI 模型的访问。

"结构化输出已成为智能体 AI 技术栈中极具价值的一环。智能体需要持续地摄取和产出结构化数据，因此 Anthropic 的结构化输出为开发者补上了一个真实的缺口。智能体工作流每次都能可靠运行，团队可以把精力放在客户身上，而不是调试工具调用，"OpenRouter 首席运营官 Chris Clark 表示。
