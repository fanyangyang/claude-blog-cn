Projects redesigned: from folder to conversation

A new experience for Claude projects, now available in beta in Claude Code

    Claude Code

    Claude Code

过去，在一次构建中管理多个会话需要你拆分任务、来回交接，再把结果拼到一起。现在，在 Claude Code 项目中，你只需描述要完成的工作，Claude 会统筹全局。 

Claude 会评估请求范围、分配工作、协调并行线程、审查产出，并组装最终成果。你可以全程把控进度，甚至用手机也能操作；当你离开电脑后，它也会继续工作。

举个例子：配置一个项目，设定目标为降低应用结账环节的 p75 延迟。然后让 Claude 对每个端点做性能分析、测试优化方案，并在并行线程中提交 PR。或者连接你的 API、Web 和移动端代码仓库，设定目标为下线已废弃的 v1 端点。Claude 会为每个仓库创建一条线程来迁移调用方、运行测试、提交 PR，然后告诉你哪些需要先合并。

从今天起，全新版项目以 beta 形式向部分使用 Claude Code 云端会话、且在网页端和桌面端没有既有项目的 Claude Pro 和 Max 订阅者开放。 

未来一周内，我们将向更多上述套餐的 Claude Code 用户扩大访问范围。之后，全新版项目将逐步覆盖整个 Claude 以及 Team 和 Enterprise 套餐。如果你使用 Pro 或 Max 但尚未获得访问权限，可以加入等候名单。

Pro 和 Max 套餐上的既有项目将继续保持现有方式运行。随着逐步推广到聊天和 Cowork，我们会完成升级。

线程负责干活，Claude 负责指挥 

项目包含执行工作的线程和负责调度的协调器。

启动一个项目时，你选择一个目标以及代码仓库或上下文。Claude 会先建议它可以立即着手的工作。你可以配置项目的云环境、连接器、插件、指令和模型。

你可以在项目主聊天中监控和引导整体进度，也可以深入每条线程查看和调整细节。在项目中给 Claude 下指令，就像给幕僚长交代任务一样，它会将工作路由到新的或已有的线程。

Claude 还会主动汇报和推进工作。连接了代码仓库后，线程会提交 pull request 并运行你的测试；连接了文档后，它会阅读并起草内容。 

在底层，每条线程都是一个 Claude Code 云端会话，在各自的分支和代码仓库副本上工作。 协调器负责保持工作有序，但如果多条线程碰巧改了同一段代码，冲突会像普通 PR 一样以 merge conflict 的方式解决。 

需要时，每条线程还可以通过子代理、循环和工作流将分配到的工作进一步拆分，让大型任务完成得更快。

上下文随时间积累

项目为长期运行或 agentic 工作流而设计：即那些需要不止一次回复、且不止一个部分的工作。 

随着时间推移，Claude 会越来越了解项目细节并将其应用到工作中。每条线程现在都会向一个共享记忆中写入和读取信息，减少了对复杂 prompt engineering 的需求。

比如，Claude 能记住发版改到了周五、某个导出功能被砍掉的原因、或者改动计费服务前需要先找谁确认。 

Claude 还会记住你的工作方式和沟通习惯。你可以要求它调整汇报频率、开启新线程的频次，或每次更新的详细程度。

除了记忆之外，项目现在还包含一个资料库，收集你添加的文件和 Claude 产出的 artifacts。这让你更容易找到相关材料，也让后续工作能基于过往成果继续推进。 

下一步

项目可以同时运行多条线程，每条都是完整的 Claude Code 会话。正因如此，项目可能更快达到用量上限。你可以查看项目专属的用量情况，并为协调器聊天和工作线程选择模型和 effort level。 

目前线程在云端运行；在本地机器上与你的本地工具和代码一起、在你的网络环境下运行的功能即将推出。 

开始使用 项目。
