Claude Managed Agents 新功能：dreaming、outcomes 与多智能体编排

Dreaming, outcomes, and multiagent orchestration are now available in Claude Managed Agents. Build agents that learn, meet a quality bar, and work in parallel.

今天我们在 Claude Managed Agents 中以研究预览形式推出 dreaming。Dreaming 通过回顾过往会话来扩展 memory，发现模式并帮助 agent 自我改进。我们还向使用 Managed Agents 构建的开发者开放 outcomes、多智能体编排和 webhooks。这些更新合在一起，让 agent 能以更少引导处理复杂任务。

用 dreaming 构建会自我改进的 agent

Dreaming 是 Claude Managed Agents 中的定时流程，会回顾 agent 会话和 memory store，抽取模式并整理记忆，让 agent 随时间改进。你决定要多少控制：dreaming 可以自动更新记忆，也可以让你在落地前审阅变更。

Dreaming 会浮现单个 agent 自己看不见的模式，包括反复出现的错误、agent 逐渐收敛的工作流，以及团队共享的偏好。它也会重组记忆，让记忆在演进过程中保持高信号。这对长时工作和多智能体编排尤其有用。

Memory 和 dreaming 合在一起，构成面向会自我改进的 agent 的稳健记忆系统。Memory 让每个 agent 在工作过程中捕捉所学。Dreaming 则在会话之间打磨这些记忆，抽取跨 agent 的共享经验并保持更新。

Dreaming 可在 Claude Platform 上的 Managed Agents 中使用；开发者可以在此申请访问。

Outcomes：为 agent 的工作定义质量标准

借助 outcomes，你写下描述成功是什么样的评分标准，agent 就朝它努力。一个独立的 grader 在自己的上下文窗口中按你的标准评估输出，因此不会被 agent 的推理影响。当有不对的地方时，grader 会指出需要改什么，agent 再做一轮。

当 agent 知道“好”是什么样时，它们会做得最好。例如一套结构框架、一份演示标准，或一组必须满足的要求。有了 outcomes，agent 可以对照那条标准检查自己的工作，并自我纠正直到输出足够好，而不需要人去审每一轮尝试。

Outcomes 对需要关注细节和穷尽覆盖的任务特别有用。它也适用于主观质量，比如文案是否符合品牌声音，或设计是否遵循视觉规范。在测试中，outcomes 比标准提示循环最多提升了 10 个点的任务成功率，最大增益出现在最难的问题上。Outcomes 也提升了文件生成质量，在我们的内部基准中，docx 任务成功率 +8.4%，pptx +10.1%。

你现在也可以定义一个 outcome，让 agent 运行，并在完成后通过 webhook 收到通知。

多智能体编排：用多个 agent 处理复杂任务

当工作多到单个 agent 难以做好时，多智能体编排让一个主导 agent 把工作拆成若干块，并把每一块委派给拥有自己模型、提示词和工具的专家。例如，主导 agent 可以开展一次调查，同时子 agent 分头翻部署历史、错误日志、指标和支持工单。

这些专家在共享文件系统上并行工作，并贡献到主导 agent 的整体上下文。因为事件是持久的，每个 agent 都记得自己做过什么，主导 agent 可以在工作流中途再回头和其他 agent 核对。你也可以在 Claude Console 中追踪每一步：哪个 agent 做了什么、按什么顺序、为什么，从而完整看清任务如何被委派和执行。

团队在构建什么

团队正在用 dreaming、outcomes 和多智能体编排交付能核验自己工作、跨会话学习、并并行处理复杂任务的 agent：

  • Harvey 用 Managed Agents 协调复杂法律工作，例如长文起草和文档创建。有了 dreaming，他们的 agent 会记住会话之间学到的内容，包括文件类型变通方法和工具特定模式。在他们的测试中，完成率上升了约 6 倍。
  • Netflix 的平台团队构建了一个分析 agent，处理来自不同来源的数百次构建日志。面对会影响数千个应用的变更，关键是找出在许多应用中反复出现的问题。多智能体编排让 agent 能并行分析批次，并只浮现值得采取行动的模式。
  • Every 的 Spiral 用多智能体编排和 outcomes 驱动其新 API 和 CLI 背后的写作 agent。主导 agent 运行在 Haiku 上：它接收传入请求，必要时提出简短跟进问题，再把起草工作委派给运行在 Opus 上的子 agent。当用户要求多份草稿时，子 agent 并行运行。写作质量是 Spiral 的核心价值，因此他们用 outcomes 来强制执行。每份草稿都会对照一份评分标准打分，标准来自 Every 的编辑原则和从记忆中提取的用户声音。只有越过门槛的草稿才会返回。
  • Wisedocs 在 Managed Agents 上构建了文档质量检查 agent，用 outcomes 对照内部指南为每次审查打分。审查现在快了 50%，同时仍与团队标准保持一致。

开始使用

Dreaming 以研究预览形式提供；outcomes、多智能体编排和 memory 作为 Managed Agents 的一部分以公开测试形式提供。要开始使用 dreaming，请在此申请访问。了解更多请查阅我们的 文档，或访问 Claude Console 部署你的第一个 agent。
