Brex 如何用 Claude Code 提升代码质量与生产力

Learn how Claude Code breaks down barriers between technical and non-technical teams by making programming easier and more accessible.

两年前，Andy Reed 加入 Brex 担任内容设计师时，他从未想过自己有一天会写代码、开发 Figma 插件。 

Reed 说：“如果没有 Claude Code，过去一个月我连一半的工作都完不成。” 

但当他真正用上了 Claude Code（Anthropic 的智能体编码解决方案）之后，这一切确实发生了——而他的故事只是这家智能金融平台重塑公司运作方式的一个缩影。 

为了了解更多，我们与 Brex 的三位团队成员聊了聊他们使用 Claude Code 的方式： 

  • Hércules Gimenes，Product AI 团队的软件工程负责人
  • Sumeet Marwaha，数据与分析（Data & Analytics）负责人
  • Andy Reed，高级内容设计师

这些对话带给我们的不只是生产力提升的故事——尽管团队报告在特定任务上获得了 3 到 4 倍的改进。它更关乎从根本上重新想象公司如何协同工作：简化工作流、激发创造性的问题解决方式，并大规模推动协作。

用智能体编码完成思维方式的转变

对 Hércules Gimenes 和 Product AI 团队来说，Claude Code 代表的意义远不止一个新工具。

“Claude Code 带来的是一种思维方式的转变，”他解释道，“你不再是坐在驾驶座上的人，而是 Claude 所做变更的审查者。你负责把握愿景和方向。”

这种转变重新定义了 Brex 的“写代码”意味着什么——这正是该公司 AI 优先原则的体现。工程师不再把时间花在实现细节上，而是专注于架构和问题本身。结果？代码变得更好，而不仅仅是更快。

“我不觉得自己用 Claude Code 省了多少时间，”Gimenes 说，“我把更多精力放在打磨问题本身上。你可以在同样的时间里针对同一个问题尝试三种方案，试完第三种之后，你会对问题有清晰得多的理解，界面也会干净得多。”

打破技术与非技术岗位之间的壁垒

当 Product AI 团队在探索提升代码质量的新方法时，Reed 也经历了自己的顿悟时刻。 

作为一名内容设计师，他在 Claude Code 中发现了意想不到的东西：独立性。

以前，改一个简单的字符串都需要提交工单、等待工程师处理。现在，Reed 可以直接提交 PR。但真正的转变发生在他 tackling 一个被无限期搁置的项目时：将完整的内容规范集成到 Brex 设计系统的每一个组件中。

“如果手动做，可能要花几周甚至几个月，”Reed 解释说。借助 Claude Code，他在几天内就完成了这个项目，系统地加入了从内部风格指南、无障碍标准和外部最佳实践中提炼的内容规范。

这一影响在各个团队间扩散开来。工程师和设计师的工具中如今直接内嵌了内容规范，无需再频繁来回对照，也把错误消灭在发生之前。这是智能金融发挥作用的一个小而有力的例证：系统在后台运行，让人得以专注于更高价值的创造性工作。

让全组织的数据访问民主化

与此同时，Sumeet Marwaha 领导的数据与分析团队正在解决另一个同样重要的挑战：让 Brex 的每个人都能用上数据，而不只是 SQL 专家。

该团队构建了 Brex Explorer，一个由 Claude Code 和 MCP 服务器驱动的 text-to-SQL 界面。现在，销售经理可以用自然语言提问：“在佛罗里达州杰克逊维尔，有多少客户在 Brex 账户中拥有超过 1000 万美元，且是在过去一年内完成开户的？”系统会翻译这条查询、执行它，并对结果进行总结。

真正的乘数效应来自他们的 AI 数据工程 agent。以前需要专业知识才能完成的任务——比如新增数据表并完成所有必要的文件修改和测试配置——现在任何工程师都能胜任。

“这大概相当于速度提升 4 倍，同时贡献者的数量增加了约 2 倍，”Marwaha 指出。Claude Code 在整个组织中的渗透率已达 50%，Marwaha 希望到月底能达到 100%。

“万能工具”带来的意外收获

随着 Brex 各团队陆续用上 Claude Code，一些令人惊喜的用例浮出水面。在一次公司黑客马拉松中，Gimenes 用 Claude Code 的 headless 模式，只用了几个小时就构建出一个功能完善的提交 agent，而这类开发通常需要好几天。

Reed 则发现自己现在能构建以前从未想过要做的工具，比如一个自动根据 Brex 标准审查设计的 Figma 插件。“感觉就像身边有一个全世界最好的实习生，”他说。

但最显著的意外收获，或许是 Claude Code 扮演起了组织知识库的角色。Brex 的 monorepo 采用 Kotlin 和 Bazel 构建、结构复杂，理解不同系统之间如何关联一直是个难题。现在，Claude Code 就像一个“神谕”，能即时回答关于代码库功能的问题。

“以前开设计会议时，大家会讨论某个东西应该怎么运作，但没人真正了解它内部到底是怎么实现的，”Reed 解释说，“现在，我的另一台显示器上就坐着这位神谕。”

在全公司推广 Claude Code 最佳实践

随着 Claude Code 在 Brex 的普及，各团队沉淀出的最佳实践已成为标准：

  • 结构化的上下文管理：monorepo 中的每个主要目录都有自己的 CLAUDE.md 文件，包含领域相关的上下文。新工程师无需依赖“口口相传”的经验，就能了解 Mastercard 集成的细节或银行监管要求。
  • 自动化文档：Product AI 团队实现了 CI/CD 检查，当代码变更可能导致文档过时时会发出提醒并推动更新。“拥有可以信赖的最新文档，这本身就很强大，”Gimenes 强调。
  • 上下文感知的命令：团队创建了自动加载相关上下文的自定义命令。例如 /submit-pr 命令会在执行前获取 git 状态、最近变更和相关 PR 信息。
  • 从探索开始：“你要找的东西不再只存在于某位资深工程师的脑子里了，”Marwaha 说，“它就在代码库里，人人都能访问。”

Claude Code 在 Brex 的未来

Brex 的团队已经在规划下一代应用：

  • 数据团队准备着手以前碰都不敢碰的项目，比如分析数万亿条信用卡交易明细数据点——在 Claude Code 让它变得可行之前，这类工作太枯燥、不值得投入。他们还在开发面向特定角色的 agent，包括一个服务于 RevOps 任务的 agent。
  • Product AI 团队设想了更精妙的上下文管理：文档自动更新，上下文既保持去中心化又触手可及。

从构建技术工具的内容设计师，到推动数据访问民主化的数据分析师，Claude Code 已经成为 Gimenes 口中的“万能工具”——非常适合把 Brex 的领域知识与外部最佳实践结合起来。 

它也凸显了一种有力的双重性：Brex 交付给客户的智能金融——帮助他们更聪明地花钱、更快地行动——同样塑造着 Brex 团队内部的工作方式，让每一位员工无论技术背景如何，都能快速而自信地进行创造。
