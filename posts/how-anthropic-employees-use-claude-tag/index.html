Anthropic 员工如何使用 Claude Tag

Producing customer-ready collateral, compiling weekly issue reports, and running legal review, all where the work already happens.

Claude Tag 将 Claude 引入 Slack 等聊天工具，你可以像@同事一样在对话中 @Claude，它会获取对话上下文、完成任务，然后将答案或结果发布回对话中。它还可以跟随对话进展，利用可用上下文、记忆和已设定的常驻指令来决定何时参与聊天。过去几个月，Anthropic 的团队一直在使用 Claude Tag 在共享频道中进行自助数据分析、处理支持工单，或帮助排查棘手 Bug 的根本原因。

我们整理了十几个受 Anthropic 内部工作启发的 Claude Tag 使用案例，包括具体的提示词和设置说明。在这篇文章中，我们重点介绍三位 Anthropic 员工如何用 Claude Tag 提升工作流程效率，并附上他们使用的提示词，方便你借鉴或调整适合自己工作场景的用法。

将 Slack 对话转化为精炼文档

在最近一次功能发布中，一位销售代表请求提供非技术性资料，用于向客户和潜在客户解释该功能的工作原理；产品营销团队的 Hema Thanki 将随后产生的 Slack 对话在 45 分钟内转化为了一份可供审阅的文档。

那条 Slack 对话超过 15 条消息，多位同事提出了建议或额外需求，对于实际需要什么、现有技术资料是否足够，也存在一些争议。Hema 没有试图澄清这些模糊之处，而是在对话中 @了 Claude：

‍@Claude，通读这条 Slack 对话，整理出一份 [需求方] 想要的一页纸文档。

‍

Claude 在大约两分钟内生成了一份两页的草稿，涵盖该功能的通俗解释、商业价值、实施涉及的内容，以及包含更详细信息的附录。

接着，Hema 让 Claude 核验其回答：

‍@Claude，这份文档中的所有内容是否都真实准确？

Claude 将文档中的陈述分为两类：已通过公开文档验证的，以及属于其自身推论的（已标注需产品负责人确认）。Hema 提供了两个包含相关信息官方资源，Claude 据此重写了一个章节，使其与这些资源中的核准措辞保持一致。

此时，Hema 注意到被截断的对话导致框架偏差，于是她粘贴了更完整的上下文。她与 Claude 反复沟通，总共迭代了四个版本。从首次提出需求约 45 分钟后，她将文档发给了该功能的产品负责人进行审阅。Hema 的时间没有花在研究和起草文档上，而是用于验证准确性、提供来源、决定哪些信息需要包含——这些都是需要人类判断的任务，也使得最终交付给客户的文档更加出色。

除了从 Slack 对话生成简报外，Hema 在日常工作中也广泛使用 Claude Tag。她维护了一个私密的 Slack 频道，在单独的对话中提出请求，像@同事一样在频道中@Claude。在这个频道中，Claude 可以读取她粘贴或附上的任何内容，搜索 Slack 工作区和公开文档，并在后台工作，发布一个随进度更新的检查清单。Claude 的访问权限是有意限定的：它仅从已被授予访问权限的频道和文档中获取信息，当它没有权限访问某些资源时会主动告知。

整合并跟进散落在 Slack 频道中的各类请求

当新功能上线时，销售代表通常需要跟踪并告知那些曾提出该功能需求的客户。这些请求通过 Slack 或产品反馈中心传达，可能分散在数月的历史记录中。产品策略与运营团队的 Steph Soderborg 成功整合了所有与即将上线功能相关的需求，并直接通知了每一位代表客户提出该需求的销售代表，整个过程仅用了约 26 分钟。

首先，Steph 向 Claude 发送了搜索目标、匹配条件的一句话定义，以及她期望的输出范例——一份来自之前发布的七条记录列表：

‍@Claude，我们即将发布 [一个新功能]。你能搜索 Slack……找出所有为他们的客户提出过此功能需求的人……包括他们的 Slack 昵称和团队、提出该需求的客户账号，以及 Slack 中的原始需求链接。

‍

Claude 在多个频道和整个工作区中运行了约 20 种搜索变体。产品反馈中心阻止了其直接访问，因此 Claude 通过 Slack 交叉引用找到了相关内容，并整合了另一个内部助手发布的首轮列表，去重后合并。整合后的列表在大约 26 分钟内返回，包含约 24 个客户账号，每个需求者一行，包含其 Slack 昵称、团队、客户账号以及原始需求链接。

Steph 随后让 Claude 承担了一项她独自无法完成的大型整合工作：她想要了解前一周企业客户报告的所有产品问题，包括哪些出了问题、哪些已修复，以及哪些问题指向同一根本原因。她让 Claude 阅读所有涉及事件、升级、支持和产品反馈的 Slack 频道。大约 50 分钟后，Claude 发布了一份按产品领域分类的总结，包含 23 个仍未解决的问题和 14 个已解决的问题，从约 120 条原始信息中提炼而来。每个问题都附有摘要和源对话链接。Steph 随后让 Claude 检查其工作，它又发现了 15 个额外问题。

Steph 估计，手动梳理、分析和综合如此大量的信息，至少需要她全职工作一周，甚至可能永远无法完成。而借助 Claude Tag，她只需花几分钟整理需求，Claude 便在后台完成了工作。

Steph 也在一个私密频道中与 Claude 协作，预先发送完整的指令，包括搜索范围、匹配条件，以及通常的输出格式示例。Claude 搜索工作区、读取已受邀的频道，并在工作时发布进度更新。当反馈中心阻止访问时，Claude 会尝试通过可访问的文档和频道收集相关信息，甚至请求访问这些频道。

加速法律文档审核

Anthropic 的法务团队在每篇博客、落地页、邮件或其他宣传资料公开发布前都会进行审核。在产品发布前的几天里，营销团队可能在紧迫的时间限制下提交数十份不同的资料供审核。这还不包括日常审核队列中的其他营销资料——从一段话的社交媒体文案到 2500 字的博客草稿，从包含十几个标签页的规划文档到包含多个变体的邮件系列。法务顾问 Molly Villagra 创建了一个专门的 Slack 频道，让 Claude Tag 先对每份营销资料进行审查，将营销法务审核周转时间从一天（或更久）缩短到每份资料 30 分钟。

营销人员提交法务审核时，只需在 Slack 频道中发布文档链接。没有工程背景的 Molly 为 Claude 设定了具体的规则和指令。Claude 不仅能发现法律问题（如未经证实的营销宣称），还能帮助核实营销内容中的事实性陈述，因为它可以访问公司 Slack、内部知识索引和公共互联网。如果发现问题，Claude 会列出具体问题并提供解决说明，直接与需求方协作处理。对于仍需法务签批的遗留问题，Claude 会@对应的法务顾问，后者可以快速审阅被标记的陈述。

例如，在最近的一次新闻稿审核中，Claude 标记了三个关键问题，随后几分钟内，它在无需提示的情况下，从内部文档中找到所需信息并自行解决了其中一个问题。Molly 通过@Claude 在营销法务审核频道中要求将其设为默认行为：

‍你标记的三个点很好，但它们都可以由你自行核实。以后你再标记问题时，能否尝试实时核实这些信息？

应 Molly 的要求，Claude Tag 将此新指令添加到了它在未来所有审核中遵循的指令集中，实现了通过频道反馈实时改进。

这一反馈循环启发了 Molly 创建了一个新的例行流程：让 Claude 每周五审阅本周的法务反馈，并提出共享指令的更新建议供她批准。

以上分享的每个工作流都在为 Anthropic 员工节省数小时甚至数天的工作时间，并使得之前根本不可能开展的项目成为现实。你的团队最想先交给 Claude 处理哪些工作流或项目？
